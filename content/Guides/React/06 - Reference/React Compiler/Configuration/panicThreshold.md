# panicThreshold

## Огляд

Параметр `panicThreshold` контролює, як React Compiler обробляє помилки під час компіляції.

```js
{
  panicThreshold: 'none' // Рекомендовано
}
```

## Довідка

### `panicThreshold`

Визначає, чи повинні помилки компіляції зупиняти збірку, чи пропускати оптимізацію.

#### Тип

```
'none' | 'critical_errors' | 'all_errors'
```

#### Значення за замовчуванням

`'none'`

#### Варіанти

- **`'none'`** (за замовчуванням, рекомендовано): Пропускати компоненти, які не можна скомпілювати, та продовжувати збірку
- **`'critical_errors'`**: Зупиняти збірку лише при критичних помилках компілятора
- **`'all_errors'`**: Зупиняти збірку при будь-якій діагностиці компілятора

#### Застереження

- Продакшен збірки завжди повинні використовувати `'none'`
- Зупинка збірки запобігає створенню вашого додатку
- Компілятор автоматично виявляє та пропускає проблемний код при `'none'`
- Вищі порогові значення корисні лише під час розробки для налагодження

## Використання

### Конфігурація для продакшену (рекомендовано)

Для продакшен збірок завжди використовуйте `'none'`. Це значення за замовчуванням:

```js
{
  panicThreshold: 'none'
}
```

Це забезпечує:
- Ваша збірка ніколи не зламається через проблеми компілятора
- Компоненти, які не можна оптимізувати, працюють нормально
- Максимальна кількість компонентів оптимізується
- Стабільні продакшен деплої

### Налагодження під час розробки

Тимчасово використовуйте суворіші порогові значення для пошуку проблем:

```js
const isDevelopment = process.env.NODE_ENV === 'development';

{
  panicThreshold: isDevelopment ? 'critical_errors' : 'none',
  logger: {
    logEvent(filename, event) {
      if (isDevelopment && event.kind === 'CompileError') {
        // ...
      }
    }
  }
}
```
