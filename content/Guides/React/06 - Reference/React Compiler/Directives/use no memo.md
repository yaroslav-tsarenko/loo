# "use no memo"

## Вступ

`"use no memo"` запобігає оптимізації функції React Compiler.

---

## Довідка

### `"use no memo"`

Додайте `"use no memo"` на початку функції, щоб запобігти оптимізації React Compiler.

```js
function MyComponent() {
  "use no memo";
  // ...
}
```

Коли функція містить `"use no memo"`, React Compiler повністю пропустить її під час оптимізації. Це корисно як тимчасовий запасний вихід при налагодженні або при роботі з кодом, який не працює коректно з компілятором.

#### Застереження

* `"use no memo"` повинен бути на самому початку тіла функції, перед будь-яким іншим кодом (коментарі допускаються)
* Директива повинна бути записана в подвійних або одинарних лапках, не у зворотних
* Директива повинна точно відповідати `"use no memo"` або її псевдоніму `"use no forget"`
* Ця директива має пріоритет над усіма режимами компіляції та іншими директивами
* Вона призначена як тимчасовий інструмент налагодження, а не як постійне рішення

### Як `"use no memo"` відключає оптимізацію

React Compiler аналізує ваш код під час збірки для застосування оптимізацій. `"use no memo"` створює явну межу, яка вказує компілятору повністю пропустити функцію.

Ця директива має пріоритет над усіма іншими налаштуваннями:
* У режимі `all`: Функція пропускається незважаючи на глобальне налаштування
* У режимі `infer`: Функція пропускається, навіть якщо евристика б її оптимізувала

Компілятор обробляє ці функції так, ніби React Compiler не був увімкнений, залишаючи їх точно такими, як написано.

### Коли використовувати `"use no memo"`

`"use no memo"` слід використовувати помірно та тимчасово. Типові сценарії включають:

#### Налагодження проблем компілятора

Коли ви підозрюєте, що компілятор спричиняє проблеми, тимчасово вимкніть оптимізацію для ізоляції проблеми:

```js
function ProblematicComponent({ data }) {
  "use no memo"; // TODO: Видалити після виправлення проблеми #123

  // Порушення Rules of React, які не були статично виявлені
  // ...
}
```

#### Інтеграція зі сторонніми бібліотеками

При інтеграції з бібліотеками, які можуть бути несумісні з компілятором:

```js
function ThirdPartyWrapper() {
  "use no memo";

  useThirdPartyHook(); // Має побічні ефекти, які компілятор може неправильно оптимізувати
  // ...
}
```

## Використання

Директива `"use no memo"` розміщується на початку тіла функції, щоб запобігти оптимізації React Compiler цієї функції:

```js
function MyComponent() {
  "use no memo";
  // Тіло функції
}
```

Директиву також можна розмістити на початку файлу для впливу на всі функції в цьому модулі:

```js
"use no memo";

// Усі функції в цьому файлі будуть пропущені компілятором
```

`"use no memo"` на рівні функції перевизначає директиву на рівні модуля.

---

## Усунення проблем

### Директива не запобігає компіляції

Якщо `"use no memo"` не працює:

```js
// ❌ Неправильно — директива після коду
function Component() {
  const data = getData();
  "use no memo"; // Занадто пізно!
}

// ✅ Правильно — директива першою
function Component() {
  "use no memo";
  const data = getData();
}
```

Також перевірте:
* Правопис — повинно бути точно `"use no memo"`
* Лапки — повинні використовуватися одинарні або подвійні лапки, не зворотні

### Найкращі практики

**Завжди документуйте, чому** ви відключаєте оптимізацію:

```js
// ✅ Добре — зрозуміле пояснення та відстеження
function DataProcessor() {
  "use no memo"; // TODO: Видалити після виправлення порушення Rules of React
  // ...
}

// ❌ Погано — без пояснення
function Mystery() {
  "use no memo";
  // ...
}
```

### Дивіться також

* `"use memo"` — увімкнення компіляції
* React Compiler — посібник із початку роботи
