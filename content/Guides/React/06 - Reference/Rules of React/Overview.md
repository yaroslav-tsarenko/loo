# Rules of React

## Вступ

Як і різні мови програмування мають свої власні способи вираження концепцій, React має свої власні ідіоми — або правила — для того, як виражати патерни у спосіб, що легко зрозуміти та створює високоякісні додатки.

## Огляд

Цей розділ описує правила, яких потрібно дотримуватися для написання ідіоматичного React коду. Написання ідіоматичного React коду може допомогти вам писати добре організовані, безпечні та компоновані додатки. Ці властивості роблять ваш додаток більш стійким до змін та полегшують роботу з іншими розробниками, бібліотеками та інструментами.

Ці правила відомі як **Rules of React**. Це саме правила — а не просто рекомендації — у тому сенсі, що якщо їх порушити, ваш додаток ймовірно матиме баги. Ваш код також стає неідіоматичним та важчим для розуміння та міркування.

**Рекомендація:** Використовуйте [Strict Mode](/reference/react/StrictMode) разом із [ESLint плагіном](https://www.npmjs.com/package/eslint-plugin-react-hooks) React, щоб допомогти вашій кодовій базі дотримуватися Rules of React. Дотримуючись Rules of React, ви зможете знаходити та вирішувати баги та підтримувати ваш додаток у належному стані.

## Компоненти та хуки повинні бути чистими

Чистота компонентів та хуків є ключовим правилом React, що робить ваш додаток передбачуваним, легким для налагодження та дозволяє React автоматично оптимізувати ваш код.

### Компоненти повинні бути ідемпотентними
React компоненти повинні завжди повертати однаковий вивід відносно їхніх вхідних даних — props, state та context.

### Побічні ефекти повинні виконуватися поза рендером
Побічні ефекти не повинні виконуватися в render, оскільки React може рендерити компоненти кілька разів для створення найкращого користувацького досвіду.

### Props та state є незмінними
Props та state компонента є незмінними знімками відносно одного рендеру. Ніколи не мутуйте їх напряму.

### Значення, повернуті з хуків та передані як аргументи, є незмінними
Після передачі значень у хук ви не повинні їх модифікувати. Як props у JSX, значення стають незмінними при передачі в хук.

### Значення є незмінними після передачі в JSX
Не мутуйте значення після того, як вони були використані в JSX. Перемістіть мутацію до створення JSX.

---

## React викликає компоненти та хуки

React відповідає за рендеринг компонентів та хуків, коли це необхідно для оптимізації користувацького досвіду. Він є декларативним: ви вказуєте React, що рендерити в логіці вашого компонента, і React визначить, як найкраще відобразити це для вашого користувача.

### Ніколи не викликайте функції компонентів напряму
Компоненти повинні використовуватися лише в JSX. Не викликайте їх як звичайні функції.

### Ніколи не передавайте хуки як звичайні значення
Хуки повинні викликатися лише всередині компонентів. Ніколи не передавайте їх як звичайні значення.

---

## Rules of Hooks

Хуки визначаються за допомогою JavaScript функцій, але вони представляють особливий тип повторно використовуваної UI логіки з обмеженнями щодо того, де їх можна викликати. Потрібно дотримуватися Rules of Hooks при їх використанні.

### Викликайте хуки лише на верхньому рівні
Не викликайте хуки всередині циклів, умов або вкладених функцій. Натомість завжди використовуйте хуки на верхньому рівні вашої React функції, перед будь-якими ранніми поверненнями.

### Викликайте хуки лише з React функцій
Не викликайте хуки зі звичайних JavaScript функцій.
