# `<Profiler>`

## Огляд

`<Profiler>` дозволяє програмно вимірювати продуктивність рендерингу дерева React.

```js
<Profiler id="App" onRender={onRender}>
  <App />
</Profiler>
```

---

## Довідка

### Компонент `<Profiler>`

Обгорніть дерево компонентів у `<Profiler>`, щоб виміряти його продуктивність рендерингу.

```js
<Profiler id="App" onRender={onRender}>
  <App />
</Profiler>
```

#### Пропси

- **`id`**: Рядок, що ідентифікує частину UI, яку ви вимірюєте.
- **`onRender`**: Колбек `onRender`, який React викликає кожного разу, коли компоненти всередині профільованого дерева оновлюються. Він отримує інформацію про те, що було відрендерено та скільки часу це зайняло.

#### Застереження

- Профілювання додає деякі додаткові накладні витрати, тому **воно вимкнене у продакшн-збірці за замовчуванням.** Щоб увімкнути профілювання у продакшні, потрібно активувати спеціальну продакшн-збірку з увімкненим профілюванням.

---

### Колбек `onRender`

React викликатиме ваш колбек `onRender` з інформацією про те, що було відрендерено.

```js
function onRender(id, phase, actualDuration, baseDuration, startTime, commitTime) {
  // Агрегувати або логувати часові показники рендерингу...
}
```

#### Параметри

- **`id`**: Рядковий проп `id` дерева `<Profiler>`, яке щойно зафіксувало зміни. Це дозволяє ідентифікувати, яка частина дерева була зафіксована, якщо ви використовуєте кілька профайлерів.

- **`phase`**: `"mount"`, `"update"` або `"nested-update"`. Це дозволяє дізнатися, чи дерево було змонтовано вперше, чи перерендерено через зміну пропсів, стану або хуків.

- **`actualDuration`**: Кількість мілісекунд, витрачених на рендеринг `<Profiler>` та його нащадків для поточного оновлення. Це показує, наскільки добре піддерево використовує мемоїзацію (наприклад, `memo` та `useMemo`). В ідеалі це значення має значно зменшитися після початкового монтування, оскільки багато нащадків потребуватимуть перерендерингу лише при зміні їхніх конкретних пропсів.

- **`baseDuration`**: Кількість мілісекунд, що оцінює, скільки часу знадобилося б для перерендерингу всього піддерева `<Profiler>` без будь-яких оптимізацій. Обчислюється шляхом підсумовування найновіших тривалостей рендерингу кожного компонента в дереві. Це значення оцінює найгірший випадок вартості рендерингу (наприклад, початкове монтування або дерево без мемоїзації). Порівняйте `actualDuration` з ним, щоб побачити, чи працює мемоїзація.

- **`startTime`**: Числова мітка часу, коли React почав рендеринг поточного оновлення.

- **`commitTime`**: Числова мітка часу, коли React зафіксував поточне оновлення. Це значення є спільним для всіх профайлерів у фіксації, що дозволяє групувати їх за потреби.

## Використання

### Програмне вимірювання продуктивності рендерингу

Обгорніть компонент `<Profiler>` навколо дерева React, щоб виміряти його продуктивність рендерингу.

```js
<App>
  <Profiler id="Sidebar" onRender={onRender}>
    <Sidebar />
  </Profiler>
  <PageContent />
</App>
```

Потрібні два пропси: `id` (рядок) та колбек `onRender` (функція), який React викликає кожного разу, коли компонент у дереві "фіксує" оновлення.

> **Увага**: Профілювання додає деякі додаткові накладні витрати, тому **воно вимкнене у продакшн-збірці за замовчуванням.** Щоб увімкнути профілювання у продакшні, потрібно активувати спеціальну продакшн-збірку з увімкненим профілюванням.

> **Примітка**:
> - `<Profiler>` дозволяє збирати вимірювання програмно. Якщо ви шукаєте інтерактивний профайлер, спробуйте вкладку Profiler у React Developer Tools. Вона надає подібну функціональність як розширення браузера.
> - Компоненти, обгорнуті у `<Profiler>`, також будуть відмічені в треках Component у React Performance навіть у профільних збірках. У збірках для розробки всі компоненти відмічаються в треку Components незалежно від того, чи вони обгорнуті у `<Profiler>`.

### Вимірювання різних частин застосунку

Ви можете використовувати кілька компонентів `<Profiler>` для вимірювання різних частин вашого застосунку:

```js
<App>
  <Profiler id="Sidebar" onRender={onRender}>
    <Sidebar />
  </Profiler>
  <Profiler id="Content" onRender={onRender}>
    <Content />
  </Profiler>
</App>
```

Ви також можете вкладати компоненти `<Profiler>`:

```js
<App>
  <Profiler id="Sidebar" onRender={onRender}>
    <Sidebar />
  </Profiler>
  <Profiler id="Content" onRender={onRender}>
    <Content>
      <Profiler id="Editor" onRender={onRender}>
        <Editor />
      </Profiler>
      <Preview />
    </Content>
  </Profiler>
</App>
```

Хоча `<Profiler>` є легковісним компонентом, його слід використовувати лише за потреби. Кожне використання додає деякі накладні витрати на CPU та пам'ять до застосунку.
