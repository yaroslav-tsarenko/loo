# useId

## Огляд

`useId` — це React Hook для генерації унікальних ID, які можна передавати атрибутам доступності.

```js
const id = useId()
```

---

## Довідка

### `useId()`

Викликайте `useId` на верхньому рівні компонента для генерації унікального ID:

```js
import { useId } from 'react';

function PasswordField() {
  const passwordHintId = useId();
  // ...
}
```

#### Параметри

`useId` не приймає жодних параметрів.

#### Повертає

`useId` повертає унікальний рядок ID, пов'язаний з цим конкретним викликом `useId` у цьому конкретному компоненті.

#### Застереження

* `useId` — це Hook, тому його можна викликати лише **на верхньому рівні компонента** або власних Hooks.
* `useId` **не слід використовувати для генерації ключів кешу** для `use()`.
* `useId` **не слід використовувати для генерації ключів** у списку. Ключі мають генеруватися з ваших даних.
* `useId` наразі не можна використовувати в асинхронних Server Components.

---

## Використання

### Генерація унікальних ID для атрибутів доступності

```js
import { useId } from 'react';

function PasswordField() {
  const passwordHintId = useId();
  return (
    <>
      <label>
        Пароль:
        <input
          type="password"
          aria-describedby={passwordHintId}
        />
      </label>
      <p id={passwordHintId}>
        Пароль має містити щонайменше 18 символів
      </p>
    </>
  );
}
```

Тепер, навіть якщо `PasswordField` з'являється кілька разів на екрані, згенеровані ID не конфліктуватимуть.

**Застереження щодо серверного рендерингу:** `useId` вимагає ідентичного дерева компонентів на сервері та клієнті. Якщо дерева не збігаються точно, згенеровані ID не збігатимуться.

### Чому useId кращий за інкрементний лічильник

Основна перевага `useId` — React гарантує, що він працює з серверним рендерингом. Під час серверного рендерингу компоненти генерують HTML. Пізніше, на клієнті, гідратація приєднує обробники подій до згенерованого HTML. Для роботи гідратації вихід клієнта має збігатися з серверним HTML.

З інкрементним лічильником це дуже важко гарантувати, оскільки порядок гідратації Client Components може не збігатися з порядком генерації серверного HTML. `useId` генерується з "батьківського шляху" викликаючого компонента, тому він збігається незалежно від порядку рендерингу.

### Генерація ID для кількох пов'язаних елементів

Якщо потрібно надати ID кільком пов'язаним елементам, викликайте `useId` для генерації спільного префікса:

```js
import { useId } from 'react';

export default function Form() {
  const id = useId();
  return (
    <form>
      <label htmlFor={id + '-firstName'}>Ім'я:</label>
      <input id={id + '-firstName'} type="text" />
      <hr />
      <label htmlFor={id + '-lastName'}>Прізвище:</label>
      <input id={id + '-lastName'} type="text" />
    </form>
  );
}
```

---

### Вказання спільного префікса для всіх згенерованих ID

Якщо ви рендерите кілька незалежних React-додатків на одній сторінці, передайте `identifierPrefix` як опцію до `createRoot` або `hydrateRoot`:

```js
const root1 = createRoot(document.getElementById('root1'), {
  identifierPrefix: 'my-first-app-'
});
root1.render(<App />);

const root2 = createRoot(document.getElementById('root2'), {
  identifierPrefix: 'my-second-app-'
});
root2.render(<App />);
```

Це гарантує, що ID, згенеровані різними додатками, ніколи не конфліктуватимуть.
