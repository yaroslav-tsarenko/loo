# useDeferredValue

## Огляд

`useDeferredValue` — це React Hook, який дозволяє відкласти оновлення частини UI.

```js
const deferredValue = useDeferredValue(value)
```

---

## Довідка

### `useDeferredValue(value, initialValue?)`

Викликайте `useDeferredValue` на верхньому рівні компонента, щоб отримати відкладену версію значення.

```js
import { useState, useDeferredValue } from 'react';

function SearchPage() {
  const [query, setQuery] = useState('');
  const deferredQuery = useDeferredValue(query);
  // ...
}
```

#### Параметри

* `value`: Значення, яке ви хочете відкласти. Може мати будь-який тип.
* **необов'язково** `initialValue`: Значення для використання під час початкового рендеру компонента. Якщо цю опцію пропущено, `useDeferredValue` не буде відкладати під час початкового рендеру, оскільки немає попередньої версії `value`.

#### Повертає

- `currentValue`: Під час початкового рендеру повернене відкладене значення буде `initialValue` або тим самим значенням, яке ви надали. Під час оновлень React спочатку спробує повторний рендеринг зі старим значенням (тому поверне старе значення), а потім спробує інший повторний рендеринг у фоновому режимі з новим значенням (тому поверне оновлене значення).

#### Застереження

- Коли оновлення відбувається всередині Transition, `useDeferredValue` завжди повертає нове `value` і не запускає відкладений рендеринг.
- Значення, які ви передаєте до `useDeferredValue`, мають бути примітивними (рядки, числа) або об'єктами, створеними поза рендерингом.
- Коли `useDeferredValue` отримує інше значення, окрім поточного рендеру він планує повторний рендеринг у фоновому режимі з новим значенням. Фоновий рендеринг можна перервати.
- `useDeferredValue` інтегрований з [`<Suspense>`](/reference/react/Suspense). Якщо фонове оновлення призупиняє UI, користувач не побачить запасний варіант.
- `useDeferredValue` сам по собі не запобігає додатковим мережевим запитам.
- Немає фіксованої затримки, спричиненої `useDeferredValue`. React почне фоновий рендеринг одразу після завершення оригінального.

## Використання

### Показ застарілого контенту під час завантаження нового

```js
import { Suspense, useState, useDeferredValue } from 'react';
import SearchResults from './SearchResults.js';

export default function App() {
  const [query, setQuery] = useState('');
  const deferredQuery = useDeferredValue(query);
  return (
    <>
      <label>
        Пошук альбомів:
        <input value={query} onChange={e => setQuery(e.target.value)} />
      </label>
      <Suspense fallback={<h2>Завантаження...</h2>}>
        <SearchResults query={deferredQuery} />
      </Suspense>
    </>
  );
}
```

`query` оновиться негайно, тому поле введення відобразить нове значення. Проте `deferredQuery` зберігатиме попереднє значення, поки дані не завантажаться, тому `SearchResults` деякий час показуватиме застарілі результати.

#### Як це працює під капотом

1. **Спочатку React повторно рендерить з новим `query`, але зі старим `deferredQuery`.** Значення `deferredQuery` "відстає" від значення `query`.
2. **У фоновому режимі React намагається повторно відрендерити з оновленими обома значеннями.** Якщо це призупиняється, React відмовляється від спроби та повторює після завантаження даних.

---

### Індикація застарілого контенту

Ви можете додати візуальну індикацію, коли відображається застарілий список результатів:

```js
<div style={{
  opacity: query !== deferredQuery ? 0.5 : 1,
}}>
  <SearchResults query={deferredQuery} />
</div>
```

### Відкладення повторного рендерингу частини UI

Також можна застосувати `useDeferredValue` як оптимізацію продуктивності. Це корисно, коли частина UI повільно рендериться і ви хочете запобігти блокуванню решти UI.

```js
function App() {
  const [text, setText] = useState('');
  const deferredText = useDeferredValue(text);
  return (
    <>
      <input value={text} onChange={e => setText(e.target.value)} />
      <SlowList text={deferredText} />
    </>
  );
}
```

> **Пастка:** Ця оптимізація вимагає, щоб `SlowList` був обгорнутий у [`memo`](/reference/react/memo). Оскільки коли `text` змінюється, React має швидко перерендерити батьківський компонент. Під час цього рендеру `deferredText` все ще має попереднє значення, тому `SlowList` може пропустити повторний рендеринг (його props не змінилися). Без `memo` він все одно рендерився б, що зводить нанівець оптимізацію.

---

### Чим відкладення значення відрізняється від debouncing та throttling?

Переваги `useDeferredValue`:

1. **Глибока інтеграція з React** — адаптується до пристрою користувача.
2. **Немає фіксованої затримки** — на швидкому пристрої відкладений рендеринг відбувається майже миттєво.
3. **Переривається за замовчуванням** — якщо React рендерить великий список, але користувач натискає клавішу, React відмовиться від рендерингу, обробить натискання і почне рендеринг знову.
4. **Можна комбінувати** — debouncing та throttling все ще корисні для зменшення мережевих запитів. Ці техніки можна використовувати разом.
