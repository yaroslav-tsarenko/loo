# Вбудовані React Hooks

## Огляд

*Hooks* дозволяють використовувати різні можливості React у ваших компонентах. Ви можете використовувати вбудовані Hooks або комбінувати їх для створення власних.

---

## State Hooks

*State* дозволяє компоненту ["запам'ятовувати" інформацію, як-от введення користувача.](/learn/state-a-components-memory) Наприклад, компонент форми може використовувати state для збереження значення поля введення, а компонент галереї зображень може використовувати state для збереження індексу вибраного зображення.

Щоб додати state до компонента, використовуйте один із цих Hooks:

* **`useState`** — оголошує змінну state, яку можна оновлювати безпосередньо.
* **`useReducer`** — оголошує змінну state з логікою оновлення всередині [функції reducer.](/learn/extracting-state-logic-into-a-reducer)

```javascript
function ImageGallery() {
  const [index, setIndex] = useState(0);
  // ...
}
```

## Context Hooks

*Context* дозволяє компоненту [отримувати інформацію від віддалених батьківських компонентів без передачі через props.](/learn/passing-props-to-a-component) Наприклад, компонент верхнього рівня вашого додатка може передати поточну тему UI всім компонентам нижче, незалежно від глибини вкладеності.

* **`useContext`** — читає та підписується на context.

```javascript
function Button() {
  const theme = useContext(ThemeContext);
  // ...
}
```

## Ref Hooks

*Refs* дозволяють компоненту [зберігати інформацію, яка не використовується для рендерингу,](/learn/referencing-values-with-refs) наприклад, DOM-вузол або ідентифікатор таймера. На відміну від state, оновлення ref не викликає повторний рендеринг компонента. Refs є "аварійним виходом" з парадигми React. Вони корисні, коли потрібно працювати з системами, що не належать до React, наприклад, з вбудованими API браузера.

* **`useRef`** — оголошує ref. Ви можете зберігати в ньому будь-яке значення, але найчастіше він використовується для зберігання DOM-вузла.
* **`useImperativeHandle`** — дозволяє налаштувати ref, який відкриває ваш компонент. Використовується рідко.

```javascript
function Form() {
  const inputRef = useRef(null);
  // ...
}
```

## Effect Hooks

*Effects* дозволяють компоненту [підключатися та синхронізуватися з зовнішніми системами.](/learn/synchronizing-with-effects) Це включає роботу з мережею, DOM браузера, анімаціями, віджетами, написаними з використанням іншої UI-бібліотеки, та іншим кодом, що не належить до React.

* **`useEffect`** — підключає компонент до зовнішньої системи.

```javascript
function ChatRoom({ roomId }) {
  useEffect(() => {
    const connection = createConnection(roomId);
    connection.connect();
    return () => connection.disconnect();
  }, [roomId]);
  // ...
}
```

**Примітка:** Effects є "аварійним виходом" з парадигми React. Не використовуйте Effects для організації потоку даних вашого додатка. Якщо ви не взаємодієте з зовнішньою системою, [вам, можливо, не потрібен Effect.](/learn/you-might-not-need-an-effect)

### Варіації Effect Hook

Існують дві рідко використовувані варіації `useEffect` з відмінностями в часі виконання:

* **`useLayoutEffect`** — спрацьовує до того, як браузер перемалює екран. Тут можна вимірювати макет.
* **`useInsertionEffect`** — спрацьовує до того, як React внесе зміни в DOM. Бібліотеки можуть вставляти динамічний CSS тут.

### Відокремлення подій від Effects

* **`useEffectEvent`** — створює нереактивну подію для виклику з будь-якого Effect hook.

## Performance Hooks

Поширений спосіб оптимізації продуктивності повторного рендерингу — пропуск непотрібної роботи. Наприклад, ви можете вказати React повторно використовувати кешований результат обчислення або пропустити повторний рендеринг, якщо дані не змінилися з попереднього рендеру.

### Кешування обчислень та функцій

Щоб пропустити обчислення та непотрібний повторний рендеринг, використовуйте один із цих Hooks:

- **`useMemo`** — дозволяє кешувати результат дорогого обчислення.
- **`useCallback`** — дозволяє кешувати визначення функції перед передачею його оптимізованому компоненту.

```javascript
function TodoList({ todos, tab, theme }) {
  const visibleTodos = useMemo(() => filterTodos(todos, tab), [todos, tab]);
  // ...
}
```

### Пріоритезація рендерингу

Іноді ви не можете пропустити повторний рендеринг, оскільки екран дійсно потребує оновлення. У такому випадку можна покращити продуктивність, відокремивши блокуючі оновлення, які мають бути синхронними (як-от введення в поле), від неблокуючих оновлень, які не потребують блокування інтерфейсу користувача (як-от оновлення діаграми).

Для пріоритезації рендерингу використовуйте один із цих Hooks:

- **`useTransition`** — дозволяє позначити перехід state як неблокуючий та дозволити іншим оновленням переривати його.
- **`useDeferredValue`** — дозволяє відкласти оновлення некритичної частини UI та дати іншим частинам оновитися першими.

## Інші Hooks

Ці Hooks здебільшого корисні авторам бібліотек і рідко використовуються в коді додатків.

- **`useDebugValue`** — дозволяє налаштувати мітку, яку React DevTools відображає для вашого власного Hook.
- **`useId`** — дозволяє компоненту пов'язати з собою унікальний ID. Зазвичай використовується з API доступності.
- **`useSyncExternalStore`** — дозволяє компоненту підписатися на зовнішнє сховище.
- **`useActionState`** — дозволяє керувати state дій.
