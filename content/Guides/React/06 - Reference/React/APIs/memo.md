# `memo`

## Огляд

`memo` дозволяє пропустити повторний рендеринг компонента, коли його пропси не змінилися.

```js
const MemoizedComponent = memo(SomeComponent, arePropsEqual?)
```

> **Примітка**: React Compiler автоматично застосовує еквівалент `memo` до всіх компонентів, зменшуючи потребу в ручній мемоїзації.

---

## Довідка

### `memo(Component, arePropsEqual?)`

Обгорніть компонент у `memo`, щоб отримати *мемоїзовану* версію цього компонента. Ця мемоїзована версія зазвичай не буде перерендерюватися, коли батьківський компонент перерендерюється, якщо її пропси не змінилися. Однак React все ще може перерендерити її — мемоїзація є оптимізацією продуктивності, а не гарантією.

```js
import { memo } from 'react';

const SomeComponent = memo(function SomeComponent(props) {
  // ...
});
```

#### Параметри

- **`Component`**: Компонент, який ви хочете мемоїзувати. `memo` не модифікує цей компонент, а повертає новий, мемоїзований компонент. Приймається будь-який допустимий компонент React, включаючи функції та компоненти `forwardRef`.

- **`arePropsEqual` (необов'язковий)**: Функція, що приймає два аргументи: попередні пропси компонента та його нові пропси. Повертає `true`, якщо старі та нові пропси рівні (компонент рендеритиме той самий вивід), інакше повертає `false`. За замовчуванням React порівнює кожен проп за допомогою [`Object.is`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/is).

#### Повертає

`memo` повертає новий компонент React, який поводиться так само, як наданий компонент, за винятком того, що React не завжди перерендерюватиме його, коли батьківський компонент перерендерюється, якщо його пропси не змінилися.

---

## Використання

### Пропуск повторного рендерингу при незмінних пропсах

React зазвичай перерендерює компонент щоразу, коли його батьківський компонент перерендерюється. За допомогою `memo` ви можете створити компонент, який React не перерендерюватиме при перерендері батьківського компонента, поки його нові пропси залишаються такими самими, як старі.

Для мемоїзації компонента обгорніть його в `memo`:

```js
const Greeting = memo(function Greeting({ name }) {
  return <h1>Hello, {name}!</h1>;
});

export default Greeting;
```

Компонент React завжди повинен мати чисту логіку рендерингу — він повинен повертати той самий вивід, якщо його пропси, стан і контекст не змінилися. Використовуючи `memo`, ви повідомляєте React, що ваш компонент відповідає цій вимозі.

**Важливо:** Навіть з `memo` ваш компонент перерендериться, якщо:
- Його власний стан зміниться
- Контекст, який він використовує, зміниться

#### Приклад: Повторний рендеринг на основі пропсів

```js
import { memo, useState } from 'react';

export default function MyApp() {
  const [name, setName] = useState('');
  const [address, setAddress] = useState('');
  return (
    <>
      <label>
        Name{': '}
        <input value={name} onChange={e => setName(e.target.value)} />
      </label>
      <label>
        Address{': '}
        <input value={address} onChange={e => setAddress(e.target.value)} />
      </label>
      <Greeting name={name} />
    </>
  );
}

const Greeting = memo(function Greeting({ name }) {
  console.log("Greeting was rendered at", new Date().toLocaleTimeString());
  return <h3>Hello{name && ', '}{name}!</h3>;
});
```

У цьому прикладі:
- `Greeting` перерендерюється при зміні `name` (це проп)
- `Greeting` НЕ перерендерюється при зміні `address` (це не проп)

> **Примітка**: Покладайтесь на `memo` лише як на оптимізацію продуктивності. Якщо ваш код не працює без нього, знайдіть та виправте основну проблему спочатку.

### Чи варто додавати memo скрізь?

**Коли мемоїзація корисна:**
- Застосунки з деталізованими взаємодіями (як редактори малювання, де часто переміщуються фігури)
- Компоненти, що часто перерендерюються з тими самими пропсами
- Компоненти з ресурсомістким рендерингом

**Коли мемоїзація непотрібна:**
- Застосунки з грубими взаємодіями (як заміна сторінок або розділів)
- Компоненти з непомітною затримкою при перерендері
- Коли пропси завжди різні (мемоїзація марна)

**Найкращі практики для зменшення потреби в мемоїзації:**

1. **Приймайте JSX як children** — Коли компонент-обгортка оновлює свій стан, React знає, що дочірні компоненти не потребують перерендерингу

2. **Надавайте перевагу локальному стану** — Не піднімайте стан вище, ніж потрібно; тримайте тимчасовий стан (форми, стани наведення) локально

3. **Зберігайте чистоту логіки рендерингу** — Якщо перерендеринг спричиняє проблеми, це помилка — виправте її замість додавання мемоїзації

4. **Уникайте непотрібних Effects** — Більшість проблем продуктивності пов'язані з ланцюгами оновлень, що виникають з Effects

5. **Видаляйте непотрібні залежності** — Спрощуйте Effects замість покладання на мемоїзацію

### Оновлення мемоїзованого компонента через стан

Навіть коли компонент мемоїзований, він все одно перерендерюватиметься при зміні його власного стану. Мемоїзація стосується лише пропсів від батьківського компонента.

Якщо ви встановлюєте змінну стану в її поточне значення, React пропустить перерендеринг вашого компонента навіть без `memo`.

---

### Оновлення мемоїзованого компонента через контекст

Навіть коли компонент мемоїзований, він все одно перерендерюватиметься при зміні контексту, який він використовує. Мемоїзація стосується лише пропсів від батьківського компонента.

```js
import { createContext, memo, useContext, useState } from 'react';

const ThemeContext = createContext(null);

export default function MyApp() {
  const [theme, setTheme] = useState('dark');

  function handleClick() {
    setTheme(theme === 'dark' ? 'light' : 'dark');
  }

  return (
    <ThemeContext value={theme}>
      <button onClick={handleClick}>
        Switch theme
      </button>
      <Greeting name="Taylor" />
    </ThemeContext>
  );
}

const Greeting = memo(function Greeting({ name }) {
  console.log("Greeting was rendered at", new Date().toLocaleTimeString());
  const theme = useContext(ThemeContext);
  return (
    <h3 className={theme}>Hello, {name}!</h3>
  );
});
```

Щоб компонент перерендерювався лише при зміні *частини* контексту, розділіть компонент на два. Читайте потрібне з контексту у зовнішньому компоненті та передайте це мемоїзованому дочірньому як проп.

### Мінімізація змін пропсів

При використанні `memo` ваш компонент перерендерюється щоразу, коли будь-який проп не є *поверхнево рівним* попередньому. React порівнює кожен проп за допомогою [`Object.is`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/is): `Object.is(3, 3)` — це `true`, але `Object.is({}, {})` — це `false`.

#### Використання `useMemo` для пропсів-об'єктів

```js
function Page() {
  const [name, setName] = useState('Taylor');
  const [age, setAge] = useState(42);

  const person = useMemo(
    () => ({ name, age }),
    [name, age]
  );

  return <Profile person={person} />;
}

const Profile = memo(function Profile({ person }) {
  // ...
});
```

#### Кращий підхід: Мінімізуйте інформацію в пропсах

Замість передачі цілих об'єктів приймайте окремі значення:

```js
function Page() {
  const [name, setName] = useState('Taylor');
  const [age, setAge] = useState(42);
  return <Profile name={name} age={age} />;
}

const Profile = memo(function Profile({ name, age }) {
  // ...
});
```

#### Проєктуйте значення, що змінюються рідше

```js
function GroupsLanding({ person }) {
  const hasGroups = person.groups !== null;
  return <CallToAction hasGroups={hasGroups} />;
}

const CallToAction = memo(function CallToAction({ hasGroups }) {
  // ...
});
```

#### Для пропсів-функцій

Або оголосіть функції поза компонентом, або використовуйте [`useCallback`](/reference/react/useCallback):

```js
const handleClick = () => { /* ... */ }; // Визначено зовні

// АБО

const handleClick = useCallback(() => { /* ... */ }, []);
```

### Вказання користувацької функції порівняння

У рідкісних випадках, коли мінімізація змін пропсів неможлива, ви можете надати користувацьку функцію порівняння як другий аргумент `memo`. React використовуватиме її замість поверхневої рівності.

```js
const Chart = memo(function Chart({ dataPoints }) {
  // ...
}, arePropsEqual);

function arePropsEqual(oldProps, newProps) {
  return (
    oldProps.dataPoints.length === newProps.dataPoints.length &&
    oldProps.dataPoints.every((oldPoint, index) => {
      const newPoint = newProps.dataPoints[index];
      return oldPoint.x === newPoint.x && oldPoint.y === newPoint.y;
    })
  );
}
```

Функція повинна повертати `true` лише якщо нові пропси призведуть до того самого виводу, що й старі.

> **Попередження**: Якщо ви надаєте користувацьку реалізацію `arePropsEqual`, **ви повинні порівнювати кожен проп, включаючи функції**. Функції часто замикають пропси та стан батьківських компонентів. Якщо ви повернете `true`, коли `oldProps.onClick !== newProps.onClick`, ваш компонент продовжить "бачити" пропси та стан з попереднього рендеру всередині обробника `onClick`, що призведе до заплутаних помилок.
>
> Уникайте глибоких перевірок рівності всередині `arePropsEqual`, якщо ви не впевнені на 100%, що структура даних має відому обмежену глибину. **Глибокі перевірки рівності можуть стати неймовірно повільними** та заморозити ваш застосунок.

## Інтеграція з React Compiler

### Чи потрібен `React.memo` при використанні React Compiler?

Коли ви вмикаєте [React Compiler](/learn/react-compiler), вам зазвичай більше не потрібен `React.memo`. Компілятор автоматично оптимізує повторний рендеринг компонентів.

#### Без React Compiler

Вам потрібен `React.memo` для запобігання непотрібним перерендерам:

```js
// Батьківський компонент перерендерюється кожну секунду
function Parent() {
  const [seconds, setSeconds] = useState(0);

  useEffect(() => {
    const interval = setInterval(() => {
      setSeconds(s => s + 1);
    }, 1000);
    return () => clearInterval(interval);
  }, []);

  return (
    <>
      <h1>Seconds: {seconds}</h1>
      <ExpensiveChild name="John" />
    </>
  );
}

// Без memo перерендерюється кожну секунду, хоча пропси не змінюються
const ExpensiveChild = memo(function ExpensiveChild({ name }) {
  console.log('ExpensiveChild rendered');
  return <div>Hello, {name}!</div>;
});
```

#### З увімкненим React Compiler

Та сама оптимізація відбувається автоматично без `memo`:

```js
// memo не потрібен — компілятор запобігає перерендерам автоматично
function ExpensiveChild({ name }) {
  console.log('ExpensiveChild rendered');
  return <div>Hello, {name}!</div>;
}
```

**Результат:** Ви можете безпечно видалити `React.memo` з ваших компонентів при використанні React Compiler. Компілятор надає ту саму оптимізацію автоматично, роблячи ваш код чистішим та легшим для підтримки.

> **Примітка**: Оптимізація компілятора насправді більш всеосяжна, ніж `React.memo`. Він також мемоїзує проміжні значення та ресурсомісткі обчислення всередині ваших компонентів, подібно до комбінування `React.memo` з `useMemo` по всьому дереву компонентів.

## Усунення проблем

### Мій компонент перерендерюється, коли проп є об'єктом, масивом або функцією

React порівнює старі та нові пропси за допомогою поверхневої рівності — він перевіряє, чи кожен новий проп рівний за посиланням старому. Якщо ви створюєте новий об'єкт або масив кожного разу при перерендері батьківського компонента, навіть якщо окремі елементи однакові, React все одно вважатиме їх зміненими. Аналогічно, якщо ви створюєте нову функцію при рендерингу батьківського компонента, React вважатиме її зміненою, навіть якщо визначення функції таке саме.

**Рішення:** Спрощуйте пропси або мемоїзуйте пропси в батьківському компоненті.
