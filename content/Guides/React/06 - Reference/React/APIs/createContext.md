# `createContext`

## Огляд

`createContext` дозволяє створити контекст, який компоненти можуть надавати або читати.

```js
const SomeContext = createContext(defaultValue)
```

---

## Довідка

### `createContext(defaultValue)`

Викликайте `createContext` поза будь-якими компонентами для створення контексту.

```js
import { createContext } from 'react';

const ThemeContext = createContext('light');
```

#### Параметри

- `defaultValue`: Значення, яке ви хочете надати контексту, коли в дереві над компонентом, що читає контекст, немає відповідного провайдера контексту. Якщо у вас немає значущого значення за замовчуванням, вкажіть `null`. Значення за замовчуванням призначене як "крайній випадок" запасного варіанту. Воно статичне і ніколи не змінюється з часом.

#### Повертає

`createContext` повертає об'єкт контексту.

**Сам об'єкт контексту не містить жодної інформації.** Він представляє, *який* контекст інші компоненти читають або надають. Зазвичай ви використовуватимете `SomeContext` у компонентах вище для вказання значення контексту, та викликатимете `useContext(SomeContext)` у компонентах нижче для його читання. Об'єкт контексту має кілька властивостей:

- `SomeContext` дозволяє надавати значення контексту компонентам.
- `SomeContext.Consumer` — це альтернативний і рідко використовуваний спосіб читання значення контексту.
- `SomeContext.Provider` — це застарілий спосіб надання значення контексту до React 19.

---

### Провайдер `SomeContext`

Обгорніть ваші компоненти у провайдер контексту, щоб вказати значення цього контексту для всіх компонентів всередині:

```js
function App() {
  const [theme, setTheme] = useState('light');
  // ...
  return (
    <ThemeContext value={theme}>
      <Page />
    </ThemeContext>
  );
}
```

> **Примітка**: Починаючи з React 19, ви можете рендерити `<SomeContext>` як провайдер. У старіших версіях React використовуйте `<SomeContext.Provider>`.

#### Пропси

- `value`: Значення, яке ви хочете передати всім компонентам, що читають цей контекст всередині цього провайдера, незалежно від глибини вкладеності. Значення контексту може бути будь-якого типу. Компонент, що викликає `useContext(SomeContext)` всередині провайдера, отримує `value` найближчого відповідного провайдера контексту над ним.

---

### `SomeContext.Consumer`

До появи `useContext` існував старіший спосіб читання контексту:

```js
function Button() {
  // Застарілий спосіб (не рекомендується)
  return (
    <ThemeContext.Consumer>
      {theme => (
        <button className={theme} />
      )}
    </ThemeContext.Consumer>
  );
}
```

Хоча цей старіший спосіб все ще працює, **новий код повинен читати контекст за допомогою `useContext()`:**

```js
function Button() {
  // Рекомендований спосіб
  const theme = useContext(ThemeContext);
  return <button className={theme} />;
}
```

#### Пропси

- `children`: Функція. React викличе функцію, яку ви передаєте, з поточним значенням контексту, визначеним тим самим алгоритмом, що й `useContext()`, та відрендерить результат, який ви повернете з цієї функції. React також повторно запустить цю функцію та оновить UI щоразу, коли контекст з батьківських компонентів зміниться.

## Використання

### Створення контексту

Контекст дозволяє компонентам передавати інформацію глибоко вниз без явної передачі пропсів.

Викликайте `createContext` поза будь-якими компонентами для створення одного або кількох контекстів.

```js
import { createContext } from 'react';

const ThemeContext = createContext('light');
const AuthContext = createContext(null);
```

`createContext` повертає об'єкт контексту. Компоненти можуть читати контекст, передаючи його в `useContext()`:

```js
function Button() {
  const theme = useContext(ThemeContext);
  // ...
}

function Profile() {
  const currentUser = useContext(AuthContext);
  // ...
}
```

За замовчуванням значення, які вони отримують, будуть значеннями за замовчуванням, які ви вказали при створенні контекстів. Однак само по собі це не корисно, оскільки значення за замовчуванням ніколи не змінюються.

Контекст корисний, оскільки ви можете **надавати інші, динамічні значення з ваших компонентів:**

```js
function App() {
  const [theme, setTheme] = useState('dark');
  const [currentUser, setCurrentUser] = useState({ name: 'Taylor' });

  // ...

  return (
    <ThemeContext value={theme}>
      <AuthContext value={currentUser}>
        <Page />
      </AuthContext>
    </ThemeContext>
  );
}
```

Тепер компонент `Page` та будь-які компоненти всередині нього, незалежно від глибини, "бачитимуть" передані значення контексту. Якщо передані значення контексту змінюються, React також перерендерить компоненти, що читають контекст.

---

### Імпорт та експорт контексту з файлу

Часто компонентам у різних файлах потрібен доступ до одного контексту. Тому зазвичай контексти оголошуються в окремому файлі. Потім можна використовувати оператор `export`, щоб зробити контекст доступним для інших файлів:

```js
// Contexts.js
import { createContext } from 'react';

export const ThemeContext = createContext('light');
export const AuthContext = createContext(null);
```

Компоненти, оголошені в інших файлах, можуть використовувати оператор `import` для читання або надання цього контексту:

```js
// Button.js
import { ThemeContext } from './Contexts.js';

function Button() {
  const theme = useContext(ThemeContext);
  // ...
}
```

```js
// App.js
import { ThemeContext, AuthContext } from './Contexts.js';

function App() {
  // ...
  return (
    <ThemeContext value={theme}>
      <AuthContext value={currentUser}>
        <Page />
      </AuthContext>
    </ThemeContext>
  );
}
```

Це працює подібно до імпорту та експорту компонентів.

## Усунення проблем

### Не можу знайти спосіб змінити значення контексту

Код на кшталт цього вказує значення контексту *за замовчуванням*:

```js
const ThemeContext = createContext('light');
```

Це значення ніколи не змінюється. React використовує це значення лише як запасний варіант, якщо не може знайти відповідний провайдер вище.

Щоб зробити контекст змінним з часом, додайте стан та обгорніть компоненти у провайдер контексту.
