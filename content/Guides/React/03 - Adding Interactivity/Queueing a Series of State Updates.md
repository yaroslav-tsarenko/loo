# Постановка в чергу серії оновлень state

## Вступ

Встановлення змінної state ставить у чергу інший render. Але іноді ви можете захотіти виконати кілька операцій над значенням перед постановкою наступного render у чергу. Щоб зрозуміти, як це зробити, потрібно зрозуміти, як React групує оновлення state.

### Ви дізнаєтесь

- Що таке "батчинг" (batching) і як React використовує його для обробки кількох оновлень state
- Як застосувати кілька оновлень до однієї змінної state підряд

## React групує оновлення state

Ви можете очікувати, що натискання кнопки "+3" збільшить лічильник тричі, тому що вона викликає `setNumber(number + 1)` тричі:

```js
import { useState } from 'react';

export default function Counter() {
  const [number, setNumber] = useState(0);

  return (
    <>
      <h1>{number}</h1>
      <button onClick={() => {
        setNumber(number + 1);
        setNumber(number + 1);
        setNumber(number + 1);
      }}>+3</button>
    </>
  )
}
```

Проте значення state кожного render є фіксованими, тому значення `number` всередині обробника подій першого render завжди `0`, незалежно від того, скільки разів ви викликаєте `setNumber(1)`:

```js
setNumber(0 + 1);
setNumber(0 + 1);
setNumber(0 + 1);
```

**React чекає, поки *весь* код в обробниках подій виконається, перш ніж обробляти ваші оновлення state.** Тому повторний render відбувається лише *після* всіх цих викликів `setNumber()`.

Це схоже на офіціанта, який приймає замовлення в ресторані — він не біжить на кухню при згадці першої страви. Натомість він дає вам закінчити замовлення, дозволяє внести зміни та приймає замовлення від інших людей за столом.

Ця поведінка, також відома як **батчинг** (batching), дозволяє оновлювати кілька змінних state — навіть з кількох компонентів — без запуску занадто багатьох повторних render'ів. Проте це також означає, що UI не оновиться до *завершення* вашого обробника подій та всього коду в ньому. Це робить ваш додаток React набагато швидшим та дозволяє уникнути заплутаних "незавершених" render'ів, де оновлена лише частина змінних.

**React не групує *кілька* навмисних подій, таких як кліки** — кожен клік обробляється окремо. React групує лише тоді, коли це загалом безпечно. Це гарантує, що, наприклад, якщо перший клік вимикає форму, другий клік не відправить її знову.

## Оновлення одного state кілька разів перед наступним render

Це нетипове використання, але якщо ви хочете оновити одну й ту саму змінну state кілька разів перед наступним render, замість передачі *наступного значення state* як `setNumber(number + 1)`, ви можете передати *функцію*, яка обчислює наступний state на основі попереднього в черзі, наприклад `setNumber(n => n + 1)`. Це спосіб сказати React "зробити щось зі значенням state" замість простої заміни.

Спробуйте збільшити лічильник тепер:

```js
import { useState } from 'react';

export default function Counter() {
  const [number, setNumber] = useState(0);

  return (
    <>
      <h1>{number}</h1>
      <button onClick={() => {
        setNumber(n => n + 1);
        setNumber(n => n + 1);
        setNumber(n => n + 1);
      }}>+3</button>
    </>
  )
}
```

Тут `n => n + 1` називається **функцією-оновлювачем** (updater function). Коли ви передаєте її в сетер state:

1. React ставить цю функцію в чергу для обробки після виконання всього іншого коду в обробнику подій.
2. Під час наступного render React проходить через чергу та надає вам остаточний оновлений state.

```js
setNumber(n => n + 1);
setNumber(n => n + 1);
setNumber(n => n + 1);
```

Ось як React обробляє ці рядки коду під час виконання обробника подій:

1. `setNumber(n => n + 1)`: `n => n + 1` — це функція. React додає її в чергу.
2. `setNumber(n => n + 1)`: `n => n + 1` — це функція. React додає її в чергу.
3. `setNumber(n => n + 1)`: `n => n + 1` — це функція. React додає її в чергу.

Коли ви викликаєте `useState` під час наступного render, React проходить через чергу. Попередній state `number` був `0`, тому це те, що React передає першій функції-оновлювачу як аргумент `n`. Потім React бере повернене значення попередньої функції-оновлювача та передає його наступному оновлювачу як `n`, і так далі:

| оновлення в черзі | `n` | повертає |
|---|---|---|
| `n => n + 1` | `0` | `0 + 1 = 1` |
| `n => n + 1` | `1` | `1 + 1 = 2` |
| `n => n + 1` | `2` | `2 + 1 = 3` |

React зберігає `3` як кінцевий результат і повертає його з `useState`.

Тому натискання "+3" у прикладі вище правильно збільшує значення на 3.

### Що відбувається, якщо ви оновлюєте state після заміни

Що щодо цього обробника подій? Як ви думаєте, яким буде `number` при наступному render?

```js
<button onClick={() => {
  setNumber(number + 5);
  setNumber(n => n + 1);
}}>
```

```js
import { useState } from 'react';

export default function Counter() {
  const [number, setNumber] = useState(0);

  return (
    <>
      <h1>{number}</h1>
      <button onClick={() => {
        setNumber(number + 5);
        setNumber(n => n + 1);
      }}>Increase the number</button>
    </>
  )
}
```

Ось що цей обробник подій каже React зробити:

1. `setNumber(number + 5)`: `number` — це `0`, тому `setNumber(0 + 5)`. React додає *"замінити на `5`"* у свою чергу.
2. `setNumber(n => n + 1)`: `n => n + 1` — це функція-оновлювач. React додає *цю функцію* у свою чергу.

Під час наступного render React проходить через чергу state:

| оновлення в черзі | `n` | повертає |
|---|---|---|
| "замінити на `5`" | `0` (не використовується) | `5` |
| `n => n + 1` | `5` | `5 + 1 = 6` |

React зберігає `6` як кінцевий результат і повертає його з `useState`.

> **Примітка:** Ви могли помітити, що `setState(5)` фактично працює як `setState(n => 5)`, але `n` не використовується!

### Що відбувається, якщо ви замінюєте state після оновлення

Спробуємо ще один приклад. Як ви думаєте, яким буде `number` при наступному render?

```js
<button onClick={() => {
  setNumber(number + 5);
  setNumber(n => n + 1);
  setNumber(42);
}}>
```

```js
import { useState } from 'react';

export default function Counter() {
  const [number, setNumber] = useState(0);

  return (
    <>
      <h1>{number}</h1>
      <button onClick={() => {
        setNumber(number + 5);
        setNumber(n => n + 1);
        setNumber(42);
      }}>Increase the number</button>
    </>
  )
}
```

Ось як React обробляє ці рядки коду під час виконання цього обробника подій:

1. `setNumber(number + 5)`: `number` — це `0`, тому `setNumber(0 + 5)`. React додає *"замінити на `5`"* у свою чергу.
2. `setNumber(n => n + 1)`: `n => n + 1` — це функція-оновлювач. React додає *цю функцію* у свою чергу.
3. `setNumber(42)`: React додає *"замінити на `42`"* у свою чергу.

Під час наступного render React проходить через чергу state:

| оновлення в черзі | `n` | повертає |
|---|---|---|
| "замінити на `5`" | `0` (не використовується) | `5` |
| `n => n + 1` | `5` | `5 + 1 = 6` |
| "замінити на `42`" | `6` (не використовується) | `42` |

Потім React зберігає `42` як кінцевий результат і повертає його з `useState`.

Підсумовуючи, ось як можна думати про те, що ви передаєте в сетер state `setNumber`:

- **Функція-оновлювач** (наприклад, `n => n + 1`) додається в чергу.
- **Будь-яке інше значення** (наприклад, число `5`) додає "замінити на `5`" у чергу, ігноруючи те, що вже в черзі.

Після завершення обробника подій React запустить повторний render. Під час повторного render React обробить чергу. Функції-оновлювачі виконуються під час render, тому **функції-оновлювачі повинні бути чистими (pure)** і лише *повертати* результат. Не намагайтеся встановлювати state зсередини них або запускати інші побічні ефекти. У Strict Mode React запустить кожну функцію-оновлювач двічі (але відкине другий результат), щоб допомогти знайти помилки.

### Конвенції іменування

Поширеною практикою є називати аргумент функції-оновлювача першими літерами відповідної змінної state:

```js
setEnabled(e => !e);
setLastName(ln => ln.reverse());
setFriendCount(fc => fc * 2);
```

Якщо ви віддаєте перевагу більш розгорнутому коду, інша поширена конвенція — повторити повну назву змінної state, наприклад `setEnabled(enabled => !enabled)`, або використовувати префікс, наприклад `setEnabled(prevEnabled => !prevEnabled)`.

## Підсумок

- Встановлення state не змінює змінну в поточному render, але запитує новий render.
- React обробляє оновлення state після завершення виконання обробників подій. Це називається батчинг.
- Щоб оновити state кілька разів в одній події, використовуйте функцію-оновлювач `setNumber(n => n + 1)`.

## Завдання

### Завдання 1: Виправте лічильник запитів

Ви працюєте над додатком-маркетплейсом мистецтва, який дозволяє користувачу надсилати кілька замовлень одночасно. Кожного разу, коли користувач натискає кнопку "Buy", лічильник "Pending" повинен збільшуватися на одиницю. Через три секунди лічильник "Pending" повинен зменшуватися, а лічильник "Completed" — збільшуватися.

Проте лічильник "Pending" поводиться не так, як очікувалося. При натисканні "Buy" він зменшується до `-1` (що не повинно бути можливим!). І якщо натиснути швидко двічі, обидва лічильники поводяться непередбачувано.

Чому це відбувається? Виправте обидва лічильники.

```js
import { useState } from 'react';

export default function RequestTracker() {
  const [pending, setPending] = useState(0);
  const [completed, setCompleted] = useState(0);

  async function handleClick() {
    setPending(pending + 1);
    await delay(3000);
    setPending(pending - 1);
    setCompleted(completed + 1);
  }

  return (
    <>
      <h3>
        Pending: {pending}
      </h3>
      <h3>
        Completed: {completed}
      </h3>
      <button onClick={handleClick}>
        Buy
      </button>
    </>
  );
}

function delay(ms) {
  return new Promise(resolve => {
    setTimeout(resolve, ms);
  });
}
```

#### Рішення

Всередині обробника подій `handleClick` значення `pending` та `completed` відповідають тому, якими вони були на момент події кліку. Для першого render `pending` був `0`, тому `setPending(pending - 1)` стає `setPending(-1)`, що неправильно. Оскільки ви хочете *збільшити* або *зменшити* лічильники, а не встановити їх у конкретне значення, визначене під час кліку, натомість передайте функції-оновлювачі:

```js
import { useState } from 'react';

export default function RequestTracker() {
  const [pending, setPending] = useState(0);
  const [completed, setCompleted] = useState(0);

  async function handleClick() {
    setPending(p => p + 1);
    await delay(3000);
    setPending(p => p - 1);
    setCompleted(c => c + 1);
  }

  return (
    <>
      <h3>
        Pending: {pending}
      </h3>
      <h3>
        Completed: {completed}
      </h3>
      <button onClick={handleClick}>
        Buy
      </button>
    </>
  );
}

function delay(ms) {
  return new Promise(resolve => {
    setTimeout(resolve, ms);
  });
}
```

Це гарантує, що при збільшенні або зменшенні лічильника ви робите це відносно його *останнього* state, а не state на момент кліку.

### Завдання 2: Реалізуйте чергу state самостійно

У цьому завданні ви реалізуєте невелику частину React з нуля! Це не так складно, як здається.

Зверніть увагу, що є **чотири тестові випадки.** Вони відповідають прикладам, які ви бачили раніше на цій сторінці. Ваше завдання — реалізувати функцію `getFinalState` так, щоб вона повертала правильний результат для кожного з цих випадків.

Ви отримаєте два аргументи: `baseState` — початковий state (наприклад, `0`), і `queue` — масив, що містить суміш чисел (наприклад, `5`) та функцій-оновлювачів (наприклад, `n => n + 1`) у порядку додавання.

Ваше завдання — повернути кінцевий state, як показують таблиці на цій сторінці!

#### Підказка

Якщо відчуваєте, що застрягли, почніть з цієї структури коду:

```js
export function getFinalState(baseState, queue) {
  let finalState = baseState;

  for (let update of queue) {
    if (typeof update === 'function') {
      // TODO: застосувати функцію-оновлювач
    } else {
      // TODO: замінити state
    }
  }

  return finalState;
}
```

Заповніть відсутні рядки!

#### Рішення

Це саме той алгоритм, описаний на цій сторінці, який React використовує для обчислення кінцевого state:

```js
export function getFinalState(baseState, queue) {
  let finalState = baseState;

  for (let update of queue) {
    if (typeof update === 'function') {
      // Застосувати функцію-оновлювач.
      finalState = update(finalState);
    } else {
      // Замінити наступний state.
      finalState = update;
    }
  }

  return finalState;
}
```

Тепер ви знаєте, як працює ця частина React!
