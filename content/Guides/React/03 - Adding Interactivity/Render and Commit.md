# Render та Commit

## Вступ

Перш ніж ваші компоненти відобразяться на екрані, вони повинні бути відрендерені React. Розуміння кроків у цьому процесі допоможе вам зрозуміти, як виконується ваш код та пояснити його поведінку.

### Ви дізнаєтесь

- Що означає render у React
- Коли і чому React рендерить компонент
- Кроки, що беруть участь у відображенні компонента на екрані
- Чому render не завжди призводить до оновлення DOM

---

## Огляд: Триетапний процес

Уявіть, що ваші компоненти — це кухарі на кухні, які готують смачні страви з інгредієнтів. У цьому сценарії React — це офіціант, який приймає замовлення від клієнтів та приносить їм їжу. Цей процес запиту та подачі UI має три кроки:

1. **Тригер** render (доставка замовлення гостя на кухню)
2. **Render** компонента (підготовка замовлення на кухні)
3. **Commit** у DOM (розміщення замовлення на столі)

---

## Крок 1: Тригер render

Є дві причини для render компонента:

1. Це **початковий render** компонента.
2. **State** компонента (або одного з його предків) **було оновлено**.

### Початковий render

Коли ваш додаток запускається, потрібно запустити початковий render. Фреймворки та пісочниці іноді приховують цей код, але він виконується шляхом виклику `createRoot` з цільовим DOM-вузлом, а потім виклику його методу `render` з вашим компонентом:

```js
import Image from './Image.js';
import { createRoot } from 'react-dom/client';

const root = createRoot(document.getElementById('root'))
root.render(<Image />);
```

```js
export default function Image() {
  return (
    <img
      src="https://react.dev/images/docs/scientists/ZF6s192.jpg"
      alt="'Floralis Genérica' by Eduardo Catalano: a gigantic metallic flower sculpture with reflective petals"
    />
  );
}
```

Спробуйте закоментувати виклик `root.render()` та побачите, як компонент зникне!

### Повторні render при оновленні state

Після початкового render компонента ви можете запускати подальші render'и, оновлюючи його state за допомогою функції `set`. Оновлення state компонента автоматично ставить render у чергу. (Уявіть це як гостя ресторану, який замовляє чай, десерт та різні інші речі після першого замовлення, залежно від стану його спраги чи голоду.)

---

## Крок 2: React рендерить ваші компоненти

Після того як ви запустили render, React викликає ваші компоненти, щоб з'ясувати, що відобразити на екрані. **"Render" — це React, який викликає ваші компоненти.**

- **При початковому render** React викличе кореневий компонент.
- **При подальших render'ах** React викличе функціональний компонент, оновлення state якого запустило render.

Цей процес рекурсивний: якщо оновлений компонент повертає інший компонент, React відрендерить _той_ компонент далі, і якщо той компонент також щось повертає, він відрендерить _той_ компонент далі, і так далі. Процес продовжиться, поки не залишиться вкладених компонентів і React точно знатиме, що повинно бути відображено на екрані.

У наступному прикладі React викличе `Gallery()` та `Image()` кілька разів:

```js
export default function Gallery() {
  return (
    <section>
      <h1>Inspiring Sculptures</h1>
      <Image />
      <Image />
      <Image />
    </section>
  );
}

function Image() {
  return (
    <img
      src="https://react.dev/images/docs/scientists/ZF6s192.jpg"
      alt="'Floralis Genérica' by Eduardo Catalano: a gigantic metallic flower sculpture with reflective petals"
    />
  );
}
```

- **Під час початкового render** React створить DOM-вузли для `<section>`, `<h1>` та трьох тегів `<img>`.
- **Під час повторного render** React обчислить, які з їхніх властивостей, якщо такі є, змінилися з попереднього render. Він нічого не зробить з цією інформацією до наступного кроку — фази commit.

### Застереження: Render повинен завжди бути чистим обчисленням

Render повинен завжди бути чистим обчисленням:

- **Однакові вхідні дані, однаковий результат.** За однакових вхідних даних компонент повинен завжди повертати той самий JSX. (Коли хтось замовляє салат з помідорами, він не повинен отримати салат з цибулею!)
- **Він займається своєю справою.** Він не повинен змінювати жодних об'єктів чи змінних, що існували до render. (Одне замовлення не повинно змінювати замовлення іншого.)

Інакше ви можете зіткнутися зі заплутаними помилками та непередбачуваною поведінкою в міру зростання складності вашої кодової бази. При розробці в "Strict Mode" React викликає функцію кожного компонента двічі, що допомагає виявити помилки, спричинені нечистими функціями.

### Поглиблено: Оптимізація продуктивності

Поведінка за замовчуванням — рендерити всі компоненти, вкладені в оновлений компонент — не є оптимальною для продуктивності, якщо оновлений компонент знаходиться дуже високо в дереві. Якщо ви зіткнулися з проблемою продуктивності, є кілька опціональних способів вирішення, описаних у розділі Продуктивність. **Не оптимізуйте передчасно!**

## Крок 3: React виконує commit змін у DOM

Після render (виклику) ваших компонентів React модифікує DOM.

- **При початковому render** React використовує DOM API `appendChild()`, щоб розмістити всі створені DOM-вузли на екрані.
- **При повторних render'ах** React застосовує мінімально необхідні операції (обчислені під час render!), щоб DOM відповідав останньому результату render.

**React змінює DOM-вузли лише якщо є різниця між render'ами.** Наприклад, ось компонент, який повторно рендериться з різними props, переданими від батьківського компонента щосекунди. Зверніть увагу, що ви можете додати текст у `<input>`, оновлюючи його `value`, але текст не зникає при повторному render компонента:

```js
export default function Clock({ time }) {
  return (
    <>
      <h1>{time}</h1>
      <input />
    </>
  );
}
```

Це працює, тому що на останньому кроці React оновлює лише вміст `<h1>` з новим `time`. Він бачить, що `<input>` з'являється в JSX на тому ж місці, що й минулого разу, тому React не чіпає `<input>` — або його `value`!

---

## Епілог: Відмальовування браузером

Після того як render завершено і React оновив DOM, браузер перемалює екран. Хоча цей процес відомий як "browser rendering", ми називаємо його "відмальовуванням" (painting), щоб уникнути плутанини.

---

## Підсумок

- Будь-яке оновлення екрана в додатку React відбувається у три кроки:
  1. Тригер
  2. Render
  3. Commit
- Ви можете використовувати Strict Mode для пошуку помилок у ваших компонентах
- React не чіпає DOM, якщо результат render такий самий, як минулого разу
