# Ваш UI як дерево

## Вступ

Ваш додаток React набуває форми з багатьма компонентами, вкладеними один в одного. Як React відстежує структуру компонентів вашого додатку?

React, як і багато інших UI-бібліотек, моделює UI як дерево. Уявлення вашого додатку як дерева корисне для розуміння відносин між компонентами. Це розуміння допоможе вам налагоджувати майбутні концепції, такі як продуктивність та управління state.

### Ви дізнаєтесь

* Як React "бачить" структури компонентів
* Що таке дерево рендерингу і для чого воно корисне
* Що таке дерево залежностей модулів і для чого воно корисне

---

## Ваш UI як дерево

Дерева — це модель відносин між елементами. UI часто представляється за допомогою деревоподібних структур. Наприклад, браузери використовують деревоподібні структури для моделювання HTML ([DOM](https://developer.mozilla.org/docs/Web/API/Document_Object_Model/Introduction)) та CSS ([CSSOM](https://developer.mozilla.org/docs/Web/API/CSS_Object_Model)). Мобільні платформи також використовують дерева для представлення ієрархії відображень.

React створює UI-дерево з ваших компонентів. Як і браузери та мобільні платформи, React також використовує деревоподібні структури для управління та моделювання відносин між компонентами в додатку React. Ці дерева є корисними інструментами для розуміння потоку даних через додаток React та оптимізації рендерингу і розміру додатку.

---

## Дерево рендерингу

Головна особливість компонентів — це можливість створювати компоненти з інших компонентів. Коли ми вкладаємо компоненти, ми маємо концепцію батьківських і дочірніх компонентів, де кожен батьківський компонент сам може бути дочірнім для іншого компонента.

Коли ми рендеримо додаток React, ми можемо змоделювати ці відносини у дереві, відомому як дерево рендерингу.

### Приклад: Додаток з надихаючими цитатами

```js
// src/App.js
import FancyText from './FancyText';
import InspirationGenerator from './InspirationGenerator';
import Copyright from './Copyright';

export default function App() {
  return (
    <>
      <FancyText title text="Get Inspired App" />
      <InspirationGenerator>
        <Copyright year={2004} />
      </InspirationGenerator>
    </>
  );
}
```

```js
// src/FancyText.js
export default function FancyText({title, text}) {
  return title
    ? <h1 className='fancy title'>{text}</h1>
    : <h3 className='fancy cursive'>{text}</h3>
}
```

```js
// src/InspirationGenerator.js
import * as React from 'react';
import quotes from './quotes';
import FancyText from './FancyText';

export default function InspirationGenerator({children}) {
  const [index, setIndex] = React.useState(0);
  const quote = quotes[index];
  const next = () => setIndex((index + 1) % quotes.length);

  return (
    <>
      <p>Your inspirational quote is:</p>
      <FancyText text={quote} />
      <button onClick={next}>Inspire me again</button>
      {children}
    </>
  );
}
```

```js
// src/Copyright.js
export default function Copyright({year}) {
  return <p className='small'>©️ {year}</p>;
}
```

```js
// src/quotes.js
export default [
  "Don't let yesterday take up too much of today." — Will Rogers",
  "Ambition is putting a ladder against the sky.",
  "A joy that's shared is a joy made double.",
];
```

### Розуміння структури дерева рендерингу

React створює *дерево рендерингу*, UI-дерево, що складається з відрендерених компонентів.

З прикладу додатку ми можемо побудувати дерево рендерингу:

* **Кореневий вузол**: `App` (перший компонент, який React рендерить)
* **Дочірні вузли**: `FancyText` та `InspirationGenerator`
* **Внучаті вузли**: Ще один `FancyText` (відрендерений InspirationGenerator) та `Copyright` (переданий як children)

Дерево складається з вузлів, кожен з яких представляє компонент. Кожна стрілка в дереві вказує від батьківського компонента до дочірнього.

### Де HTML-теги в дереві рендерингу?

Ви помітите, що в дереві рендерингу немає згадки про HTML-теги, які рендерить кожен компонент. Це тому, що дерево рендерингу складається лише з компонентів React.

React, як UI-фреймворк, є платформо-незалежним. На react.dev ми показуємо приклади, що рендеряться у веб, який використовує HTML-розмітку як свої UI-примітиви. Але додаток React з тим самим успіхом може рендеритися на мобільній або десктопній платформі, які можуть використовувати інші UI-примітиви, такі як [UIView](https://developer.apple.com/documentation/uikit/uiview) або [FrameworkElement](https://learn.microsoft.com/en-us/dotnet/api/system.windows.frameworkelement?view=windowsdesktop-7.0).

Ці платформні UI-примітиви не є частиною React. Дерева рендерингу React можуть надати розуміння вашого додатку React незалежно від того, на якій платформі він рендериться.

### Умовний рендеринг та дерева рендерингу

Дерево рендерингу представляє один прохід рендерингу додатку React. З умовним рендерингом батьківський компонент може рендерити різних дочірніх залежно від переданих даних.

#### Приклад: Умовний рендеринг цитати або кольору

```js
// src/InspirationGenerator.js
import * as React from 'react';
import inspirations from './inspirations';
import FancyText from './FancyText';
import Color from './Color';

export default function InspirationGenerator({children}) {
  const [index, setIndex] = React.useState(0);
  const inspiration = inspirations[index];
  const next = () => setIndex((index + 1) % inspirations.length);

  return (
    <>
      <p>Your inspirational {inspiration.type} is:</p>
      {inspiration.type === 'quote'
      ? <FancyText text={inspiration.value} />
      : <Color value={inspiration.value} />}

      <button onClick={next}>Inspire me again</button>
      {children}
    </>
  );
}
```

```js
// src/Color.js
export default function Color({value}) {
  return <div className="colorbox" style={{backgroundColor: value}} />
}
```

```js
// src/inspirations.js
export default [
  {type: 'quote', value: "Don't let yesterday take up too much of today." — Will Rogers"},
  {type: 'color', value: "#B73636"},
  {type: 'quote', value: "Ambition is putting a ladder against the sky."},
  {type: 'color', value: "#256266"},
  {type: 'quote', value: "A joy that's shared is a joy made double."},
  {type: 'color', value: "#F9F2B4"},
];
```

У цьому прикладі, залежно від значення `inspiration.type`, ми можемо рендерити `<FancyText>` або `<Color>`. Дерево рендерингу може бути різним для кожного проходу рендерингу.

### Компоненти верхнього рівня та листові компоненти

Хоча дерева рендерингу можуть відрізнятися для різних проходів рендерингу, ці дерева загалом корисні для визначення *компонентів верхнього рівня* та *листових компонентів* у додатку React:

* **Компоненти верхнього рівня** — це компоненти, найближчі до кореневого компонента, які впливають на продуктивність рендерингу всіх компонентів під ними і часто містять найбільшу складність.
* **Листові компоненти** — знаходяться біля низу дерева, не мають дочірніх компонентів і часто перерендерюються.

Визначення цих категорій компонентів корисне для розуміння потоку даних та продуктивності вашого додатку.

## Дерево залежностей модулів

Інші відносини в додатку React, які можна змоделювати деревом, — це залежності модулів додатку. Коли ми розбиваємо наші компоненти та логіку на окремі файли, ми створюємо [JS-модулі](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules), де можемо експортувати компоненти, функції або константи.

Кожен вузол у дереві залежностей модулів — це модуль, і кожна гілка представляє оператор `import` у цьому модулі.

Якщо ми візьмемо попередній додаток Inspirations, ми можемо побудувати дерево залежностей модулів (або просто дерево залежностей):

* **Кореневий вузол**: `App.js` (файл точки входу, що зазвичай містить кореневий компонент)
* **Залежності першого рівня**: `InspirationGenerator.js`, `FancyText.js`, `Copyright.js`
* **Залежності другого рівня**: З `InspirationGenerator.js` — `FancyText.js`, `Color.js`, `inspirations.js`

### Відмінності між деревом рендерингу та деревом залежностей модулів

Порівнюючи дерево рендерингу та дерево залежностей модулів того самого додатку, є подібні структури, але деякі помітні відмінності:

* Вузли, що складають дерево, представляють **модулі, а не компоненти**
* **Модулі без компонентів**, такі як `inspirations.js`, також представлені в цьому дереві. Дерево рендерингу включає лише компоненти.
* **Організаційні відмінності**: `Copyright.js` з'являється під `App.js` у дереві модулів, але в дереві рендерингу компонент `Copyright` з'являється як дочірній `InspirationGenerator`. Це тому, що `InspirationGenerator` приймає JSX як children props, тому рендерить `Copyright` як дочірній компонент, але не імпортує модуль.

### Використання дерев залежностей

Дерева залежностей корисні для визначення того, які модулі необхідні для запуску вашого додатку React. При збірці додатку React для продакшну зазвичай є крок збірки, що пакує весь необхідний JavaScript для відправки клієнту. Інструмент, відповідальний за це, називається [бандлер](https://developer.mozilla.org/en-US/docs/Learn/Tools_and_testing/Understanding_client-side_tools/Overview#the_modern_tooling_ecosystem), і бандлери використовують дерево залежностей для визначення того, які модулі повинні бути включені.

Із зростанням вашого додатку часто зростає і розмір бандлу. Великі розміри бандлів є дорогими для завантаження та запуску клієнтом. Великі розміри бандлів можуть затримувати час відображення UI. Розуміння дерева залежностей вашого додатку може допомогти з налагодженням цих проблем.

---

## Підсумок

* Дерева — поширений спосіб представлення відносин між сутностями. Вони часто використовуються для моделювання UI.
* **Дерева рендерингу** представляють вкладені відносини між компонентами React протягом одного рендеру.
* З умовним рендерингом дерево рендерингу може змінюватися між різними рендерами. З різними значеннями props компоненти можуть рендерити різних дочірніх.
* Дерева рендерингу допомагають визначити, що таке компоненти верхнього рівня та листові компоненти. Компоненти верхнього рівня впливають на продуктивність рендерингу всіх компонентів під ними, а листові компоненти часто перерендерюються. Їх визначення корисне для розуміння та налагодження продуктивності рендерингу.
* **Дерева залежностей** представляють залежності модулів у додатку React.
* Дерева залежностей використовуються інструментами збірки для пакування необхідного коду для відправки додатку.
* Дерева залежностей корисні для налагодження великих розмірів бандлів, що уповільнюють час відображення, та виявлення можливостей оптимізації пакованого коду.
