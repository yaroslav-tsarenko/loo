# Синхронізація з Effects

## Вступ

Effects дозволяють компонентам React синхронізуватися із зовнішніми системами. Вони дають змогу виконувати код після рендерингу для синхронізації компонентів із системами поза React, такими як:
- Керування компонентами, що не належать React, на основі state React
- Налаштування серверних з'єднань
- Відправка аналітичних логів при появі компонентів

## Цілі навчання

- Що таке Effects і чим вони відрізняються від подій
- Як оголосити Effect у компоненті
- Як пропустити непотрібні повторні запуски Effect
- Чому Effects запускаються двічі в режимі розробки і як з цим працювати

## Що таке Effects і чим вони відрізняються від подій?

### Два типи логіки в компонентах React

**Код рендерингу** (верхній рівень компонента):
- Приймає props та state, перетворює їх і повертає JSX
- Повинен бути чистим -- лише обчислює результати без побічних ефектів
- Не повинен змінювати DOM чи інші зовнішні системи

**Обробники подій** (вкладені функції в компонентах):
- Виконують дії, а не просто обчислення
- Містять "побічні ефекти", що змінюють стан програми
- Запускаються конкретними взаємодіями користувача (натискання, введення тощо)

### Effects проти подій

**Effects** визначають побічні ефекти, спричинені самим рендерингом, а не конкретними подіями. Вони запускаються в кінці фіксації (commit) після оновлення екрана, що робить їх ідеальними для синхронізації із зовнішніми системами.

**Ключова відмінність**: Відправка повідомлення в чаті -- це подія (безпосередньо спричинена натисканням кнопки), тоді як налаштування серверного з'єднання -- це Effect (має відбуватися при появі компонента, незалежно від взаємодії).

## Можливо, вам не потрібен Effect

**Важливо**: Не поспішайте додавати Effects до компонентів. Effects зазвичай використовуються для "виходу за межі" коду React та синхронізації із зовнішніми системами (браузерні API, сторонні віджети, мережа тощо). Якщо Effect лише коригує state на основі іншого state, вам, можливо, не потрібен Effect.

## Як написати Effect

### Три кроки

1. **Оголосіть Effect** -- за замовчуванням запускається після кожної фіксації
2. **Вкажіть залежності** -- контролюйте, коли Effect повторно запускається
3. **Додайте очищення за потреби** -- зупиніть або скасуйте те, що Effect робив

### Крок 1: Оголошення Effect

Імпортуйте Hook `useEffect`:

```js
import { useEffect } from 'react';
```

Викличте його на верхньому рівні компонента:

```js
function MyComponent() {
  useEffect(() => {
    // Код тут виконуватиметься після *кожного* рендерингу
  });
  return <div />;
}
```

Кожного разу, коли компонент рендериться, React оновлює екран і потім виконує код всередині `useEffect`. Effect "відкладає" виконання коду до відображення рендерингу на екрані.

### Приклад: Компонент відеоплеєра

```js
function VideoPlayer({ src, isPlaying }) {
  const ref = useRef(null);

  useEffect(() => {
    if (isPlaying) {
      ref.current.play();
    } else {
      ref.current.pause();
    }
  });

  return <video ref={ref} src={src} loop playsInline />;
}
```

**Чому не викликати play()/pause() під час рендерингу?**
- Рендеринг повинен бути чистим обчисленням
- DOM ще не існує при першому рендерингу
- Effects запускаються після оновлення DOM React

### Важливе застереження: Нескінченні цикли

```js
// НЕ РОБІТЬ ТАК -- створює нескінченний цикл
const [count, setCount] = useState(0);
useEffect(() => {
  setCount(count + 1);
});
```

Це створює цикл, оскільки: Effect запускається -> встановлює state -> запускає повторний рендеринг -> Effect запускається знову

Effects повинні синхронізуватися із зовнішніми системами, а не запускати оновлення state безпосередньо.

### Крок 2: Вказання залежностей Effect

За замовчуванням Effects запускаються після кожного рендерингу, що може бути:
- **Повільним**: Непотрібна синхронізація із зовнішніми системами
- **Неправильним**: Анімації/інша поведінка запускаються неочікувано

#### Масив залежностей

Вкажіть залежності як другий аргумент `useEffect`:

```js
useEffect(() => {
  if (isPlaying) {
    ref.current.play();
  } else {
    ref.current.pause();
  }
}, [isPlaying]);
```

React пропускає повторний запуск Effect, якщо всі залежності мають ті самі значення, що й при попередньому рендерингу, використовуючи порівняння `Object.is`.

#### Патерни залежностей

```js
// Запускається після кожного рендерингу
useEffect(() => {
  // ...
});

// Запускається лише при монтуванні (компонент з'являється)
useEffect(() => {
  // ...
}, []);

// Запускається при монтуванні та при зміні a або b
useEffect(() => {
  // ...
}, [a, b]);
```

### Чому Refs не входять до залежностей

```js
function VideoPlayer({ src, isPlaying }) {
  const ref = useRef(null);
  useEffect(() => {
    if (isPlaying) {
      ref.current.play();
    } else {
      ref.current.pause();
    }
  }, [isPlaying]); // ref не включений
```

`useRef` повертає той самий об'єкт при кожному рендерингу, тому він має стабільну ідентичність і не потребує бути залежністю. Те саме стосується функцій-сеттерів `useState`.

### Крок 3: Додавання очищення за потреби

Деякі Effects повинні вказати, як зупинити, скасувати або очистити:
- "підключити" потребує "відключити"
- "підписатися" потребує "відписатися"
- "отримати дані" потребує скасування або ігнорування

Поверніть функцію очищення з вашого Effect:

```js
useEffect(() => {
  const connection = createConnection();
  connection.connect();
  
  return () => {
    connection.disconnect();
  };
}, []);
```

React викликає функцію очищення:
- Кожного разу перед повторним запуском Effect
- Останній раз при демонтуванні компонента

#### Приклад: Підключення до чат-кімнати

```js
export default function ChatRoom() {
  useEffect(() => {
    const connection = createConnection();
    connection.connect();
    return () => connection.disconnect();
  }, []);
  return <h1>Ласкаво просимо до чату!</h1>;
}
```

**Поведінка в режимі розробки**: У Strict Mode React перемонтовує компоненти для перевірки очищення:
1. `"Підключення..."`
2. `"Відключено."`
3. `"Підключення..."`

Це правильна поведінка, яка перевіряє правильність роботи очищення. У продакшені ви побачите лише одне підключення.

## Як обробляти подвійний запуск Effects у режимі розробки

React навмисно перемонтовує компоненти в режимі розробки для пошуку помилок. Правильний підхід -- не "запустити Effect один раз", а "виправити мій Effect, щоб він працював після перемонтування".

### Поширені патерни

#### Керування компонентами, що не належать React

```js
useEffect(() => {
  const map = mapRef.current;
  map.setZoomLevel(zoomLevel);
}, [zoomLevel]);
```

Очищення не потрібне -- виклик `setZoomLevel` двічі з тим самим значенням нешкідливий.

Для API, які викидають помилку при дублюванні (наприклад, `showModal`):

```js
useEffect(() => {
  const dialog = dialogRef.current;
  dialog.showModal();
  return () => dialog.close();
}, []);
```

#### Підписка на події

```js
useEffect(() => {
  function handleScroll(e) {
    console.log(window.scrollX, window.scrollY);
  }
  window.addEventListener('scroll', handleScroll);
  return () => window.removeEventListener('scroll', handleScroll);
}, []);
```

#### Запуск анімацій

```js
useEffect(() => {
  const node = ref.current;
  node.style.opacity = 1; // Запуск анімації
  return () => {
    node.style.opacity = 0; // Скидання до початкового значення
  };
}, []);
```

#### Отримання даних

```js
useEffect(() => {
  let ignore = false;

  async function startFetching() {
    const json = await fetchTodos(userId);
    if (!ignore) {
      setTodos(json);
    }
  }

  startFetching();

  return () => {
    ignore = true;
  };
}, [userId]);
```

Прапорець `ignore` запобігає оновленню state від застарілих запитів.

#### Відправка аналітики

```js
useEffect(() => {
  logVisit(url); // Відправляє POST-запит
}, [url]);
```

Це запускається двічі в режимі розробки, але один раз у продакшені. Реалізуйте `logVisit` для роботи лише в продакшені або використовуйте перевірки середовища.

### Антипатерни: Не використовуйте Refs для запобігання подвійному запуску

```js
// НЕ РОБІТЬ ТАК
const connectionRef = useRef(null);
useEffect(() => {
  if (!connectionRef.current) {
    connectionRef.current = createConnection();
    connectionRef.current.connect();
  }
}, []);
```

Це запобігає подвійному запуску Effect у розробці, але не виправляє основну помилку -- з'єднання все одно не буде очищено при демонтуванні компонента.

## Effects, які мають бути подіями

Деяка логіка взагалі не повинна бути в Effects. Наприклад, покупка товару має бути в обробнику подій, а не в Effect:

```js
// НЕ РОБІТЬ ТАК
useEffect(() => {
  fetch('/api/buy', { method: 'POST' });
}, []);

// РОБІТЬ ТАК
function handleClick() {
  fetch('/api/buy', { method: 'POST' });
}
```

Effects призначені для побічних ефектів, спричинених рендерингом. Покупка спричинена конкретною взаємодією користувача.

## Ініціалізація застосунку

Логіка, яка повинна виконуватися лише раз при запуску застосунку:

```js
if (typeof window !== 'undefined') {
  checkAuthToken();
  loadDataFromLocalStorage();
}

function App() {
  // ...
}
```

Розмістіть це поза компонентами, щоб забезпечити одноразове виконання після завантаження сторінки.

## Кожен рендеринг має власні Effects

Effects є частиною результату рендерингу. Кожен рендеринг має власний Effect із захопленими значеннями:

```js
export default function ChatRoom({ roomId }) {
  useEffect(() => {
    const connection = createConnection(roomId);
    connection.connect();
    return () => connection.disconnect();
  }, [roomId]);

  return <h1>Ласкаво просимо до {roomId}!</h1>;
}
```

При зміні `roomId`:
1. React порівнює залежності
2. Якщо вони відрізняються, запускає очищення попереднього Effect
3. Потім запускає новий Effect

## Ключові висновки

- На відміну від подій, Effects спричинені самим рендерингом, а не конкретними взаємодіями
- Effects синхронізують компоненти із зовнішніми системами
- За замовчуванням Effects запускаються після кожного рендерингу
- React пропускає Effects, якщо всі залежності мають ті самі значення
- Ви не можете "обирати" залежності -- вони визначаються вашим кодом
- Порожній масив `[]` відповідає монтуванню компонента
- У Strict Mode React перемонтовує компоненти один раз у режимі розробки для перевірки Effects
- Якщо Effect ламається через перемонтування, реалізуйте функцію очищення
- React викликає функції очищення перед наступним запуском Effect та під час демонтування

## Завдання

### Завдання 1: Фокусування поля при монтуванні

Використовуйте `useEffect` з порожнім масивом залежностей для фокусування input при монтуванні:

```js
useEffect(() => {
  ref.current.focus();
}, []);
```

### Завдання 2: Умовне фокусування поля

Додайте `shouldFocus` до залежностей та використовуйте умовну логіку:

```js
useEffect(() => {
  if (shouldFocus) {
    ref.current.focus();
  }
}, [shouldFocus]);
```

### Завдання 3: Виправлення інтервалу, що запускається двічі

Збережіть ідентифікатор інтервалу та очистіть його у функції очищення:

```js
useEffect(() => {
  const intervalId = setInterval(onTick, 1000);
  return () => clearInterval(intervalId);
}, []);
```

### Завдання 4: Виправлення отримання даних всередині Effect

Використовуйте прапорець `ignore` для запобігання умовам гонки:

```js
useEffect(() => {
  let ignore = false;
  setBio(null);
  fetchBio(person).then(result => {
    if (!ignore) {
      setBio(result);
    }
  });
  return () => {
    ignore = true;
  };
}, [person]);
```
