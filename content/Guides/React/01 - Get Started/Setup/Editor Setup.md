# Налаштування редактора

## Вступ

Правильно налаштований редактор може зробити код зрозумілішим для читання та швидшим для написання. Він навіть може допомогти знаходити помилки під час написання! Якщо це ваше перше налаштування редактора або ви хочете покращити поточний, є кілька рекомендацій.

### Ви дізнаєтесь
* Які найпопулярніші редактори
* Як автоматично форматувати код

---

## Ваш редактор

[VS Code](https://code.visualstudio.com/) — один з найпопулярніших редакторів, що використовуються сьогодні. Він має великий маркетплейс розширень та добре інтегрується з популярними сервісами, такими як GitHub. Більшість функцій, перелічених нижче, можна додати до VS Code як розширення, що робить його дуже конфігурованим!

Інші популярні текстові редактори, що використовуються в спільноті React:

* **[WebStorm](https://www.jetbrains.com/webstorm/)** — інтегроване середовище розробки, спеціально розроблене для JavaScript.
* **[Sublime Text](https://www.sublimetext.com/)** — має підтримку JSX та TypeScript, [підсвічування синтаксису](https://stackoverflow.com/a/70960574/458193) та автодоповнення з коробки.
* **[Vim](https://www.vim.org/)** — надзвичайно конфігурований текстовий редактор, створений для ефективного створення та зміни будь-якого тексту. Він включений як "vi" у більшості систем UNIX та Apple OS X.

## Рекомендовані функції текстового редактора

Деякі редактори мають ці функції з коробки, інші можуть потребувати додавання розширення. Перевірте, яку підтримку надає ваш обраний редактор!

### Лінтинг

Лінтери коду знаходять проблеми у вашому коді під час написання, допомагаючи виправити їх рано. [ESLint](https://eslint.org/) — популярний лінтер з відкритим кодом для JavaScript.

* [Встановіть ESLint з рекомендованою конфігурацією для React](https://www.npmjs.com/package/eslint-config-react-app) (переконайтесь, що у вас [встановлений Node](https://nodejs.org/en/download/current/)!)
* [Інтегруйте ESLint у VSCode з офіційним розширенням](https://marketplace.visualstudio.com/items?itemName=dbaeumer.vscode-eslint)

**Важливо:** Переконайтесь, що ви увімкнули всі правила [`eslint-plugin-react-hooks`](https://www.npmjs.com/package/eslint-plugin-react-hooks) для вашого проєкту. Вони є необхідними та знаходять найсерйозніші помилки на ранній стадії. Рекомендований пресет [`eslint-config-react-app`](https://www.npmjs.com/package/eslint-config-react-app) вже включає їх.

### Форматування

Останнє, що ви хочете робити при спільному використанні коду з іншим розробником, — це сперечатися про [табуляції проти пробілів](https://www.google.com/search?q=tabs+vs+spaces)! На щастя, [Prettier](https://prettier.io/) очистить ваш код, переформатувавши його відповідно до заданих, конфігурованих правил. Запустіть Prettier, і всі ваші табуляції будуть конвертовані в пробіли, а відступи, лапки тощо також будуть змінені відповідно до конфігурації. В ідеальному налаштуванні Prettier запускається при збереженні файлу, швидко вносячи ці зміни за вас.

Ви можете встановити [розширення Prettier у VSCode](https://marketplace.visualstudio.com/items?itemName=esbenp.prettier-vscode) за такими кроками:

1. Запустіть VS Code
2. Використайте Quick Open (натисніть Ctrl/Cmd+P)
3. Вставте `ext install esbenp.prettier-vscode`
4. Натисніть Enter

#### Форматування при збереженні

В ідеалі ви повинні форматувати код при кожному збереженні. VS Code має налаштування для цього!

1. У VS Code натисніть `CTRL/CMD + SHIFT + P`.
2. Введіть "settings"
3. Натисніть Enter
4. У рядку пошуку введіть "format on save"
5. Переконайтесь, що опція "format on save" увімкнена!

> **Примітка:** Якщо ваш пресет ESLint має правила форматування, вони можуть конфліктувати з Prettier. Ми рекомендуємо вимкнути всі правила форматування у вашому пресеті ESLint за допомогою [`eslint-config-prettier`](https://github.com/prettier/eslint-config-prettier), щоб ESLint використовувався *лише* для пошуку логічних помилок. Якщо ви хочете забезпечити форматування файлів перед злиттям pull request, використовуйте [`prettier --check`](https://prettier.io/docs/en/cli.html#--check) для вашої системи безперервної інтеграції.
