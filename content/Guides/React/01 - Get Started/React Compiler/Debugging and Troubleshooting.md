# Налагодження та усунення неполадок React Compiler

## Вступ

Цей гайд допоможе вам ідентифікувати та виправити проблеми при використанні React Compiler. Дізнайтеся, як налагоджувати проблеми компіляції та вирішувати поширені проблеми.

### Ви дізнаєтесь

* Різницю між помилками компілятора та проблемами під час виконання
* Поширені патерни, що порушують компіляцію
* Покроковий робочий процес налагодження

---

## Розуміння поведінки компілятора

React Compiler розроблений для обробки коду, який дотримується [Правил React](/reference/rules). Коли він зустрічає код, який може порушувати ці правила, він безпечно пропускає оптимізацію, замість того щоб ризикувати змінити поведінку вашого застосунку.

### Помилки компілятора проти проблем під час виконання

**Помилки компілятора** виникають під час збірки та запобігають компіляції вашого коду. Вони рідкісні, оскільки компілятор розроблений для пропуску проблемного коду, а не для аварії.

**Проблеми під час виконання** виникають, коли скомпільований код поводиться інакше, ніж очікувалося. У більшості випадків, якщо ви зіткнулися з проблемою React Compiler, це проблема під час виконання. Зазвичай це трапляється, коли ваш код порушує Правила React непомітними способами, які компілятор не зміг виявити, і компілятор помилково скомпілював компонент, який мав бути пропущений.

При налагодженні проблем під час виконання зосередьте зусилля на пошуку порушень Правил React у проблемних компонентах, які не були виявлені правилом ESLint. Компілятор покладається на те, що ваш код дотримується цих правил, і коли вони порушуються способами, які він не може виявити, тоді виникають проблеми під час виконання.

---

## Поширені проблемні патерни

Один з основних способів, яким React Compiler може зламати ваш застосунок — якщо ваш код був написаний з розрахунком на мемоїзацію для коректності. Це означає, що ваш застосунок залежить від того, що конкретні значення мемоїзуються для правильної роботи. Оскільки компілятор може мемоїзувати інакше, ніж ваш ручний підхід, це може призвести до неочікуваної поведінки, як-от надмірне спрацьовування ефектів, нескінченні цикли або відсутні оновлення.

Поширені сценарії, де це відбувається:

- **Ефекти, що покладаються на референтну рівність** — Коли ефекти залежать від того, що об'єкти або масиви зберігають те саме посилання між рендерами
- **Масиви залежностей, що потребують стабільних посилань** — Коли нестабільні залежності викликають надмірне спрацьовування ефектів або створюють нескінченні цикли
- **Умовна логіка на основі перевірок посилань** — Коли код використовує перевірки референтної рівності для кешування або оптимізації

## Робочий процес налагодження

Дотримуйтесь цих кроків, коли зіткнулися з проблемами:

### Помилки збірки компілятора

Якщо ви зіткнулися з помилкою компілятора, яка неочікувано ламає вашу збірку, це ймовірно помилка в компіляторі. Повідомте про це в репозиторій [facebook/react](https://github.com/facebook/react/issues) з:
- Повідомленням про помилку
- Кодом, який спричинив помилку
- Версіями React та компілятора

### Проблеми під час виконання

Для проблем з поведінкою під час виконання:

#### 1. Тимчасово вимкніть компіляцію

Використовуйте `"use no memo"` для ізоляції того, чи пов'язана проблема з компілятором:

```js
function ProblematicComponent() {
  "use no memo"; // Пропустити компіляцію для цього компонента
  // ... решта компонента
}
```

Якщо проблема зникає, вона ймовірно пов'язана з порушенням Правил React.

Ви також можете спробувати видалити ручну мемоїзацію (useMemo, useCallback, memo) з проблемного компонента, щоб перевірити, що ваш застосунок працює правильно без будь-якої мемоїзації. Якщо помилка все ще виникає при видаленні всієї мемоїзації, у вас є порушення Правил React, яке потрібно виправити.

#### 2. Виправляйте проблеми поетапно

1. Ідентифікуйте першопричину (часто мемоїзація для коректності)
2. Тестуйте після кожного виправлення
3. Видаліть `"use no memo"` після виправлення
4. Перевірте, що компонент показує позначку ✨ в React DevTools

## Повідомлення про помилки компілятора

Якщо ви вважаєте, що знайшли помилку компілятора:

1. **Переконайтесь, що це не порушення Правил React** — Перевірте за допомогою ESLint
2. **Створіть мінімальне відтворення** — Ізолюйте проблему в маленькому прикладі
3. **Протестуйте без компілятора** — Підтвердіть, що проблема виникає лише з компіляцією
4. **Подайте [issue](https://github.com/facebook/react/issues/new?template=compiler_bug_report.yml)**:
   - Версії React та компілятора
   - Мінімальний код для відтворення
   - Очікувана проти фактичної поведінки
   - Будь-які повідомлення про помилки
