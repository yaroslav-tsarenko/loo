# React Compiler — Вступ

## Огляд

React Compiler — це новий інструмент часу збірки, який автоматично оптимізує ваш застосунок React. Він працює зі звичайним JavaScript і розуміє Правила React, тому вам не потрібно переписувати код для його використання.

### Ви дізнаєтесь
* Що робить React Compiler
* Початок роботи з компілятором
* Стратегії поступового впровадження
* Налагодження та усунення неполадок, коли щось іде не так
* Використання компілятора для вашої React-бібліотеки

---

## Що робить React Compiler?

React Compiler автоматично оптимізує ваш застосунок React під час збірки. React часто достатньо швидкий без оптимізації, але іноді вам потрібно вручну мемоїзувати компоненти та значення, щоб ваш застосунок залишався чуйним. Ця ручна мемоїзація є нудною, легко помилитися та додає додатковий код для підтримки. React Compiler робить цю оптимізацію автоматично за вас, звільняючи від цього ментального навантаження, щоб ви могли зосередитися на створенні функцій.

### До React Compiler

Без компілятора вам потрібно вручну мемоїзувати компоненти та значення для оптимізації повторних рендерів:

```js
import { useMemo, useCallback, memo } from 'react';

const ExpensiveComponent = memo(function ExpensiveComponent({ data, onClick }) {
  const processedData = useMemo(() => {
    return expensiveProcessing(data);
  }, [data]);

  const handleClick = useCallback((item) => {
    onClick(item.id);
  }, [onClick]);

  return (
    <div>
      {processedData.map(item => (
        <Item key={item.id} onClick={() => handleClick(item)} />
      ))}
    </div>
  );
});
```

#### Примітка — Непомітна помилка в ручній мемоїзації

Ця ручна мемоїзація має непомітну помилку, яка порушує мемоїзацію:

```js
<Item key={item.id} onClick={() => handleClick(item)} />
```

Навіть незважаючи на те, що `handleClick` обгорнуто в `useCallback`, стрілкова функція `() => handleClick(item)` створює нову функцію при кожному рендері компонента. Це означає, що `Item` завжди отримуватиме новий prop `onClick`, порушуючи мемоїзацію.

React Compiler здатний оптимізувати це правильно з або без стрілкової функції, забезпечуючи, що `Item` перерендерюється тільки коли `props.onClick` змінюється.

### Після React Compiler

З React Compiler ви пишете той самий код без ручної мемоїзації:

```js
function ExpensiveComponent({ data, onClick }) {
  const processedData = expensiveProcessing(data);

  const handleClick = (item) => {
    onClick(item.id);
  };

  return (
    <div>
      {processedData.map(item => (
        <Item key={item.id} onClick={() => handleClick(item)} />
      ))}
    </div>
  );
}
```

React Compiler автоматично застосовує оптимальну мемоїзацію, забезпечуючи перерендеринг вашого застосунку лише тоді, коли це необхідно.

## Поглиблене вивчення: Яку мемоїзацію додає React Compiler?

Автоматична мемоїзація React Compiler в основному зосереджена на **покращенні продуктивності оновлення** (повторний рендеринг існуючих компонентів), тому вона фокусується на двох випадках використання:

1. **Пропуск каскадного перерендерингу компонентів**
   - Перерендеринг `<Parent />` викликає перерендеринг багатьох компонентів у його дереві, навіть коли змінився лише `<Parent />`

2. **Пропуск дорогих обчислень поза React**
   - Наприклад, виклик `expensivelyProcessAReallyLargeArrayOfObjects()` всередині вашого компонента або hook, якому потрібні ці дані

### Оптимізація повторних рендерів

React дозволяє виражати UI як функцію від поточного state (точніше: props, state та context). У поточній реалізації, коли state компонента змінюється, React перерендерить цей компонент _та всіх його дочірніх_ — якщо ви не застосували якусь форму ручної мемоїзації з `useMemo()`, `useCallback()` або `React.memo()`. Наприклад, у наступному прикладі `<MessageButton>` перерендериться кожного разу, коли змінюється state `<FriendList>`:

```javascript
function FriendList({ friends }) {
  const onlineCount = useFriendOnlineCount();
  if (friends.length === 0) {
    return <NoFriends />;
  }
  return (
    <div>
      <span>{onlineCount} онлайн</span>
      {friends.map((friend) => (
        <FriendListCard key={friend.id} friend={friend} />
      ))}
      <MessageButton />
    </div>
  );
}
```

React Compiler автоматично застосовує еквівалент ручної мемоїзації, забезпечуючи перерендеринг лише відповідних частин застосунку при зміні state, що іноді називають "дрібнозернистою реактивністю". У прикладі вище React Compiler визначає, що значення, повернуте `<FriendListCard />`, може бути повторно використано навіть при зміні `friends`, та може уникнути повторного створення цього JSX _та_ перерендерингу `<MessageButton>` при зміні лічильника.

### Дорогі обчислення також мемоїзуються

React Compiler також може автоматично мемоїзувати дорогі обчислення, що використовуються під час рендерингу:

```js
// **Не** мемоїзується React Compiler, оскільки це не компонент або hook
function expensivelyProcessAReallyLargeArrayOfObjects() { /* ... */ }

// Мемоїзується React Compiler, оскільки це компонент
function TableContainer({ items }) {
  // Цей виклик функції буде мемоїзовано:
  const data = expensivelyProcessAReallyLargeArrayOfObjects(items);
  // ...
}
```

Однак якщо `expensivelyProcessAReallyLargeArrayOfObjects` — справді дорога функція, ви можете розглянути реалізацію власної мемоїзації поза React, оскільки:

- React Compiler мемоїзує лише компоненти та hooks React, не кожну функцію
- Мемоїзація React Compiler не є спільною між кількома компонентами або hooks

Тому якщо `expensivelyProcessAReallyLargeArrayOfObjects` використовувалася в багатьох різних компонентах, навіть якщо передавалися ті самі items, дороге обчислення виконувалося б повторно. Ми рекомендуємо спочатку профілювати, щоб побачити, чи це справді настільки дорого, перш ніж ускладнювати код.

## Чи варто спробувати компілятор?

Ми заохочуємо всіх почати використовувати React Compiler. Хоча компілятор все ще є необов'язковим доповненням до React сьогодні, у майбутньому деякі функції можуть вимагати компілятор для повноцінної роботи.

### Чи безпечно його використовувати?

React Compiler тепер стабільний та був ретельно протестований у продакшені. Хоча він використовувався в продакшені в таких компаніях як Meta, розгортання компілятора у продакшен для вашого застосунку залежатиме від здоров'я вашої кодової бази та того, наскільки добре ви дотримуєтесь Правил React.

---

## Які інструменти збірки підтримуються?

React Compiler може бути встановлений через кілька інструментів збірки, таких як Babel, Vite, Metro та Rsbuild.

React Compiler — це насамперед легка обгортка плагіна Babel навколо основного компілятора, який був спроєктований для від'єднання від самого Babel. Хоча початкова стабільна версія компілятора залишиться переважно плагіном Babel, ми працюємо з командами swc та oxc над створенням першокласної підтримки React Compiler, щоб вам не доводилося додавати Babel назад у ваші конвеєри збірки в майбутньому.

Користувачі Next.js можуть увімкнути React Compiler, що викликається через swc, використовуючи v15.3.1 та вище.

## Що робити з useMemo, useCallback та React.memo?

За замовчуванням React Compiler мемоїзує ваш код на основі свого аналізу та евристик. У більшості випадків ця мемоїзація буде такою ж точною, або більш точною, ніж те, що ви могли б написати.

Однак у деяких випадках розробникам може знадобитися більше контролю над мемоїзацією. Hooks `useMemo` та `useCallback` можуть продовжувати використовуватися з React Compiler як запасний варіант для забезпечення контролю над тим, які значення мемоїзуються. Поширений випадок — якщо мемоїзоване значення використовується як залежність ефекту, щоб забезпечити, що ефект не спрацьовує повторно, навіть коли його залежності не змінюються суттєво.

**Для нового коду** ми рекомендуємо покладатися на компілятор для мемоїзації та використовувати `useMemo`/`useCallback` там, де потрібен точний контроль.

**Для існуючого коду** ми рекомендуємо або залишити існуючу мемоїзацію на місці (її видалення може змінити результат компіляції), або ретельно протестувати перед видаленням мемоїзації.
