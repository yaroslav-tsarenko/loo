# Поступове впровадження React Compiler

## Вступ

React Compiler можна впроваджувати поступово, дозволяючи спочатку спробувати його на конкретних частинах вашої кодової бази. Цей гайд показує, як поступово розгортати компілятор в існуючих проєктах.

### Ви дізнаєтесь

* Чому рекомендується поступове впровадження
* Використання перевизначень Babel для впровадження на основі директорій
* Використання директиви "use memo" для компіляції за згодою
* Використання директиви "use no memo" для виключення компонентів
* Прапорці функцій під час виконання з гейтингом
* Моніторинг прогресу впровадження

---

## Чому поступове впровадження?

React Compiler розроблений для автоматичної оптимізації всієї вашої кодової бази, але ви не зобов'язані впроваджувати його одразу повністю. Поступове впровадження дає вам контроль над процесом розгортання, дозволяючи протестувати компілятор на малих частинах вашого застосунку перед розширенням на решту.

Починаючи з малого, ви будуєте впевненість в оптимізаціях компілятора. Ви можете перевірити, що ваш застосунок поводиться правильно зі скомпільованим кодом, виміряти покращення продуктивності та ідентифікувати будь-які крайні випадки, специфічні для вашої кодової бази. Цей підхід особливо цінний для продакшен-застосунків, де стабільність є критичною.

Поступове впровадження також полегшує вирішення будь-яких порушень Правил React, які може знайти компілятор. Замість виправлення порушень по всій кодовій базі одразу, ви можете вирішувати їх систематично при розширенні покриття компілятора. Це робить міграцію керованою та знижує ризик введення помилок.

Контролюючи, які частини вашого коду компілюються, ви також можете проводити A/B-тести для вимірювання реального впливу оптимізацій компілятора. Ці дані допомагають приймати обґрунтовані рішення щодо повного впровадження та демонструють цінність для вашої команди.

---

## Підходи до поступового впровадження

Існує три основні підходи для поступового впровадження React Compiler:

1. **Перевизначення Babel** — Застосування компілятора до конкретних директорій
2. **Згода з "use memo"** — Компіляція лише компонентів, які явно підключаються
3. **Гейтинг під час виконання** — Контроль компіляції за допомогою прапорців функцій

Усі підходи дозволяють протестувати компілятор на конкретних частинах вашого застосунку перед повним розгортанням.

---

## Впровадження на основі директорій з перевизначеннями Babel

Опція `overrides` Babel дозволяє застосовувати різні плагіни до різних частин вашої кодової бази. Це ідеально для поступового впровадження React Compiler директорія за директорією.

### Базова конфігурація

Почніть з застосування компілятора до конкретної директорії:

```js
// babel.config.js
module.exports = {
  plugins: [
    // Глобальні плагіни, що застосовуються до всіх файлів
  ],
  overrides: [
    {
      test: './src/modern/**/*.{js,jsx,ts,tsx}',
      plugins: [
        'babel-plugin-react-compiler'
      ]
    }
  ]
};
```

### Розширення покриття

У міру набуття впевненості додавайте більше директорій:

```js
// babel.config.js
module.exports = {
  plugins: [
    // Глобальні плагіни
  ],
  overrides: [
    {
      test: ['./src/modern/**/*.{js,jsx,ts,tsx}', './src/features/**/*.{js,jsx,ts,tsx}'],
      plugins: [
        'babel-plugin-react-compiler'
      ]
    },
    {
      test: './src/legacy/**/*.{js,jsx,ts,tsx}',
      plugins: [
        // Інші плагіни для застарілого коду
      ]
    }
  ]
};
```

### З опціями компілятора

Ви також можете налаштувати опції компілятора для кожного перевизначення:

```js
// babel.config.js
module.exports = {
  plugins: [],
  overrides: [
    {
      test: './src/experimental/**/*.{js,jsx,ts,tsx}',
      plugins: [
        ['babel-plugin-react-compiler', {
          // опції ...
        }]
      ]
    },
    {
      test: './src/production/**/*.{js,jsx,ts,tsx}',
      plugins: [
        ['babel-plugin-react-compiler', {
          // опції ...
        }]
      ]
    }
  ]
};
```

## Режим згоди з "use memo"

Для максимального контролю ви можете використовувати `compilationMode: 'annotation'`, щоб компілювати лише компоненти та hooks, які явно підключаються за допомогою директиви `"use memo"`.

> **Примітка:** Цей підхід дає вам детальний контроль над окремими компонентами та hooks. Він корисний, коли ви хочете протестувати компілятор на конкретних компонентах без впливу на цілі директорії.

### Конфігурація режиму анотацій

```js
// babel.config.js
module.exports = {
  plugins: [
    ['babel-plugin-react-compiler', {
      compilationMode: 'annotation',
    }],
  ],
};
```

### Використання директиви

Додайте `"use memo"` на початку функцій, які ви хочете компілювати:

```js
function TodoList({ todos }) {
  "use memo"; // Підключити цей компонент до компіляції

  const sortedTodos = todos.slice().sort();

  return (
    <ul>
      {sortedTodos.map(todo => (
        <TodoItem key={todo.id} todo={todo} />
      ))}
    </ul>
  );
}

function useSortedData(data) {
  "use memo"; // Підключити цей hook до компіляції

  return data.slice().sort();
}
```

З `compilationMode: 'annotation'` ви повинні:
- Додати `"use memo"` до кожного компонента, який хочете оптимізувати
- Додати `"use memo"` до кожного користувацького hook
- Пам'ятати додавати його до нових компонентів

Це дає точний контроль над тим, які компоненти компілюються, поки ви оцінюєте вплив компілятора.

## Прапорці функцій під час виконання з гейтингом

Опція `gating` дозволяє контролювати компіляцію під час виконання за допомогою прапорців функцій. Це корисно для проведення A/B-тестів або поступового розгортання компілятора на основі сегментів користувачів.

### Як працює гейтинг

Компілятор обгортає оптимізований код у перевірку під час виконання. Якщо перевірка повертає `true`, запускається оптимізована версія. В іншому випадку запускається оригінальний код.

### Конфігурація гейтингу

```js
// babel.config.js
module.exports = {
  plugins: [
    ['babel-plugin-react-compiler', {
      gating: {
        source: 'ReactCompilerFeatureFlags',
        importSpecifierName: 'isCompilerEnabled',
      },
    }],
  ],
};
```

### Реалізація прапорця функції

Створіть модуль, який експортує вашу функцію гейтингу:

```js
// ReactCompilerFeatureFlags.js
export function isCompilerEnabled() {
  // Використовуйте вашу систему прапорців функцій
  return getFeatureFlag('react-compiler-enabled');
}
```

## Усунення неполадок при впровадженні

Якщо ви зіткнулися з проблемами під час впровадження:

1. Використовуйте `"use no memo"` для тимчасового виключення проблемних компонентів
2. Перегляньте [гайд з налагодження](/learn/react-compiler/debugging) для поширених проблем
3. Виправте порушення Правил React, ідентифіковані плагіном ESLint
4. Розгляньте використання `compilationMode: 'annotation'` для більш поступового впровадження
