# Як думати як програміст

> [!success] 🎯 Після цього розділу ти зможеш
> - розбити незнайому задачу на маленькі кроки і записати їх псевдокодом;
> - знайти баг через `console.log` і точки зупинки (breakpoints) у DevTools;
> - прочитати повідомлення про помилку й зрозуміти, де шукати причину;
> - швидко знайти відповідь у пошуковику та на MDN;
> - поставити питання людині чи AI так, щоб отримати корисну допомогу, а не готовий код, якого не розумієш.

## 🤔 Передбач

> [!quiz] Що виведе код? (у ньому є баг)
> level: junior · type: output · id: jss-10-quiz-01
>
> ```js
> function average(nums) {
>   let total = 0
>   for (let i = 0; i <= nums.length; i++) {
>     total += nums[i]
>   }
>   return total / nums.length
> }
> console.log(average([2, 4]))
> ```
>
> **Відповідь:** `NaN`
>
> **Пояснення:** через `<=` цикл робить зайву ітерацію з `i = 2`. Елемента `nums[2]` немає — це `undefined`, а `6 + undefined` дає `NaN`, і далі все «заражене». Класична помилка на одиницю. У цьому розділі навчимося знаходити такі баги систематично, а не вгадуванням.

## 🧒 Простими словами

Програміст — це не людина, яка пише код без помилок. Це **детектив**, який:

1. розуміє, що саме треба розкрити (задачу);
2. збирає докази (дивиться, що реально відбувається в коді);
3. висуває версію і перевіряє її (змінює **одну** річ і дивиться результат).

Новачок бачить баг і змінює все підряд, сподіваючись на диво. Професіонал **звужує коло підозрюваних**, поки не залишиться один рядок. Це навичка, а не талант, — і вона тренується.

## 🔬 Як це працює

### 🧩 Розбий задачу на кроки

Будь-яка «страшна» задача — це кілька маленьких, які ти вже вмієш розвʼязувати. Алгоритм на кожен день:

>   - { show: s5, note: "Наостанок — дивні випадки з кроку 2. Саме на них ламаються «майже робочі» програми." }

Розберемо приклад «знайди найдовше слово в реченні». Кроки словами:

- розбити речення на слова;
- взяти перше слово як «поки що найдовше»;
- перебрати решту: якщо слово довше — запам'ятати його;
- повернути запам'ятоване.

Перший крок — метод рядка `split`: він розрізає рядок за роздільником і повертає масив.

```js
console.log('я люблю JS'.split(' ')) // → ['я', 'люблю', 'JS']
```

Решта — те, що ти вже вмієш: цикл і порівняння `length`.

### 📝 Псевдокод — план перед кодом

**Псевдокод** — кроки, записані людською мовою, але вже структуровано: з «якщо» і «для кожного». Зручно писати їх просто коментарями, а потім заповнювати кодом:

```js
function longestWord(sentence) {
  // розбити речення на слова
  const words = sentence.split(' ')
  // взяти перше слово як найдовше
  let longest = words[0]
  // для кожного слова: якщо довше — запамʼятати
  for (const word of words) {
    if (word.length > longest.length) longest = word
  }
  // повернути найдовше
  return longest
}
console.log(longestWord('я дуже люблю JavaScript')) // → JavaScript
```

Плюс: коли застрягнеш, ти точно знаєш, **на якому кроці**. І питати допомогу легше: «у мене не виходить крок 3».

> [!quiz] Заповни пропуски: втіли псевдокод «порахуй слова, довші за 3 літери»

>
> ```js fill
> const text = 'мені подобається вчити код'
> // розбити на слова
> const words = text.[[split]](' ')
> // для кожного слова: якщо довше за 3 — додати 1

>   if (w.[[length]] > 3) count++

> **Пояснення:** `split(' ')` дає масив слів, `length` слова — кількість літер. Відповідь: `3` («мені», «подобається», «вчити»).

### 🔦 Дебаг через console.log

Найпростіший і досі найпопулярніший інструмент. Принцип: **не гадай — подивись**. Друкуй проміжні значення з підписами:

```js
function average(nums) {
  let total = 0
  for (let i = 0; i <= nums.length; i++) {
    console.log('i =', i, 'nums[i] =', nums[i], 'total =', total)
    total += nums[i]
  }
  return total / nums.length
}
average([2, 4])
// i = 0 nums[i] = 2 total = 0
// i = 1 nums[i] = 4 total = 2
// i = 2 nums[i] = undefined total = 6   ← ось він!
```

Без підписів (`console.log(i, total)`) за хвилину заплутаєшся, де яке число. Для масиву обʼєктів спробуй `console.table(users)` — консоль намалює таблицю.

> [!tip] Стратегія «половинного ділення»
> Не знаєш, де зламалось? Постав `console.log` посередині коду. Значення ще правильне — баг нижче; вже неправильне — вище. Повтори з потрібною половиною. За 3–4 кроки знайдеш рядок навіть у великій програмі.

> [!quiz] Перевір себе: що найкорисніше надрукувати, якщо цикл дає неправильну суму?
> level: junior · id: jss-10-quiz-04
> - [ ] Лише фінальний результат після циклу
> - [x] Лічильник, поточний елемент і накопичувач на кожній ітерації — з підписами
> - [ ] Слово «тут» у різних місцях коду
> - [ ] Нічого — краще переписати функцію з нуля
>
> **Пояснення:** проміжні значення на кожному кроці показують, **на якій ітерації** щось пішло не так. Підписи не дають переплутати числа.

### ⏸️ Breakpoints і debugger

Коли `console.log` стає забагато, бери справжній **дебагер** — він зупиняє програму на потрібному рядку, і ти бачиш усі змінні одразу.

> [!diagram] Breakpoint: зупинити код і зазирнути всередину
> ```yaml
> layout: flow
> nodes:
>   - { id: page, label: "сторінка", text: "дія на сторінці", tone: blue, icon: "px:cursor" }
>   - { id: src, label: "DevTools → Sources → твій файл", code: "function applyDiscount(price, percent) {\n  return price - price * percent / 100\n}\napplyDiscount(200, 10)", tone: violet, icon: "px:code" }
>   - { id: scope, label: "Scope (праворуч)", text: "—", tone: yellow, icon: "px:magnifier" }
> edges:
>   - { from: page, to: src, label: "запуск коду" }
>   - { from: src, to: scope, label: "змінні зараз" }
> steps:
>   - { line: "src:2", focus: src, note: "Відкрий Chrome DevTools → вкладка Sources → свій файл і клацни по номеру рядка 2. З'явиться синя мітка — breakpoint, точка зупинки." }
>   - { move: { from: page, to: src, value: "applyDiscount(200, 10)" }, line: "src:4", note: "Виконай дію на сторінці — код стартує як завжди і викликає applyDiscount(200, 10)." }
>   - { line: "src:2", move: { from: src, to: scope, value: "пауза" }, set: { scope: "price = 200\npercent = 10" }, note: "Виконання дійшло до мітки й зупинилося: рядок 2 ще НЕ виконано. Праворуч у Scope — значення всіх змінних прямо зараз." }
>   - { line: "src:4", set: { scope: "Return value: 180" }, note: "⤵ Step over (F10) виконує рядок і зупиняється на наступному: функція повернула 200 - 200 * 10 / 100 = 180." }
>   - { focus: page, note: "▶ Resume (F8) — програма біжить далі до наступної мітки. Сторінка знову живе, а ти вже бачив усе зсередини." }
> ```

Ще простіше — написати в коді слово `debugger`. Коли DevTools відкриті, виконання зупиниться саме там:

```js
function applyDiscount(price, percent) {
  debugger // зупинка, якщо DevTools відкриті; інакше рядок ігнорується
  return price - price * percent / 100
}
```

Не забудь прибрати `debugger` перед тим, як показувати код іншим.

### 🚨 Читання помилок

Помилки здаються страшними лише першого тижня. Ось «великий пʼяток», який покриває більшість випадків:

| Помилка | Що означає | Де шукати |
|---|---|---|
| `SyntaxError: Unexpected token` | код написано не за граматикою | незакриті дужки/лапки в цьому рядку або вище |
| `ReferenceError: x is not defined` | змінної з таким ім'ям немає | одруківка, регістр, змінна з іншої функції |
| `TypeError: x is not a function` | викликаєш як функцію те, що нею не є | одруківка в назві методу, `()` після не-функції |
| `TypeError: Cannot read properties of undefined (reading 'name')` | береш `.name` з `undefined` | що зліва від `.name`? звідки там `undefined`? |
| `RangeError: Maximum call stack size exceeded` | функція викликає саму себе без кінця | умова зупинки рекурсії |

Читай повідомлення **повністю**: слово в дужках (`reading 'name'`) часто прямо називає винуватця. А стек під помилкою (рядки `at …`) показує ланцюжок викликів: верхній рядок — де впало, нижчі — хто туди привів.

> [!quiz] Склади, як читати помилку `TypeError: Cannot read properties of undefined (reading 'city')`

> Хтось читає .city зі значення undefined
> Знайти рядок з .city за номером у стеку
> З'ясувати, чому обʼєкт зліва від .city — undefined
> ```

> [!quiz] Що виведе код?
> level: junior · type: output · id: jss-10-quiz-07
>
> ```js
> try {
>   const user = {}
>   console.log(user.profile.name)
> } catch (error) {
>   console.log(error.name)
> }
> ```
>
> **Відповідь:** `TypeError`
>
> **Пояснення:** `user.profile` — `undefined`, а читати властивість з `undefined` не можна. `try/catch` перехоплює помилку, і ми друкуємо її тип. Детально про обробку помилок — у [[JavaScript - 22. Помилки та їх обробка]].

### 🔍 Як гуглити і читати MDN

Формула хорошого запиту: **мова + що хочеш зробити + англійською**.

| Погано | Добре |
|---|---|
| «не працює кнопка» | `javascript addEventListener click not working` |
| «як зробити список» | `javascript array remove element by index` |
| вставити весь код | точний текст помилки в лапках: `"is not a function" javascript` |

Найкращі джерела — **MDN** (довідник від Mozilla) і **javascript.info**. Додай `mdn` до запиту: `mdn array includes`. Сторінка MDN завжди побудована однаково:

```text
 Syntax        → як записати виклик
 Parameters    → що можна передати
 Return value  → що повернеться   ← найважливіше!
 Examples      → готові приклади: скопіюй у консоль і поекспериментуй
```

### 🤖 Як просити допомогу в людей і AI

AI-асистенти й ментори — потужні помічники, але лише якщо **ти** лишаєшся тим, хто думає. Хороше питання містить пʼять речей:

```text
 1. Мета:        «Хочу, щоб функція повертала найдовше слово»
 2. Код:         мінімальний шматок, що відтворює проблему
 3. Очікую:      longestWord('я люблю JS') → 'люблю'
 4. Отримую:     'я' / текст помилки повністю
 5. Що пробував: «друкував words — масив правильний»
```

Половина багів знаходиться, поки ти пишеш таке питання (це називають «методом гумової качечки»: поясни проблему іграшці — і сам побачиш рішення).

Правила роботи з AI для навчання:

- проси **підказку чи пояснення**, а не готовий код: «Не давай рішення, підкажи, на якому кроці помилка»;
- проси пояснити **кожен рядок** відповіді, якого не розумієш;
- **перевіряй**: AI буває впевнено неправим — запусти код і тести;
- після підказки **перепиши рішення сам** з нуля — інакше знання не залишиться.

> **Пояснення:** мета, очікуване, фактичне і вже зроблені кроки — з такими даними допомогти можна за хвилину.

## ⚠️ Пастки

> [!pitfall] Змінювати багато всього одразу
> Змінив пʼять речей — і запрацювало (або зламалось ще сильніше). Яка з них допомогла? Невідомо. Змінюй **одну** річ — запускай — дивись.

> [!pitfall] Ігнорувати текст помилки
> «Там щось червоне» — не діагноз. У повідомленні майже завжди є тип, причина і номер рядка. Прочитай його до кінця, перш ніж щось змінювати.

> [!pitfall] Копіювати код, якого не розумієш
> Код з інтернету чи від AI, який ти не можеш пояснити, — це міна сповільненої дії. Розбери кожен рядок або попроси пояснення.

> [!pitfall] «Не працює» без подробиць
> Таке питання змушує людей гадати. Що очікував? Що отримав? Який текст помилки? Без цього допомога затягнеться на години.

## ⚡ Фішки

> [!reel] 🦆 Метод гумової качечки
> Поясни свій код уголос рядок за рядком — хоч іграшковій качці. Десь на середині ти сам почуєш, де помилка. Перевірено поколіннями програмістів.

> [!reel] 🏷️ Підписуй console.log
> `console.log('total =', total)` замість `console.log(total)`. Через пʼять хвилин ти не згадаєш, яке з десяти чисел — яке.

> [!reel] ⏸️ debugger — breakpoint у коді
> Напиши `debugger` у потрібному рядку й відкрий DevTools — виконання зупиниться там, і ти побачиш усі змінні.

> [!reel] ✂️ Ділення навпіл знаходить будь-який баг
> Лог посередині: значення правильне — баг нижче, ні — вище. Кожен крок відкидає половину коду. 1000 рядків — лише 10 кроків.

> [!reel] 🤖 AI — ментор, а не списувалка
> Проси «підкажи, де помилка, але не пиши рішення». Отримав підказку — допиши сам. Інакше вчиться AI, а не ти.

## 🛠️ Практика

Усі задачі цього розділу — **детективні**: у заготовках уже є код з багом. Запусти тести, прочитай, що впало, знайди причину — і виправ мінімальною зміною.

> [!task] Середнє з багом
> level: junior · difficulty: easy · id: jss-10-task-01 · tags: debugging, loops
>
> Функція з розділу «Передбач». Виправ, щоб `average` повертала середнє арифметичне.
>
> ```js starter
> function average(nums) {
>   let total = 0
>   for (let i = 0; i <= nums.length; i++) {
>     total += nums[i]
>   }
>   return total / nums.length
> }
> ```
>
> ```js tests
> test('[2, 4] → 3', () => { expect(average([2, 4])).toBe(3) })
> test('[5] → 5', () => { expect(average([5])).toBe(5) })
> test('[1, 2, 3, 4] → 2.5', () => { expect(average([1, 2, 3, 4])).toBe(2.5) })
> ```
>
> > [!hint]- Підказка 1
> > Додай `console.log('i =', i, 'nums[i] =', nums[i])` у цикл. Яке значення `i` зайве?
>
> > [!solution]- Рішення
> > ```js
> > function average(nums) {
> >   let total = 0
> >   for (let i = 0; i < nums.length; i++) {
> >     total += nums[i]
> >   }
> >   return total / nums.length
> > }
> > ```
> >
> > Останній індекс — `length - 1`, тож умова — `<`, а не `<=`.

> [!task] Велика перша літера
> level: junior · difficulty: easy · id: jss-10-task-02 · tags: debugging, strings
>
> `capitalize(word)` має робити першу літеру великою: `'кіт'` → `'Кіт'`. Для порожнього рядка — повертати `''`. Зараз функція повертає щось дивне.
>
> ```js starter
> function capitalize(word) {
>   return word[0].toUpperCase() + word.slice(0)
> }
> ```
>
> ```js tests
> test('кіт → Кіт', () => { expect(capitalize('кіт')).toBe('Кіт') })
> test('одна літера', () => { expect(capitalize('а')).toBe('А') })
> test('порожній рядок', () => { expect(capitalize('')).toBe('') })
> ```
>
> > [!hint]- Підказка 1
> > Що повертає `'кіт'.slice(0)`? А `'кіт'.slice(1)`? Перевір у консолі. (`slice(n)` — частина рядка, починаючи з індексу `n`.)
>
> > [!hint]- Підказка 2
> > Для `''` вираз `word[0]` — це `undefined`, а в `undefined` немає методу `toUpperCase`. Додай перевірку на порожній рядок на початку.
>
> > [!solution]- Рішення
> > ```js
> > function capitalize(word) {
> >   if (word === '') return ''
> >   return word[0].toUpperCase() + word.slice(1)
> > }
> > ```
> >
> > Два баги: `slice(0)` повторював усе слово (`'Ккіт'`), а порожній рядок давав `TypeError`.

> [!task] Максимум, який не бачить відʼємних
> level: junior · difficulty: easy · id: jss-10-task-03 · tags: debugging, arrays
>
> `findMax(nums)` має повертати найбільше число непорожнього масиву. Для додатних чисел працює, а для відʼємних — ні. Чому?
>
> ```js starter
> function findMax(nums) {
>   let max = 0
>   for (const n of nums) {
>     if (n > max) max = n
>   }
>   return max
> }
> ```
>
> ```js tests
> test('додатні', () => { expect(findMax([3, 9, 2])).toBe(9) })
> test('усі відʼємні', () => { expect(findMax([-5, -2, -8])).toBe(-2) })
> test('один елемент', () => { expect(findMax([-1])).toBe(-1) })
> ```
>
> > [!hint]- Підказка 1
> > Розвʼяжи `findMax([-5, -2, -8])` руками, стежачи за `max`. Чи стане умова `n > max` хоч раз правдивою?
>
> > [!hint]- Підказка 2
> > Початкове «поки що найбільше» має бути взяте з самого масиву.
>
> > [!solution]- Рішення
> > ```js
> > function findMax(nums) {
> >   let max = nums[0]
> >   for (const n of nums) {
> >     if (n > max) max = n
> >   }
> >   return max
> > }
> > ```
> >
> > Нуль — це «вигадане» значення, якого може не бути в масиві. Безпечний старт — перший елемент.

> [!task] Найдовше слово
> level: junior · difficulty: medium · id: jss-10-task-04 · tags: problem-solving, strings, arrays
>
> Реалізуй `longestWord(sentence)` за псевдокодом нижче. Якщо кілька слів однакової довжини — поверни **перше**. Для порожнього рядка — `''`.
>
> ```text
> розбити речення на слова за пробілом
> найдовше = перше слово
> для кожного слова: якщо довше за найдовше — запамʼятати
> повернути найдовше
> ```
>
> ```js starter
> function longestWord(sentence) {
>   // розбити речення на слова
>   // найдовше = перше слово
>   // для кожного слова: якщо довше — запамʼятати
>   // повернути найдовше
> }
> ```
>
> ```js tests
> test('звичайне речення', () => { expect(longestWord('я люблю JavaScript')).toBe('JavaScript') })
> test('однакова довжина — перше', () => { expect(longestWord('кіт пес')).toBe('кіт') })
> test('одне слово', () => { expect(longestWord('привіт')).toBe('привіт') })
> test('порожній рядок', () => { expect(longestWord('')).toBe('') })
> ```
>
> > [!hint]- Підказка 1
> > `sentence.split(' ')` повертає масив слів. Для `''` — масив з одним порожнім рядком `['']`.
>
> > [!hint]- Підказка 2
> > «Однакова довжина — перше» означає строге `>` при порівнянні, а не `>=`.
>
> > [!solution]- Рішення
> > ```js
> > function longestWord(sentence) {
> >   const words = sentence.split(' ')
> >   let longest = words[0]
> >   for (const word of words) {
> >     if (word.length > longest.length) longest = word
> >   }
> >   return longest
> > }
> > ```
> >
> > Порожній рядок обробився «безкоштовно»: `''.split(' ')` → `['']`, і перше слово — `''`.

> [!task] Паліндром
> level: junior · difficulty: medium · id: jss-10-task-05 · tags: problem-solving, strings, loops
>
> Паліндром читається однаково в обидва боки: «Пилип», «шалаш». `isPalindrome(word)` повертає `true` або `false`, **не зважаючи на регістр**. Спершу напиши план коментарями, потім код.
>
> ```js starter
> function isPalindrome(word) {
>   // твій план:
>   // 1. ...
>   // 2. ...
>   return false
> }
> ```
>
> ```js tests
> test('шалаш', () => { expect(isPalindrome('шалаш')).toBe(true) })
> test('Пилип — регістр не важливий', () => { expect(isPalindrome('Пилип')).toBe(true) })
> test('кіт — ні', () => { expect(isPalindrome('кіт')).toBe(false) })
> test('одна літера', () => { expect(isPalindrome('я')).toBe(true) })
> ```
>
> > [!hint]- Підказка 1
> > План: привести до малих літер (`word.toLowerCase()`), розвернути рядок, порівняти з оригіналом.
>
> > [!hint]- Підказка 2
> > Розвернути рядок можна циклом з розділу 5: `reversed = ch + reversed` для кожного символу.
>
> > [!solution]- Рішення
> > ```js
> > function isPalindrome(word) {
> >   // 1. малі літери
> >   const lower = word.toLowerCase()
> >   // 2. розвернути рядок
> >   let reversed = ''
> >   for (const ch of lower) {
> >     reversed = ch + reversed
> >   }
> >   // 3. порівняти
> >   return lower === reversed
> > }
> > ```
> >
> > Коротша версія, яку ти зустрінеш: `lower.split('').reverse().join('') === lower`. Але цикл показує, що відбувається насправді.
