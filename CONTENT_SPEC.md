# CONTENT_SPEC — формат посібників

Цей документ описує, як писати посібники в Obsidian, щоб апка витягла з них усе: структуру, навчальні одиниці, роадмапу. Усе нижче **необов'язкове**: посібник без жодного frontmatter і callout теж працює (розділ 1), але кожен явний елемент робить результат точнішим.

## 1. Що апка розуміє без розмітки

| Що | Як визначається |
|---|---|
| Посібник | будь-яка підпапка `Guides/` |
| Індекс посібника | `_guide.md` → `Зміст.md` → `<Посібник> - Зміст.md` → `index.md` / `README.md` (перший знайдений) |
| Порядок | frontmatter `order` → номер у назві (`09.`, `09 -`, `09_`) → позиція у списку wiki-links індексу → алфавіт |
| Назва розділу | frontmatter `title` → перший `# H1` → ім'я файлу без префікса посібника і номера |
| Частина (група розділів) | папка всередині посібника; номер у назві папки задає порядок |
| Огляд частини | файл з тим самим ім'ям, що й папка (`03 - Adding Interactivity/Adding Interactivity.md`) |
| Секції розділу | заголовки `##` (для змісту сторінки — також `###`) |
| Q&A-файл | ім'я містить `Q&A`, `interview` або `співбесід` і у файлі немає `[!question]` → кожен `##` = флешкартка (див. 4.2) |
| Рівень Q&A-файлу | слово в імені: `Junior` / `Middle` / `Senior` / `Tech Lead` |

## 2. Frontmatter

### 2.1 Посібник (`_guide.md` або файл-індекс)

```yaml
---
title: JavaScript
slug: javascript
order: 1
level: junior
tags: [language, frontend]
prerequisites: []
estimatedMinutes: 1200
description: Від типів і замикань до event loop і патернів.
---
```

`prerequisites` — slug-и інших посібників: `[javascript]` для TypeScript.

### 2.2 Розділ

```yaml
---
title: Замикання та лексичне оточення
order: 4
level: middle
tags: [functions, scope]
prerequisites:
  - "[[JavaScript - 03. Функції]]"
estimatedMinutes: 35
id: js-ch-04
---
```

| Поле | Тип | Примітка |
|---|---|---|
| `title` | string | |
| `order` | number | перевизначає номер з імені |
| `level` | `junior` \| `middle` \| `senior` \| `techlead` | для фільтрів і ваги XP |
| `tags` | string[] | можна також `#тег` у тексті |
| `prerequisites` | wiki-link[] | ребра роадмапи; лапки обов'язкові (так Obsidian зберігає лінки у властивостях) |
| `estimatedMinutes` | number | без нього — оцінка 200 слів/хв + 20 с на блок коду |
| `id` | string | стабільний id розділу; без нього — шлях файлу (перейменування = новий розділ) |

## 3. Semantic callouts

Звичайний синтаксис Obsidian: `> [!type] Заголовок`, згорнутий `[!type]-`, розгорнутий `[!type]+`.

| Тип | Аліаси | Призначення |
|---|---|---|
| `tip` | `hint` поза task | порада |
| `warning` | `caution`, `attention` | обережно |
| `important` | `key` | ключова думка розділу (потрапляє в конспект розділу) |
| `example` | | приклад |
| `interview` | | як це питають на співбесіді; стає флешкарткою, якщо має відповідь під `---` |
| `pitfall` | `trap`, `gotcha` | пастка |
| `reel` | `fact`, `фішка` | «Фішка» — мікрофакт для стрічки (див. 3.1) |
| `note`, `info`, `abstract`, `todo`, `success`, `failure`, `danger`, `bug`, `quote` | стандартні Obsidian | мапляться на базові стилі |

Невідомий тип показується як нейтральна примітка з назвою типу — текст ніколи не губиться.

Емодзі в заголовках рівнів (`## 🟢 Junior`) апка прибирає і малює власний маркер рівня — у самому Obsidian усе лишається як є.

```md
> [!pitfall] typeof null
> Повертає `"object"` — історичний баг, який не виправлять.
```

### 3.1 Фішка — `[!reel]`

Стиль-only callout (акцентний тон, іконка ⚡, підпис «Фішка»). Аліаси: `fact`, `фішка`. Заголовок починається з емодзі і показується як є. Згодом рілси витягуватиме вертикальна стрічка, тож кожен — одна самодостатня ідея.

```md
> [!reel] 🧩 typeof null — це баг віком 30 років
> У першій реалізації JS тег об'єкта був `000`, а `null` — нульовий вказівник — теж мав `000`.
>
> ```js
> typeof null // → "object"
> ```
```

Вимоги: заголовок з емодзі ≤ 60 символів, тіло ≤ 280 символів + опційний код ≤ 6 рядків.

## 4. Навчальні одиниці

### 4.1 Флешкартка — `[!question]-`

```md
## 🟢 Junior

> [!question]- Яка різниця між `==` і `===`?
> *часто · теорія* · `js-01-003`
>
> `===` порівнює без приведення типів...
>
> ```js
> 0 == ''   // true
> 0 === ''  // false
> ```
```

- Рівень — з найближчого заголовка вище (`Junior`, `Middle`, `Senior`, `Tech Lead`; емодзі ігнорується) або ключ `level:` у рядку метаданих.
- Рядок метаданих — перший рядок тіла: `*частота · тип* · \`id\``. Частота: `рідко` · `іноді` · `часто` · `дуже часто`. Тип: вільний текст (`теорія`, `код`, `практика`, `порівняння`…); кожне нове значення автоматично з'являється у фільтрах.
- Відповідь — усе після порожнього рядка `>`.

### 4.2 Q&A-файл (без callouts)

```md
## 7. Як працює UPSERT?
%% id: pg-qa-007 %%

Через `INSERT ... ON CONFLICT ...`
```

Кожен `##` — питання (номер `7.` відкидається), тіло до наступного `##` — відповідь. `%% id: … %%` невидимий у режимі читання Obsidian. Режим вмикається іменем файлу (розділ 1) або `kind: qa` у frontmatter.

### 4.3 Тест — `[!quiz]`

Один правильний:

```md
> [!quiz] Що поверне typeof null?
> level: junior · id: js-quiz-001
> - [ ] "null"
> - [x] "object"
> - [ ] "undefined"
>
> **Пояснення:** історичний артефакт першої реалізації JS.
```

Кілька правильних — просто кілька `[x]` (апка покаже чекбокси замість радіокнопок і підпише «кілька відповідей»).

Що виведе код:

```md
> [!quiz] Що виведе код?
> level: middle · type: output · id: js-quiz-014
>
> ```js
> console.log(1);
> setTimeout(() => console.log(2));
> Promise.resolve().then(() => console.log(3));
> console.log(4);
> ```
>
> **Відповідь:** `1 4 3 2`
>
> **Пояснення:** мікрозадачі виконуються до макрозадач.
```

Для `type: output` можна дати або варіанти `- [ ]`, або `**Відповідь:**` для вільного вводу (порівняння без урахування пробілів і переносів).

Ключі рядка метаданих: `level`, `id`, `type` (`single` | `multi` | `output` | `order` | `fill`, за замовчуванням виводиться з чекбоксів), `tags`, `frequency`, `bank` (для `fill`).

#### 4.3.1 Склади код — `type: order` (Parsons problem)

Учень збирає код зі шматків: тапає шматок у «пулі» — він додається в кінець відповіді, тап по шматку у відповіді — повертає назад. Правильно = рівно авторський порядок.

````md
> [!quiz] Склади функцію, що рахує суму аргументів
> level: junior · type: order · id: jsd-03-quiz-07
>
> ```js order
> function sum(...nums) {
>   let total = 0
>   for (const n of nums) {
>     total += n
>   }
>   return total
> }
> return nums.length // ✗
> ```
>
> **Пояснення:** rest-параметр збирає аргументи в масив.
````

- Блок коду з позначкою `order` (` ```js order ` — з підсвіткою мови, або просто ` ```order `). Якщо `type: order` вказано, а позначки немає — береться перший блок коду.
- Шматок = рядок. Якщо в блоці є порожні рядки — шматками стають **блоки, розділені порожнім рядком** (для довших фрагментів).
- Відступи зберігаються і є частиною відповіді.
- Зайвий шматок (дистрактор) — `// ✗` у кінці рядка (також `# ✗`, `-- ✗`); показується без позначки і має лишитися в пулі. Дистрактор не повинен збігатися з правильним рядком.
- Потрібно ≥ 3 правильних шматки, інакше `content:check` покаже помилку.
- Решта тіла (текст, інші блоки коду) — умова; `**Пояснення:**` — як у звичайному тесті.

#### 4.3.2 Заповни пропуски — `type: fill`

````md
> [!quiz] Заповни пропуски, щоб `once` працював
> level: junior · type: fill · id: jsd-05-quiz-08
>
> ```js fill
> function once(fn) {
>   [[let|var]] called = false
>   return function (...args) {
>     if ([[called]]) return
>     called = [[true]]
>     return fn.apply(this, args)
>   }
> }
> ```
````

- Пропуск — `[[відповідь]]`, альтернативи через `|`: `[[let|var]]`. Буквальний `|` всередині — `\|` (`[[\|\||??]]` приймає `||` і `??`).
- Порівняння чутливе до регістру, пробіли з країв обрізаються.
- За замовчуванням — поля вводу прямо в коді. Прапорець `· bank` у рядку метаданих вмикає **банк слів**: чипи з першими відповідями всіх пропусків. `bank: const, false` додає зайві слова-дистрактори.
- Блок без жодного `[[…]]` → помилка в `content:check`.

Обидва режими дають ×1,3 XP (як за написання коду), потрапляють у «Мої помилки» і фільтр «Формат» на сторінці «Тести». Клавіатура: `1`–`9` — взяти шматок / чип, `Backspace` — прибрати останній шматок, `Enter` — перевірити.

### 4.4 Задача — `[!task]`

```md
> [!task] Реалізуй debounce
> level: middle · difficulty: medium · id: js-task-004 · tags: async, timers
>
> Напиши `debounce(fn, ms)`, який...
>
> > [!hint]- Підказка 1
> > Потрібен `setTimeout` у замиканні.
>
> > [!hint]- Підказка 2
> > Кожен новий виклик скидає попередній таймер.
>
> > [!solution]- Еталонне рішення
> > ```js
> > function debounce(fn, ms) { ... }
> > ```
```

`difficulty`: `easy` | `medium` | `hard`. Підказки відкриваються по одній у заданому порядку. Рішення показується після власної спроби або кнопки «Здаюсь».

#### 4.4.1 Задача з автотестами — блоки `starter` і `tests`

Якщо в тілі задачі є блок коду з позначкою `tests`, задача стає **автоперевірною**: замість самооцінки з'являється редактор коду, кнопка «▶️ Запустити тести» і панель результатів. Усі тести зелені → задача зарахована (XP з урахуванням підказок). «🏳️ Здаюсь» показує еталон і зараховує спробу як невдалу.

````md
> [!task] Реалізуй debounce
> level: middle · difficulty: medium · id: jsd-14-task-01
>
> Напиши `debounce(fn, ms)`, який викликає `fn` через `ms` мс після **останнього** виклику.
>
> ```js starter
> function debounce(fn, ms) {
>   // твій код
> }
> ```
>
> ```js tests
> test('викликає один раз після паузи', () => {
>   vi.useFakeTimers()
>   const spy = vi.fn()
>   const run = debounce(spy, 100)
>   run(); run()
>   vi.advanceTimersByTime(100)
>   expect(spy).toHaveBeenCalledTimes(1)
> })
>
> test('передає останні аргументи', async () => {
>   const calls = []
>   const run = debounce((x) => calls.push(x), 20)
>   run('a'); run('b')
>   await sleep(40)
>   expect(calls).toEqual(['b'])
> })
> ```
>
> > [!solution]- Еталонне рішення
> > ```js
> > function debounce(fn, ms) {
> >   let timer
> >   return function (...args) {
> >     clearTimeout(timer)
> >     timer = setTimeout(() => fn.apply(this, args), ms)
> >   }
> > }
> > ```
````

- Позначка — слово після мови: ` ```js starter `, ` ```js tests ` (також `test`, `тести`, `заготовка`). Ці блоки **не показуються** в умові: `starter` стає початковим текстом редактора (потім — збережена чернетка), `tests` — згорнутий блок «🧪 Тести» під редактором.
- `starter` без `tests` — просто заготовка в звичайній задачі з самооцінкою.
- Запускається лише JavaScript (`js`, `javascript`, `mjs`, `cjs`). Для `ts` тести не запускаються, і `content:check` про це попередить.
- Код учня і тести виконуються разом: тести бачать усі функції й змінні з коду учня; власні `const` у тестах не конфліктують з його іменами. Top-level `await` дозволений.
- `pnpm content:check` запускає **еталонне рішення** (перший блок коду в `[!solution]`) проти тестів — зламаний еталон або тест одразу видно.

**API тестів** (мінімальна підмножина Vitest/Jest):

| | |
|---|---|
| `test(name, fn)` / `it(…)` | `fn` синхронна або `async`; `describe(name, fn)` групує |
| `expect(x).toBe(y)` | `Object.is` |
| `.toEqual(y)` | глибоке порівняння (масиви, об'єкти, `Map`, `Set`, `Date`; ключі з `undefined` ігноруються), `.toStrictEqual` |
| `.toBeTruthy()` `.toBeFalsy()` `.toBeNull()` `.toBeUndefined()` `.toBeDefined()` `.toBeNaN()` | |
| `.toContain(v)` `.toHaveLength(n)` `.toMatch(re \| str)` `.toBeInstanceOf(C)` | |
| `.toBeCloseTo(n, digits = 2)` `.toBeGreaterThan(n)` `…OrEqual` `.toBeLessThan(n)` `…OrEqual` | |
| `.toThrow(msg \| RegExp \| ErrorClass)` | `expect(() => f()).toThrow('текст')` |
| `.not.…` | заперечення будь-якого матчера |
| `await expect(p).resolves.toBe(v)` / `.rejects.toThrow('…')` | проміси |
| `vi.fn(impl?)` + `.toHaveBeenCalled()` `.toHaveBeenCalledTimes(n)` `.toHaveBeenCalledWith(...args)` | шпигун; виклики в `spy.mock.calls` |
| `vi.useFakeTimers()` / `vi.useRealTimers()` | штучний годинник для `setTimeout`, `setInterval`, `Date.now()`, `new Date()`, `performance.now()` |
| `vi.advanceTimersByTime(ms)` · `vi.runAllTimers()` · `vi.getTimerCount()` · `vi.setSystemTime(ms)` | керування годинником |
| `sleep(ms)` | справжня пауза (завжди на реальних таймерах) |

Фейкові таймери вимикаються після кожного тесту автоматично. `console.log` з коду і тестів показується в панелі «Консоль».

**Пісочниця і ліміти:** код виконується у Web Worker (не в сторінці): без DOM, без мережі (`fetch`, `XMLHttpRequest`, `WebSocket`, `importScripts` вимкнені). Увесь запуск ≤ 3 с — інакше worker зупиняється з «⏱️ Таймаут: нескінченний цикл?» (результати тестів, що встигли пройти, лишаються). Один `async`-тест ≤ 1,5 с. Пиши тести з фейковими таймерами замість довгих `sleep`.

## 5. Код

````md
```ts title="server.ts" {3,5-7} showLineNumbers
```
````

| Мета | Дія |
|---|---|
| `title="…"` | назва файлу над блоком |
| `{1,4-6}` | підсвітка рядків |
| `showLineNumbers` / `noLineNumbers` | перевизначає автоправило (номери, якщо рядків > 5) |
| `// [!code ++]`, `// [!code --]`, `// [!code highlight]` | diff і підсвітка в самому коді |
| без мови | вгадується з сусідніх блоків розділу, інакше — `text` |

Obsidian ігнорує все після назви мови, тож у ньому код виглядає як раніше.

## 6. Посилання та вбудовування

| Синтаксис | Поведінка |
|---|---|
| `[[Нотатка]]`, `[[Нотатка\|текст]]` | перехід; резолвинг як в Obsidian: повний шлях → найближчий файл у тому ж посібнику → найкоротший шлях |
| `[[Нотатка#Заголовок]]` | перехід до секції |
| `[[Guides/…/Файл]]` | повний шлях |
| лінк поза `Guides/` | відкриває нотатку в Obsidian |
| `![[Нотатка]]`, `![[Нотатка#Заголовок]]` | вбудовує текст (глибина до 3, цикли обриваються) |
| `![[image.png\|400]]` | зображення з шириною |
| `#тег`, `#тег/підтег` | теги розділу |
| `==текст==` | виділення |
| `%%коментар%%` | не показується |

Wiki-links усередині коду — це код, не посилання.

## 7. Банк питань `questions.json`

Лежить у папці посібника або банку. Якщо поруч є і `.md`, і `.json` з тими самими id — перемагає `.md` (його ти редагуєш), JSON лише доповнює відсутні.

```json
[
  {
    "id": "js-01-001",
    "chapter": "01. Типи та змінні",
    "level": "junior",
    "frequency": "часто",
    "type": "теорія",
    "question": "Які примітивні типи є в JavaScript?",
    "answer": "markdown-відповідь"
  }
]
```

Прив'язка банку до посібника: `guide: javascript` у `_guide.md` банку; без нього — поле `chapter` шукається серед розділів усіх посібників.

## 8. Ідентифікатори

- Рекомендована схема: `<guide>-<NN розділу>-<NNN>` для карток, `<guide>-<NN>-quiz-<NN>`, `<guide>-<NN>-task-<NN>`, `<guide>-qa-<NNN>` (так зроблено в `JS Interview Q&A`).
- id унікальний у межах усього vault; дублікат — помилка в панелі «Проблеми контенту», друга одиниця отримує суфікс і попередження.
- Без id апка генерує `h:<хеш>` з тексту питання і пише попередження. Правка відповіді прогрес не губить; правка питання — переноситься автоматично, якщо текст схожий на ≥ 85%.
- `pnpm ids:suggest <guide>` друкує id для вставки.

## 9. Перевірки

Панель «Проблеми контенту» в налаштуваннях: одиниці без id, дублікати id, биті wiki-links, quiz без правильної відповіді, task без рішення, некоректні вправи (`order` < 3 шматків, `fill` без пропусків, `tests` без `test(…)` чи не на JS), prerequisites, що утворюють цикл, невідомі `[!viz]` id чи сценарії.

`pnpm content:check [guide]` друкує те саме для посібника і додатково проганяє еталонні рішення задач через їхні `tests`.

## 10. Як додати новий тип callout

Кожен тип — окремий модуль у `src/content/blocks/<тип>/`:

- тільки оформлення (як `tip`, `pitfall`) — файл `style.ts` з `label`, `tone` і `icon` (іконка з набору `CalloutIcon`);
- навчальна одиниця (як `question`, `quiz`, `task`) — `definition.ts` з функцією `extract`, яка повертає одиницю;
- блок-рендер (як `viz` і `figure`) — `definition.ts` з `RenderBlockDefinition.transform`, який перетворює callout на власний вузол для UI. Це не навчальна одиниця: XP і прогресу немає.

Модуль додається одним рядком у `src/content/blocks/registry.ts`. Парсер, рендерер і пошук підхоплюють його автоматично.

## 11. Шаблон

Готовий посібник-приклад з усіма блоками лежить у `templates/Новий посібник/`. Скопіюйте папку в `Guides/`, перейменуйте — і він з'явиться в бібліотеці без перезапуску.

## 12. Візуалізації — `[!viz]`

Інтерактивні покрокові схеми того, як працює JavaScript. Синтаксис:

```md
> [!viz] event-loop
> scenario: promise-vs-timeout
>
> Необов'язковий підпис під схемою (звичайний markdown).
```

- Заголовок — id візуалізації (регістр не важливий). Аліаси типу: `visualization`, `візуалізація`.
- `scenario:` — необов'язковий; без нього показується перший (типовий) сценарій.
- Усе після рядка `scenario:` — підпис під схемою.
- Невідомий id → нейтральна примітка «Візуалізацію не знайдено», текст автора лишається. Невідомий сценарій → типовий. Обидва випадки потрапляють у «Проблеми контенту».
- Читач може перемикати сценарії в самій схемі. Покрокові: ⏮ ◀ ▶ ⏯ + повзунок, клавіші ← → пробіл, свайп на телефоні.
- Покрокові схеми самі програються, коли видимі (одночасно грає лише одна ілюстрація на сторінці), доки читач не торкнеться керування. З `prefers-reduced-motion` автопрогравання вимкнене.
- Схема обгортається в `<figure>`, а текст після `scenario:` стає її підписом (`<figcaption>`).
- У Obsidian блок виглядає як звичайна цитата з назвою — нічого не ламається.
- Усі схеми й сценарії наживо (лише dev): `/viz`.

## 13. Сцени — `[!figure]`

Анімовані «скриншоти» реальних інструментів у рамці пристрою: DevTools, редактор, браузер. Курсор сам рухається, клікає й друкує, ключові місця підсвічуються з підписом. Ілюстрація програється, коли видима (лише одна на сторінці), циклічно; є кнопка пауза / відтворити / ще раз. З `prefers-reduced-motion` показується фінальний кадр і список кроків.

```md
> [!figure] devtools-console
> scenario: promise-order · device: desktop
>
> Підпис під сценою (markdown).
```

- Аліаси типу: `scene`, `сцена`.
- Рядок мета: `scenario:` (без нього — типовий), `device:` — `auto` *(за замовчуванням: вікно на десктопі, телефон на вузькому екрані)*, `desktop` або `phone`.
- Невідомий id → нейтральна примітка, текст лишається, «Проблеми контенту» отримують попередження. Невідомий сценарій → типовий.
- Усе наживо (лише dev): `/viz`, розділ «Сцени».

| id | scenario | Що показує |
|---|---|---|

## 14. Анімовані схеми — `[!diagram]`

Замість ASCII-малюнків у ```` ```text ```` — справжні HTML-фігури: блоки, стрілки, код, і **покроковий показ**, що сам
програється, коли схема на екрані (рух значень по стрілках, підсвітка рядка коду, що виконується, зміна значень змінних,
пояснення кожного кроку). Читач може гортати кроки сам (Назад / Далі / точки, ← →). У Obsidian це звичайна цитата з
yaml — нічого не ламається. Аліаси: `діаграма`, `схема`.

````md
> [!diagram] Функція: аргумент → обробка → результат
> ```yaml
> layout: flow
> nodes:
>   - { id: arg, label: аргумент, text: "5", tone: blue, icon: "px:box" }
>   - { id: fn, label: функція, code: "function double(x) {\n  return x * 2\n}" }
>   - { id: out, label: результат, text: "?", tone: green }
> edges:
>   - { from: arg, to: fn, label: "double(5)" }
>   - { from: fn, to: out, label: return }
> steps:
>   - { focus: arg, note: "Викликаємо double(5): число 5 — це аргумент." }
>   - { move: { from: arg, to: fn, value: "x = 5" }, line: "fn:1", note: "5 стає параметром x." }
>   - { line: "fn:2", note: "x * 2 → 10." }
>   - { move: { from: fn, to: out, value: "10" }, set: { out: "10" }, note: "return віддає 10 назовні." }
> ```
> Необов'язковий підпис під схемою.
````

**Макети** (`layout`):

| layout | Для чого | Як розкладає |
|---|---|---|
| `flow` | конвеєри, «вхід → обробка → вихід», запит → сервер → відповідь | зліва направо (на телефоні — згори вниз), стрілки між сусідами |
| `stack` | call stack, шари, пріоритети | згори вниз; приховані (`hide`) кадри зникають |
| `tree` | DOM, прототипи, файлове дерево, AST | дерево з лініями, `parent: id` |
| `nest` | області видимості, модулі, вкладені контексти | блоки всередині блоків, `parent: id` |
| `compare` | «до / після», `var` vs `let`, CJS vs ESM | колонки за `col`, заголовки в `columns: { a: …, b: … }` |
| `timeline` | порядок подій у часі, event loop по тіках | вертикальна шкала, мітка `at` |

**Вузол** (`nodes[]`): `id` (обовʼязково), `label` (дрібний підпис), `text` або `code` (вміст; `\n` — новий рядок),
`note` (другий рядок), `tone` (`violet` · `mint` · `blue` · `green` · `yellow` · `orange` · `red` · `pink` · `gray`),
`icon` (`px:…`, `si:…`, `pi:…`), `parent`, `col`, `at`.

**Стрілки** (`edges[]`): `from`, `to`, `label`, `tone`, `dashed`. У `flow`/`stack` малюються між сусідами; без `edges`
— між усіма сусідами; несусідні звʼязки показуються списком під схемою.

**Кроки** (`steps[]`) — що відбувається по черзі:
- `show: id | [ids]` — вузли зʼявляються (і лишаються); вузли, яких немає в жодному `show`, видно одразу;
- `hide` — вузли зникають (кадр знято зі стеку);
- `move: { from, to, value }` (або список) — значення **їде стрілкою** й «падає» в цільовий вузол;
- `line: "id:N"` (або список) — підсвітити рядок N коду вузла (те, що виконується зараз);
- `set: { id: "нове значення" }` — змінна/результат отримує нове значення (з анімацією);
- `focus` — що підсвітити (типово — те, що зʼявилося/змінилося);
- `note` — 1–2 речення: що сталося і **чому**. Пиши як учителю: по одному кроку думки.

Правила гарної схеми: 3–8 вузлів, 3–7 кроків; кожен крок — одна зміна; значення в `move` — справжні значення з коду
(`x = 5`, `"Оля"`, `[1, 2]`); коди в `code` — ті самі, що в тексті статті. Помилки yaml/невідомі id потрапляють у
«Проблеми контенту», а читач бачить нейтральну примітку замість схеми. Приклади наживо (dev): `/viz#diagrams`.
