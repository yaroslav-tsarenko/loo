Замикання (closure) у JavaScript — це функція разом із доступом до змінних того місця, де її створили. Навіть коли зовнішня функція вже повернула результат і «закінчилася», внутрішня функція все ще бачить її змінні, може їх читати й змінювати. Звідси й назва: функція ніби замикає своє оточення в собі.

Навіщо це знати? На замиканнях тримаються приватний стан, обробники подій, debounce, мемоїзація та хуки React. А ще це одне з найпопулярніших питань на співбесідах для Junior і Middle: майже завжди просять пояснити термін своїми словами й розв'язати задачу з `var` у циклі та `setTimeout`.

У цій статті — пояснення без магії, від найпростішого прикладу до реальних шаблонів, класична задача зі співбесіди з трьома способами розв'язання, типові помилки й вправи з відповідями. Увесь код можна запустити в консолі браузера або в Node.js.

## Що таке замикання: перший приклад

Почнімо з функції, яка повертає іншу функцію:

```js
function makeGreeting(name) {
  const greeting = 'Привіт';
  // внутрішня функція використовує змінні зовнішньої
  return function () {
    return `${greeting}, ${name}!`;
  };
}

const greetOlha = makeGreeting('Ольга');
// makeGreeting уже завершилася, але її змінні досі доступні
console.log(greetOlha()); // Привіт, Ольга!
```

Коли викликається `makeGreeting('Ольга')`, створюються дві змінні: параметр `name` і константа `greeting`. Функція повертає назовні іншу функцію й завершується. За логікою «звичайних» мов локальні змінні мали б зникнути. Але `greetOlha()` спокійно повертає `Привіт, Ольга!` — отже, змінні нікуди не поділися.

Офіційне формулювання з [MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Closures): замикання — це комбінація функції та посилань на її оточення, тобто **лексичне середовище** (lexical environment). Там само наголошено: у JavaScript замикання створюються щоразу, коли створюється функція.

Тобто замикання — не окрема конструкція мови й не спеціальний синтаксис. Це властивість кожної функції. Просто помітною вона стає тоді, коли функцію викликають поза місцем, де її оголосили: повертають з іншої функції, передають як колбек, вішають на подію.

> [!tip] Метафора, яка допомагає
> Уяви, що кожна функція під час створення отримує рюкзак зі змінними, які вона бачила навколо себе. Куди б функцію не передали, рюкзак їде разом із нею. Важливо: у рюкзаку лежать не копії значень, а самі змінні.

## Лексична область видимості: звідки функція бере змінні

Щоб зрозуміти замикання, треба зрозуміти одне правило: у JavaScript **лексична** (статична) область видимості. Функція бачить ті змінні, що оточують її **у тексті програми**, а не ті, що є в місці виклику.

```js
let x = 'global';

function outer() {
  let x = 'outer';
  return function inner() {
    return x;
  };
}

const inner = outer();
// inner викликається на глобальному рівні, але бачить x з outer
console.log(inner()); // outer
```

Якби область видимості була динамічною, ми б отримали `global`, бо виклик відбувається на верхньому рівні. Але JavaScript дивиться, **де функцію написано**, тож бачимо `outer`.

Вкладені функції утворюють ланцюжок областей видимості (scope chain). Найглибша функція бачить усі зовнішні рівні аж до глобального:

```js
const e = 10;

function sum(a) {
  return function (b) {
    return function (c) {
      // доступні a, b, c і глобальна e
      return a + b + c + e;
    };
  };
}

console.log(sum(1)(2)(3)); // 16
```

Пошук змінної йде зсередини назовні: спершу в поточній функції, потім у зовнішній, потім ще вище. Перша знайдена змінна з таким ім'ям «перемагає» — так працює затінення (shadowing) у прикладі з `x`.

| Де оголошено | Область видимості | Чи створює блок `{}` нову область |
|---|---|---|
| `var` | функція (або глобальна) | ні |
| `let`, `const` | блок | так |
| параметр функції | функція | — |
| оголошення `function` | функція, у якій його написано | у строгому режимі й модулях — так |

Ця різниця між `var` і `let` здається дрібницею, але саме вона ламає код у циклах — про це окремий розділ нижче.

## Як живуть змінні в замиканні

Найкраще замикання видно на лічильнику. Це класичний приклад приватного стану:

```js
function makeCounter() {
  let count = 0; // приватна змінна: ззовні до неї не дістатися

  return {
    increment() { count += 1; return count; },
    decrement() { count -= 1; return count; },
    value() { return count; },
  };
}

const a = makeCounter();
const b = makeCounter();

a.increment();
a.increment();
b.increment();

console.log(a.value(), b.value()); // 2 1
console.log(a.count);              // undefined
```

З цього коду видно три важливі речі.

1. **Кожен виклик зовнішньої функції створює нове середовище.** `a` і `b` мають кожен свій `count`, вони не заважають один одному. MDN формулює це так: кожне замикання посилається на свою версію змінної.
2. **Функції з одного виклику ділять одне середовище.** `increment`, `decrement` і `value` всередині `a` бачать той самий `count`, тому зміна через один метод видна в іншому.
3. **Змінну не видно ззовні.** `a.count` — це `undefined`, бо `count` не властивість об'єкта, а змінна в замиканні. Змінити її можна тільки через методи, які ми самі дали.

Тепер про пункт, який найчастіше розуміють неправильно: **замикання зберігає змінну, а не її значення на момент створення**. Якщо змінна зміниться пізніше, функція побачить нове значення.

```js
function makeLogger() {
  let level = 'info';
  const log = (msg) => console.log(`[${level}] ${msg}`);
  const setLevel = (newLevel) => { level = newLevel; };
  return { log, setLevel };
}

const logger = makeLogger();
logger.log('старт');      // [info] старт
logger.setLevel('debug');
logger.log('деталі');     // [debug] деталі
```

`log` створили, коли `level` дорівнював `'info'`, але після `setLevel('debug')` вона виводить уже нове значення. Функція «дивиться» в живу змінну.

> [!note] Нотатка
> Скільки часу живуть змінні з замикання? Доти, доки існує хоч одне посилання на функцію, яка їх використовує. Коли `a` і `b` перестануть бути потрібними й на них ніхто не посилатиметься, збирач сміття звільнить і їхні середовища.

## Навіщо замикання на практиці: 5 шаблонів

Замикання — не теорія для співбесід. Ти користуєшся ними щодня, навіть якщо не називаєш їх так.

### Фабрика функцій

Функція, яка створює інші функції з наперед заданими налаштуваннями:

```js
const makeAdder = (x) => (y) => x + y;

const add5 = makeAdder(5);
const add10 = makeAdder(10);

console.log(add5(2), add10(2)); // 7 12
```

Тіло в `add5` і `add10` однакове, а середовища різні: в одному `x` дорівнює 5, в іншому 10. Так само будують форматери цін із валютою, функції запитів із базовою адресою API, валідатори з мінімальною довжиною.

### Функція, яка виконується лише раз

```js
function once(fn) {
  let called = false;
  let result;
  return function (...args) {
    if (!called) {
      called = true;
      result = fn(...args);
    }
    return result;
  };
}

const init = once(() => {
  console.log('Ініціалізація…');
  return 42;
});

console.log(init());
// Ініціалізація…
// 42
console.log(init()); // 42 — без повторної ініціалізації
```

Прапорець `called` і `result` живуть у замиканні, тому кожен наступний виклик знає, що робота вже зроблена.

### Мемоїзація (кеш результатів)

```js
function memoize(fn) {
  const cache = new Map();
  return (n) => {
    if (cache.has(n)) return cache.get(n);
    const value = fn(n);
    cache.set(n, value);
    return value;
  };
}

const slowSquare = (n) => {
  console.log(`рахую ${n}…`);
  return n * n;
};
const fastSquare = memoize(slowSquare);

console.log(fastSquare(9));
// рахую 9…
// 81
console.log(fastSquare(9)); // 81 — узято з кешу
```

### Debounce для пошуку

Коли користувач друкує в полі пошуку, не треба надсилати запит на кожну літеру. Debounce чекає паузу й викликає функцію один раз:

```js
function debounce(fn, ms) {
  let timerId; // спільний для всіх викликів — завдяки замиканню
  return (...args) => {
    clearTimeout(timerId);
    timerId = setTimeout(() => fn(...args), ms);
  };
}

const search = debounce((q) => console.log(`Шукаю: ${q}`), 300);
search('j');
search('ja');
search('jav');
search('java');
// через 300 мс: Шукаю: java
```

### Обробники подій

```js
function makeSizer(size) {
  return () => {
    document.body.style.fontSize = `${size}px`;
  };
}

document.querySelector('#small').addEventListener('click', makeSizer(12));
document.querySelector('#large').addEventListener('click', makeSizer(18));
```

Цей приклад — спрощена версія того, що наводить MDN: кожен обробник пам'ятає свій `size`. Для запуску потрібна сторінка з кнопками `#small` і `#large`. Якщо ти ще не працював із подіями та DOM, почни з [плану вивчення JavaScript з нуля](/blog/javascript-z-nulya) — там є порядок тем.

| Шаблон | Що лежить у замиканні | Де трапляється |
|---|---|---|
| Фабрика функцій | налаштування (`x`, валюта, URL) | утиліти, API-клієнти |
| Приватний стан | лічильник, список, прапорець | модулі, ігрова логіка |
| `once` | `called`, `result` | ініціалізація, підключення до SDK |
| Мемоїзація | `cache` | дорогі обчислення |
| Debounce / throttle | `timerId` | пошук, ресайз, скрол |
| Обробники подій | дані для конкретної кнопки | інтерфейси, React |

## Задача зі співбесіди: var у циклі і setTimeout

Ця задача з'являється на співбесідах настільки часто, що її варто знати напам'ять. Що виведе код?

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 3
// 3
// 3
```

Більшість новачків чекає `0, 1, 2`, а отримує `3, 3, 3`. Причина в двох речах:

1. `var` має область видимості **функції**, а не блоку. У циклі не створюється три різні змінні `i` — є лише одна, спільна для всіх ітерацій.
2. `setTimeout` викликає колбек **пізніше**, після завершення поточного коду. На той момент цикл уже закінчився, і `i` дорівнює 3.

Усі три стрілкові функції замикаються на одну й ту саму змінну, тож усі бачать її фінальне значення. Як це виправити?

### Спосіб 1: let

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 0
// 1
// 2
```

Для `let` у заголовку циклу `for` діє спеціальне правило: на кожній ітерації створюється нова змінна, а її початкове значення копіюється з попередньої. Це описано в [документації MDN до `for`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/for). Отже, кожен колбек замикає власну `i`.

![Порівняння: з var усі колбеки дивляться на одну змінну, з let кожен має свою](/blog/zamykannia-v-javascript-prostymy-slovamy/img-2.webp)

### Спосіб 2: IIFE (як робили до ES2015)

```js
for (var i = 0; i < 3; i++) {
  ((n) => {
    setTimeout(() => console.log(n), 0);
  })(i);
}
// 0
// 1
// 2
```

IIFE (Immediately Invoked Function Expression) — функція, яку викликають одразу після створення. Кожен виклик створює нове середовище з параметром `n`, куди копіюється поточне значення `i`.

### Спосіб 3: forEach або фабрика функцій

```js
[0, 1, 2].forEach((n) => {
  setTimeout(() => console.log(n), 0);
});
// 0
// 1
// 2
```

Колбек `forEach` викликається окремо для кожного елемента, тому кожен виклик має своє `n`.

> [!example] Як відповісти на співбесіді
> «Замикання — це функція разом із лексичним середовищем, у якому її створили. Завдяки цьому внутрішня функція має доступ до змінних зовнішньої навіть після того, як зовнішня завершилася. Я використовую замикання для приватного стану, фабрик функцій, debounce і обробників подій. Класична пастка — `var` у циклі: усі колбеки бачать одну змінну, тому треба `let`.» Після цього покажи `makeCounter` — і відповідь готова.

## Застарілі значення і пам'ять

Замикання дуже корисні, але є дві ситуації, де вони дивують.

### «Застаріле» значення

Якщо функція бачить живу змінну, звідки береться застаріле значення? З того, що в замикання потрапило не те, що ти думаєш. Порівняй:

```js
let price = 100;

const label = `Ціна: ${price} грн`; // рядок обчислено зараз
const show = () => label;
const showLive = () => `Ціна: ${price} грн`; // рядок обчислюється під час виклику

price = 200;

console.log(show());     // Ціна: 100 грн
console.log(showLive()); // Ціна: 200 грн
```

`show` замикає змінну `label`, а в ній уже готовий рядок зі старою ціною. `showLive` замикає саму `price` і рахує рядок під час кожного виклику. У React саме так виникають «stale closures» (застарілі замикання): колбек у `useEffect` чи `setInterval` бачить значення стану з того рендеру, коли його створили, а не найновіше.

### Пам'ять

Поки функція жива, живі й усі змінні, на які вона посилається. Зазвичай це не проблема. Проблема — коли довгоживучий об'єкт (глобальний масив обробників, таймер без `clearInterval`, кеш без обмеження розміру) тримає замикання з великими даними, які вже ніхто не використовує. Тоді пам'ять не звільняється.

MDN окремо радить не створювати функції всередині інших функцій без потреби: кожен екземпляр функції має власне середовище, а це додаткова пам'ять і час. Наприклад, методи класу краще оголошувати в класі (тоді вони потрапляють у прототип), а не створювати в конструкторі для кожного об'єкта.

> [!warning] Увага
> Знімай обробники подій (`removeEventListener`) і зупиняй таймери (`clearInterval`, `clearTimeout`), коли вони вже не потрібні. Інакше разом із ними в пам'яті лишаються всі змінні з їхніх замикань.

## Типові помилки

> [!pitfall] Типова помилка
> Думати, що замикання «фотографує» значення. Воно зберігає посилання на змінну. Якщо змінна зміниться, функція побачить нове значення.

- **`var` у циклі з асинхронним колбеком.** Усі колбеки отримують одне фінальне значення. Виправлення — `let` або `forEach`.
- **Очікування, що змінна з замикання — властивість об'єкта.** `counter.count` дасть `undefined`: до змінної доступ мають лише функції, створені поруч із нею.
- **Плутанина з динамічною областю видимості.** Функція бачить змінні з місця, де її **написано**, а не з місця, де її **викликали**.
- **Спільний стан там, де потрібен окремий.** Якщо створити лічильник один раз і роздати його кільком компонентам, усі вони рахуватимуть разом. Викликай фабрику для кожного окремо.
- **Великі дані в довгоживучих замиканнях.** Обробник, який замкнув масив на сотні тисяч елементів і ніколи не знімається, тримає цей масив у пам'яті.
- **Створення функцій у кожному виклику без потреби.** Метод у конструкторі — це нова функція для кожного об'єкта. Якщо приватний стан не потрібен, оголоси метод у класі.

## Перевір себе

1. Що виведе код?
   ```js
   function f() {
     let x = 1;
     const g = () => x;
     x = 2;
     return g;
   }
   console.log(f()());
   ```
2. Що виведе цей код і чому?
   ```js
   const fns = [];
   for (let i = 0; i < 3; i++) fns.push(() => i * 10);
   console.log(fns.map((fn) => fn()));
   ```
3. Напиши функцію `makeId(prefix)`, яка повертає генератор ідентифікаторів: `userId()` → `user-1`, `user-2`, а `orderId()` має рахувати окремо й почати з `order-1`.
4. Що виведе цей код?
   ```js
   function createButtons() {
     const handlers = [];
     for (var i = 1; i <= 3; i++) handlers.push(() => `Кнопка ${i}`);
     return handlers.map((h) => h());
   }
   console.log(createButtons());
   ```

> [!solution]- Відповіді
> 1. `2`. Функція `g` замикає змінну `x`, а не її значення на момент створення. До виклику `x` уже дорівнює 2.
> 2. `[ 0, 10, 20 ]`. З `let` кожна ітерація має свою змінну `i`, тож кожна функція пам'ятає своє значення.
> 3. Розв'язок:
>    ```js
>    function makeId(prefix) {
>      let n = 0;
>      return () => `${prefix}-${++n}`;
>    }
>    const userId = makeId('user');
>    const orderId = makeId('order');
>    console.log(userId(), userId(), orderId()); // user-1 user-2 order-1
>    ```
>    Кожен виклик `makeId` створює окреме середовище з власним `n`.
> 4. `[ 'Кнопка 4', 'Кнопка 4', 'Кнопка 4' ]`. Змінна `var i` одна на всю функцію, і після циклу вона дорівнює 4 (цикл зупинився, коли умова `i <= 3` стала хибною). Заміни `var` на `let` — отримаєш `Кнопка 1`, `Кнопка 2`, `Кнопка 3`.

## Коротко

- Замикання — це функція разом із доступом до змінних того місця, де її створили. У JavaScript воно є в кожної функції.
- Область видимості лексична: важливо, де функцію написано, а не де її викликали.
- Замикання зберігає саму змінну, а не копію значення. Кожен виклик зовнішньої функції створює нове середовище.
- На замиканнях будують приватний стан, фабрики функцій, `once`, мемоїзацію, debounce і обробники подій.
- `var` у циклі з `setTimeout` дає `3, 3, 3`, бо змінна одна. `let` створює нову змінну на кожній ітерації.
- Стеж за пам'яттю: знімай обробники й таймери, не тримай великі дані в довгоживучих функціях.
