Promise у JavaScript — це об'єкт-обіцянка: він представляє результат операції, яка ще не завершилася. Наприклад, запиту до сервера, читання файлу чи таймера. Замість того щоб чекати й блокувати програму, функція одразу повертає Promise, а результат прийде пізніше: або успіх зі значенням, або помилка з причиною.

**async/await** — це зручніший запис тих самих промісів. Слово `async` перед функцією означає, що вона завжди повертає Promise. `await` всередині неї каже: «зачекай, поки проміс завершиться, і дай мені його значення». Код читається зверху вниз, як звичайний синхронний, а помилки ловляться через `try/catch`.

Без цього не обійтися в жодному реальному проєкті: кожен `fetch`, кожен запит до бази й кожне читання файлу в Node.js асинхронні. А на співбесідах Junior майже завжди питають, чим відрізняються колбеки, проміси й async/await і що виведе код із `setTimeout` та `then`. Нижче — усе по порядку, від першого промісу до паралельних запитів і таймаутів. Увесь код можна запустити в Node.js 22+ (файл `.mjs`) або в консолі браузера.

## Навіщо потрібна асинхронність

JavaScript виконує код в одному потоці: одна дія за раз. Якби запит до сервера, що триває секунду, блокував виконання, сторінка на цю секунду «зависала б»: не працювали б кнопки й скрол. Тому повільні операції запускаються у фоні, а JavaScript іде далі й обробляє результат, коли той буде готовий.

Спершу для цього використовували лише **колбеки** (callback) — функції, які передають іншій функції, щоб та викликала їх пізніше. Проблема з'являлася, коли операцій кілька й кожна залежить від попередньої:

```js
getUser(1, (user) => {
  getOrders(user.id, (orders) => {
    getDelivery(orders[0].id, (delivery) => {
      console.log(delivery.status);
      // і ще помилки треба обробити на кожному рівні
    });
  });
});
```

Таку «піраміду» прозвали callback hell: код росте вправо, помилки доводиться обробляти окремо на кожному рівні. Promise (стандарт ES2015) і async/await (ES2017) розв'язують саме цю проблему.

| Підхід | Як виглядає | Помилки | Коли трапляється |
|---|---|---|---|
| Колбеки | вкладені функції | вручну на кожному рівні | старі API, події DOM |
| Promise | ланцюжок `.then().then()` | один `.catch()` у кінці | бібліотеки, `Promise.all` |
| async/await | звичайний код зверху вниз | `try/catch` | майже весь сучасний код |

## Що таке Promise: три стани

За [документацією MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise), проміс завжди перебуває в одному з трьох станів:

| Стан | Що означає | Що далі |
|---|---|---|
| `pending` (очікування) | операція ще триває | чекаємо |
| `fulfilled` (виконано) | операція успішна, є значення | викликається `then` |
| `rejected` (відхилено) | операція впала, є причина (зазвичай `Error`) | викликається `catch` |

Проміс, який уже виконано або відхилено, називають **settled** (завершеним). Важлива властивість: стан змінюється лише один раз. Завершений проміс уже не повернеться в очікування й не змінить результат.

![Три стани промісу: очікування, виконано, відхилено](/blog/promise-async-await-javascript/img-1.webp)

Створімо проміс самі. Конструктор `new Promise` приймає функцію з двома параметрами: `resolve` (завершити успіхом) і `reject` (завершити помилкою).

```js
// функція-затримка: через ms мілісекунд повертає value
const wait = (ms, value) =>
  new Promise((resolve) => setTimeout(() => resolve(value), ms));

const p = wait(500, 'готово');
console.log(p); // Promise { <pending> }

p.then((value) => console.log(value)); // через пів секунди: готово
```

Одразу після створення проміс у стані `pending`, бо таймер ще не спрацював. Через 500 мс викликається `resolve('готово')`, проміс переходить у `fulfilled`, і `then` отримує значення.

> [!note] Нотатка
> На практиці `new Promise` пишуть рідко. Більшість API вже повертає проміси: `fetch`, `fs/promises` у Node.js, клієнти баз даних. Конструктор потрібен, щоб «загорнути» старий API на колбеках, як `setTimeout` вище.

## then, catch і finally: ланцюжки промісів

У промісу є три методи, і кожен **повертає новий проміс**. Тому їх можна з'єднувати в ланцюжок:

- `then(fn)` — викликає `fn` зі значенням, коли проміс виконано;
- `catch(fn)` — викликає `fn` з причиною, коли проміс відхилено;
- `finally(fn)` — викликає `fn` у будь-якому разі (наприклад, щоб сховати індикатор завантаження).

Що передається далі ланцюжком, залежить від того, що зробив обробник:

1. Повернув звичайне значення — наступний `then` отримає це значення.
2. Повернув проміс — ланцюжок дочекається його й передасть далі результат.
3. Кинув помилку (`throw`) — проміс відхиляється, і все до найближчого `catch` пропускається.

```js
Promise.resolve(2)
  .then((n) => n * 10)                                       // 20
  .then((n) => { throw new Error(`погане число ${n}`); })
  .then(() => console.log('сюди не дійдемо'))                // пропущено
  .catch((err) => { console.log('Помилка:', err.message); return 0; })
  .then((n) => console.log('Продовжуємо з', n))
  .finally(() => console.log('Завершено'));

// Помилка: погане число 20
// Продовжуємо з 0
// Завершено
```

Зверни увагу на рядок після `catch`. Якщо обробник помилки завершився нормально, ланцюжок вважає помилку виправленою й іде далі успішною гілкою. MDN наголошує на цьому окремо: щоб помилка й далі «текла» ланцюжком, у `catch` треба знову кинути її через `throw`.

> [!pitfall] Типова помилка
> Забути `return` у `then`. Якщо написати `.then((x) => { x * 10; })` з фігурними дужками й без `return`, наступний `then` отримає `undefined`. Стрілкова функція без фігурних дужок (`(x) => x * 10`) повертає значення сама.

## async/await: той самий Promise, але читається як звичайний код

Перепишемо роботу з промісами через `async/await`. Головні правила з [MDN про async function](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/async_function):

- async-функція **завжди повертає Promise**. Якщо повернути звичайне значення, воно загорнеться в проміс;
- якщо всередині async-функції виникла неперехоплена помилка, повернутий проміс відхиляється;
- `await` призупиняє функцію, поки проміс не завершиться, і повертає його значення. Якщо проміс відхилено, `await` кидає помилку, тож її можна зловити `try/catch`.

```js
async function getNumber() {
  return 42;
}

const result = getNumber();
console.log(result);                     // Promise { 42 }
console.log(result instanceof Promise);  // true
result.then((n) => console.log(n));      // 42
```

Навіть `return 42` дає проміс, а не число. Щоб дістати значення, потрібен `await` або `then`.

Тепер приклад із пірамідою колбеків, переписаний через `async/await`:

```js
async function showDeliveryStatus(userId) {
  try {
    const user = await getUser(userId);
    const orders = await getOrders(user.id);
    const delivery = await getDelivery(orders[0].id);
    console.log(delivery.status);
  } catch (err) {
    // сюди потрапить помилка з будь-якого з трьох запитів
    console.log('Не вдалося:', err.message);
  } finally {
    console.log('Перевірку завершено');
  }
}
```

Три кроки, один блок обробки помилок, жодної вкладеності. Логіка та сама, що й у ланцюжку `then`, але читати її значно легше.

Важливо розуміти, що `await` **не блокує весь JavaScript**. Він призупиняє лише поточну async-функцію. Поки вона чекає, браузер реагує на кліки, а інші функції виконуються. Коли проміс завершиться, функція продовжить роботу з того самого місця. Кожен такий крок «пам'ятає» локальні змінні завдяки тому ж механізму, що й [замикання в JavaScript](/blog/zamykannia-v-javascript-prostymy-slovamy).

> [!tip] Порада
> `await` працює лише всередині async-функцій. Виняток — верхній рівень JavaScript-модуля (top-level await): файли `.mjs`, `<script type="module">` у браузері або Node.js із `"type": "module"` у `package.json`. У звичайному скрипті `await` поза async-функцією дає `SyntaxError`.

## Послідовно чи паралельно: Promise.all та інші

Найчастіша помилка тих, хто щойно освоїв `await`, — чекати незалежні операції по черзі. Якщо дані користувача й список замовлень не залежать одне від одного, немає сенсу чекати перше, щоб почати друге.

```js
const wait = (ms, value) =>
  new Promise((resolve) => setTimeout(() => resolve(value), ms));

const getUser = () => wait(1000, { name: 'Оля' });
const getOrders = () => wait(1000, ['книга', 'чашка']);

console.time('послідовно');
const user1 = await getUser();
const orders1 = await getOrders(); // стартує лише після першого
console.timeEnd('послідовно');     // послідовно: 2.004s

console.time('паралельно');
const [user2, orders2] = await Promise.all([getUser(), getOrders()]);
console.timeEnd('паралельно');     // паралельно: 1.002s
console.log(user2.name, orders2);  // Оля [ 'книга', 'чашка' ]
```

Обидва запити тривають по секунді. Послідовно це дві секунди, паралельно — одна. На реальній сторінці з п'ятьма запитами різниця стає дуже відчутною.

![Послідовні запити тривають довше, паралельні через Promise.all — як найдовший із них](/blog/promise-async-await-javascript/img-2.webp)

У `Promise` є чотири методи для групи промісів. Усі приймають масив (точніше, будь-який ітерований об'єкт) і повертають один проміс:

| Метод | Коли виконується | Коли відхиляється | Для чого |
|---|---|---|---|
| `Promise.all` | усі виконані, результат — масив значень | при першій же помилці | потрібні всі дані разом |
| `Promise.allSettled` | коли всі завершилися, з будь-яким результатом | ніколи | незалежні операції, звіт про кожну |
| `Promise.race` | перший завершений, якщо він успішний | перший завершений, якщо це помилка | таймаути |
| `Promise.any` | перший успішний | усі впали (`AggregateError`) | кілька дзеркал, беремо найшвидше |

Як вони поводяться на практиці:

```js
const fail = (ms, msg) =>
  new Promise((_, reject) => setTimeout(() => reject(new Error(msg)), ms));

try {
  await Promise.all([wait(300, 'A'), fail(100, 'сервер B упав'), wait(200, 'C')]);
} catch (err) {
  console.log('all:', err.message); // all: сервер B упав
}

const results = await Promise.allSettled([wait(300, 'A'), fail(100, 'сервер B упав')]);
console.log(results.map((r) => (r.status === 'fulfilled' ? r.value : r.reason.message)));
// [ 'A', 'сервер B упав' ]

console.log(await Promise.race([wait(300, 'повільний'), wait(100, 'швидкий')]));
// швидкий

console.log(await Promise.any([fail(50, 'дзеркало 1'), wait(200, 'дзеркало 2')]));
// дзеркало 2
```

Класичне застосування `Promise.race` — таймаут для операції, яка може «зависнути»:

```js
function withTimeout(promise, ms) {
  const timeout = new Promise((_, reject) =>
    setTimeout(() => reject(new Error(`Час вийшов: ${ms} мс`)), ms));
  return Promise.race([promise, timeout]);
}

try {
  await withTimeout(wait(2000, 'дані'), 500);
} catch (err) {
  console.log(err.message); // Час вийшов: 500 мс
}
```

> [!warning] Увага
> `Promise.all` не скасовує решту операцій, коли одна впала. Запити, які вже стартували, продовжують виконуватися, просто їхні результати нікому не потрібні. Для справжнього скасування запитів `fetch` використовують `AbortController` або `AbortSignal.timeout(ms)` — приклад нижче.

## Реальний приклад: fetch з обробкою помилок

Зберемо все разом у функцію, яку можна взяти в проєкт. Тут є нюанс, на якому спотикаються навіть досвідчені розробники: `fetch` **не відхиляє проміс, якщо сервер відповів помилкою** на кшталт 404 чи 500. Проміс відхиляється лише тоді, коли запит узагалі не вдався: немає мережі, неправильна адреса, спрацював таймаут. Статус відповіді треба перевіряти самому через `response.ok`, як і радить [MDN про fetch](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch).

```js
async function getJson(url) {
  // AbortSignal.timeout скасує запит, якщо він триває довше 5 секунд
  const response = await fetch(url, { signal: AbortSignal.timeout(5000) });
  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }
  return response.json(); // теж проміс: тіло відповіді читається асинхронно
}

try {
  const user = await getJson('https://jsonplaceholder.typicode.com/users/1');
  console.log(user.name); // Leanne Graham
  await getJson('https://jsonplaceholder.typicode.com/users/99999');
} catch (err) {
  console.log('Не вдалося завантажити:', err.message); // Не вдалося завантажити: HTTP 404
}
```

Без перевірки `response.ok` другий запит «успішно» повернув би порожній об'єкт, і помилка вилізла б значно пізніше, в іншому місці коду.

## У якому порядку виконується код

Це улюблене питання співбесід: що виведе код, де змішано звичайні рядки, `setTimeout` і `then`?

```js
console.log('1: синхронний код');
setTimeout(() => console.log('4: setTimeout'), 0);
Promise.resolve().then(() => console.log('3: then'));
console.log('2: синхронний код');

// 1: синхронний код
// 2: синхронний код
// 3: then
// 4: setTimeout
```

Правило таке:

1. Спершу виконується весь синхронний код до кінця.
2. Потім — усі **мікрозадачі** (microtasks): обробники `then`, `catch`, `finally` і продовження після `await`.
3. Лише після цього — **макрозадачі** (tasks): колбеки `setTimeout`, `setInterval`, події.

Тому `then` спрацьовує раніше за `setTimeout(..., 0)`, хоча той стоїть у коді вище. Нуль мілісекунд означає не «негайно», а «у наступній черзі задач».

З `await` працює те саме правило. Код async-функції до першого `await` виконується синхронно, одразу під час виклику, а все, що після `await`, стає мікрозадачею. Детально механізм черг описано в [статті MDN про мікрозадачі](https://developer.mozilla.org/en-US/docs/Web/API/HTML_DOM_API/Microtask_guide).

> [!example] Як відповісти на співбесіді
> «Promise — це об'єкт, що представляє майбутній результат асинхронної операції, зі станами pending, fulfilled і rejected. async/await — синтаксис поверх промісів: async-функція завжди повертає проміс, а await чекає на нього й повертає значення, помилки ловляться try/catch. Незалежні запити запускаю паралельно через Promise.all. Обробники промісів — це мікрозадачі, тому вони виконуються раніше за setTimeout.»

## Типові помилки

- **Забутий `await`.** Без нього змінна містить проміс, а не значення. `getPrice() + 50`, де `getPrice` — async-функція, дасть рядок `'[object Promise]50'`, а не 150.
- **async-колбек у `forEach`.** MDN прямо пише, що `forEach` очікує синхронну функцію й не чекає на проміси. Код після циклу виконається раніше, ніж будь-який `await` всередині:

```js
const ids = [1, 2, 3];
const loaded = [];
ids.forEach(async (id) => {
  loaded.push(await wait(100, id));
});
console.log(loaded); // [] — forEach не чекав

// послідовно: for...of
const loaded2 = [];
for (const id of ids) loaded2.push(await wait(100, id));
console.log(loaded2); // [ 1, 2, 3 ]

// паралельно: map + Promise.all
const loaded3 = await Promise.all(ids.map((id) => wait(100, id)));
console.log(loaded3); // [ 1, 2, 3 ]
```

- **Незалежні запити через `await` по черзі.** Працює, але повільно. Якщо другий запит не потребує результату першого, використовуй `Promise.all`.
- **`[await p1, await p2]` для промісів, запущених заздалегідь.** Якщо `p2` відхилиться, поки код чекає `p1`, виникне необроблене відхилення, навіть якщо далі є `catch`. MDN радить замість цього `Promise.all` або `Promise.allSettled`.
- **Проміс без обробки помилок.** Відхилений проміс без `catch` чи `try/catch` дає «Unhandled promise rejection». У сучасному Node.js такий процес за замовчуванням завершується з помилкою.
- **Очікування, що `fetch` відхилиться при 404.** Не відхилиться: перевіряй `response.ok`.
- **Забутий `return` у `then`.** Наступний обробник отримає `undefined`.

## Перевір себе

1. У якому порядку з'являться літери?
   ```js
   console.log('A');
   setTimeout(() => console.log('B'), 0);
   Promise.resolve().then(() => console.log('C'));
   (async () => {
     console.log('D');
     await null;
     console.log('E');
   })();
   console.log('F');
   ```
2. Що буде в `r`?
   ```js
   const r = await Promise.resolve(1)
     .then((x) => x + 1)
     .then((x) => { x * 10; })
     .then((x) => x);
   ```
3. Що виведе код?
   ```js
   const s = await Promise.reject(new Error('ой'))
     .catch(() => 'запасне значення')
     .then((v) => v.toUpperCase());
   console.log(s);
   ```
4. Є три незалежні запити `loadProfile()`, `loadFriends()` і `loadNews()`. Новини не обов'язкові: якщо вони впали, сторінку все одно треба показати. Як їх завантажити?

> [!solution]- Відповіді
> 1. `A D F C E B`. Синхронно виконуються `A`, потім тіло async-функції до `await` (`D`), потім `F`. Далі мікрозадачі в порядку постановки в чергу: `C`, потім продовження після `await` (`E`). Останнім іде `setTimeout` — `B`.
> 2. `undefined`. У другому `then` фігурні дужки без `return`, тож функція нічого не повертає.
> 3. `ЗАПАСНЕ ЗНАЧЕННЯ`. `catch` обробив помилку й повернув рядок, ланцюжок пішов далі успішною гілкою.
> 4. Наприклад, через `Promise.allSettled`, а потім перевірити статус кожного результату:
>    ```js
>    const [profile, friends, news] = await Promise.allSettled([
>      loadProfile(), loadFriends(), loadNews(),
>    ]);
>    if (profile.status === 'rejected' || friends.status === 'rejected') {
>      throw new Error('Без профілю й друзів сторінку не показати');
>    }
>    const newsList = news.status === 'fulfilled' ? news.value : [];
>    ```
>    Можна й так: обов'язкові запити через `Promise.all`, а `loadNews().catch(() => [])` додати в той самий масив, щоб помилка новин не зупинила решту.

## Коротко

- Promise — об'єкт-обіцянка результату асинхронної операції. Стани: `pending`, `fulfilled`, `rejected`. Стан змінюється лише один раз.
- `then`, `catch` і `finally` повертають нові проміси, тому з них будують ланцюжки. Помилка пропускає все до найближчого `catch`.
- async-функція завжди повертає проміс. `await` чекає на проміс і повертає значення, а помилки ловить `try/catch`. Весь JavaScript він не блокує.
- Незалежні операції запускай паралельно: `Promise.all`, якщо потрібні всі результати, `Promise.allSettled`, якщо кожна операція незалежна.
- Обробники промісів — мікрозадачі: вони виконуються після синхронного коду, але раніше за `setTimeout`.
- `fetch` не відхиляється при 404 чи 500, а `forEach` не чекає на `await`. Ці дві пастки трапляються найчастіше.
