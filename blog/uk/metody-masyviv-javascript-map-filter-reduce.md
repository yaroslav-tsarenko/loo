**Методи масивів** — це вбудовані функції, які є в кожного масиву JavaScript: `map`, `filter`, `reduce`, `find`, `some`, `sort` та інші. Вони замінюють більшість циклів `for`: ти описуєш, *що* зробити з елементами, а не *як* їх перебирати. Код стає коротшим, і з першого слова зрозуміло, що він робить: `filter` — відбирає, `map` — перетворює, `reduce` — згортає в одне значення.

Щоб орієнтуватися, достатньо відповісти на два питання про кожен метод: **що він повертає** (новий масив, один елемент, `true`/`false` чи `undefined`) і **чи змінює він оригінальний масив**. Саме на цьому ламаються новачки, і саме про це питають на співбесідах: «чим `map` відрізняється від `forEach`», «чому `sort` зіпсував дані», «що поверне `reduce` на порожньому масиві».

Нижче — шпаргалка з усіма ходовими методами в одній таблиці, розбір кожного з робочими прикладами (код перевірено в Node.js 25, працює і в консолі браузера), ланцюжки методів на реальних даних, типові помилки й вправи з відповідями. Факти звірено з [довідником MDN про Array](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array).

## Шпаргалка: усі основні методи масивів в одній таблиці

| Метод | Що робить | Що повертає | Змінює масив? |
|---|---|---|---|
| `map(fn)` | перетворює кожен елемент | новий масив тієї ж довжини | ні |
| `filter(fn)` | відбирає елементи за умовою | новий масив (можливо, коротший) | ні |
| `find(fn)` / `findLast(fn)` | шукає перший / останній збіг | елемент або `undefined` | ні |
| `findIndex(fn)` | шукає позицію першого збігу | індекс або `-1` | ні |
| `some(fn)` / `every(fn)` | чи хоч один / чи всі відповідають умові | `true` / `false` | ні |
| `includes(value)` | чи є таке значення | `true` / `false` | ні |
| `reduce(fn, init)` | згортає масив в одне значення | будь-що: число, об'єкт, масив | ні |
| `forEach(fn)` | виконує дію для кожного елемента | `undefined` | ні (сам по собі) |
| `sort(fn)` / `toSorted(fn)` | сортує | той самий масив / новий масив | так / ні |
| `reverse()` / `toReversed()` | розвертає | той самий масив / новий масив | так / ні |
| `splice()` / `toSpliced()` | видаляє чи вставляє елементи | видалені елементи / новий масив | так / ні |
| `slice(start, end)` | вирізає шматок | новий масив | ні |
| `flat()` / `flatMap(fn)` | сплощує вкладені масиви | новий масив | ні |
| `join(sep)` | склеює в рядок | рядок | ні |
| `push` / `pop` / `shift` / `unshift` | додає чи забирає з кінця / початку | нова довжина / забраний елемент | так |

Майже всі методи перебору приймають **колбек** (callback) — функцію, яку метод викликає для кожного елемента з трьома аргументами: `(element, index, array)`. Найчастіше потрібен лише перший, іноді другий.

```js
const nums = [3, 7, 10];
nums.map((n, i) => `${i}: ${n}`);
// ['0: 3', '1: 7', '2: 10']
```

Усі приклади нижче використовують один невеликий масив товарів — так легше побачити, чим методи відрізняються:

```js
const products = [
  { name: 'Ноутбук', price: 32000, category: 'техніка', inStock: true },
  { name: 'Мишка', price: 650, category: 'техніка', inStock: false },
  { name: 'Рюкзак', price: 1800, category: 'аксесуари', inStock: true },
  { name: 'Навушники', price: 2400, category: 'техніка', inStock: true },
];
```

## map: перетворити кожен елемент

`map` створює **новий масив тієї самої довжини**, у якому кожен елемент — результат колбека. Оригінал не змінюється. Це метод для ситуацій «маю список одного, потрібен список іншого»: з об'єктів витягнути назви, з цін у гривнях отримати ціни зі знижкою, з даних отримати HTML-рядки.

```js
const names = products.map((p) => p.name);
console.log(names);
// ['Ноутбук', 'Мишка', 'Рюкзак', 'Навушники']

const discounted = products.map((p) => ({ ...p, price: Math.round(p.price * 0.9) }));
console.log(discounted[0].price); // 28800
console.log(products[0].price);   // 32000 — оригінал не змінився
```

Зверни увагу на дужки навколо об'єкта: `(p) => ({ ... })`. Без них фігурні дужки сприймаються як тіло функції, і `map` поверне масив `undefined`.

Головне правило: **колбек `map` має повертати значення**. Якщо забути `return` у функції з фігурними дужками, отримаєш масив із `undefined`:

```js
const broken = [1, 2, 3].map((n) => { n * 2; });
console.log(broken); // [undefined, undefined, undefined]

const fixed = [1, 2, 3].map((n) => n * 2);
console.log(fixed); // [2, 4, 6]
```

## filter і find: відібрати й знайти

`filter` повертає **новий масив** з елементами, для яких колбек повернув істинне значення. Якщо жоден не підійшов — порожній масив `[]`, а не `null` і не помилку.

```js
const available = products.filter((p) => p.inStock);
console.log(available.map((p) => p.name));
// ['Ноутбук', 'Рюкзак', 'Навушники']

const cheap = products.filter((p) => p.price < 100);
console.log(cheap); // []
```

`find` шукає **один елемент** — перший, що відповідає умові, — і повертає сам елемент або `undefined`. `findIndex` повертає його позицію або `-1`. Для пошуку з кінця є `findLast` і `findLastIndex`.

```js
const bag = products.find((p) => p.category === 'аксесуари');
console.log(bag.name); // Рюкзак

const lastTech = products.findLast((p) => p.category === 'техніка');
console.log(lastTech.name); // Навушники

console.log(products.findIndex((p) => p.name === 'Мишка'));  // 1
console.log(products.findIndex((p) => p.name === 'Планшет')); // -1
```

| Потрібно | Метод | Результат, якщо нічого немає |
|---|---|---|
| усі підхожі елементи | `filter` | `[]` |
| перший підхожий елемент | `find` | `undefined` |
| позиція першого підхожого | `findIndex` | `-1` |

`find` зупиняється на першому збігу, тому для пошуку одного елемента він швидший і зрозуміліший, ніж `filter(...)[0]`.

## some, every, includes: перевірити умову

Ці три методи відповідають на питання «так чи ні» і повертають `true` або `false`.

- `some` — чи **хоча б один** елемент відповідає умові;
- `every` — чи **всі** елементи відповідають умові;
- `includes` — чи є в масиві **конкретне значення** (без колбека).

```js
console.log(products.some((p) => !p.inStock));      // true — мишки немає в наявності
console.log(products.every((p) => p.price > 500));  // true
console.log(['uk', 'en', 'de'].includes('en'));     // true
```

Як і `find`, методи `some` і `every` **зупиняються, щойно відповідь відома**: `some` — на першому `true`, `every` — на першому `false`. Це прямо описано в [документації MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array#iterative_methods), і саме тому вони ефективніші за `filter(...).length > 0`.

Є дві цікаві деталі. Перша: на порожньому масиві `every` повертає `true`, а `some` — `false` (у порожньому наборі немає жодного елемента, який порушив би умову). Друга: `includes` знаходить `NaN`, а старий `indexOf` — ні, бо [`includes` порівнює алгоритмом SameValueZero](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/includes), де `NaN` дорівнює сам собі.

```js
console.log([].every((n) => n > 100)); // true
console.log([].some((n) => n > 100));  // false

console.log([1, NaN].includes(NaN)); // true
console.log([1, NaN].indexOf(NaN));  // -1
```

`includes` порівнює значення через строгу рівність, тому для об'єктів він шукає **той самий об'єкт**, а не схожий. Щоб знайти товар за назвою, бери `some` з колбеком.

## reduce: згорнути масив в одне значення

`reduce` проходить масив і накопичує результат в **акумуляторі**. Колбек отримує поточне значення акумулятора й елемент і повертає нове значення акумулятора. Другий аргумент `reduce` — початкове значення.

```js
const total = products.reduce((sum, p) => sum + p.price, 0);
console.log(total); // 36850
```

По кроках: `0 + 32000 = 32000`, далі `+ 650 = 32650`, `+ 1800 = 34450`, `+ 2400 = 36850`.

Акумулятором може бути будь-що, наприклад об'єкт-лічильник:

```js
const words = ['так', 'ні', 'так', 'так', 'можливо'];
const counts = words.reduce((acc, word) => {
  acc[word] = (acc[word] ?? 0) + 1;
  return acc; // без return на наступному кроці acc буде undefined
}, {});
console.log(counts); // { 'так': 3, 'ні': 1, 'можливо': 1 }
```

**Завжди передавай початкове значення.** Без нього `reduce` бере перший елемент як акумулятор і починає з другого. На порожньому масиві це [кидає `TypeError`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/reduce), а на масиві об'єктів дає безглуздий результат:

```js
console.log([].reduce((a, b) => a + b, 0)); // 0
[].reduce((a, b) => a + b);
// TypeError: Reduce of empty array with no initial value
```

`reduce` — найпотужніший і водночас найменш читабельний метод. MDN прямо радить не тягнутися до нього, якщо є спеціальний інструмент: `flat` для сплощення, `Object.groupBy` для групування, `find`/`some`/`every` для пошуку, `new Set` для унікальних значень. Групування з `Object.groupBy` (працює в усіх сучасних браузерах із березня 2024 року і в Node.js 21+) виглядає так:

```js
const byCategory = Object.groupBy(products, (p) => p.category);
console.log(Object.keys(byCategory)); // ['техніка', 'аксесуари']
console.log(byCategory['техніка'].length); // 3
```

## forEach і методи, що змінюють масив

`forEach` викликає колбек для кожного елемента і **завжди повертає `undefined`**. Він потрібен для побічних дій: вивести в консоль, оновити DOM, записати в лог. Якщо ти пишеш `forEach`, а всередині `push` у новий масив, — тобі потрібен `map` або `filter`.

```js
products.forEach((p, i) => console.log(`${i + 1}. ${p.name}`));
// 1. Ноутбук
// 2. Мишка
// 3. Рюкзак
// 4. Навушники
```

Зупинити `forEach` посередині не можна: `break` у колбеку — синтаксична помилка, а `return` лише завершує поточний виклик колбека. [MDN каже прямо](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/forEach): якщо потрібно зупинитися, `forEach` — не той інструмент. Бери `for...of` з `break` або `find`/`some`. Ще одна пастка: `forEach` не чекає промісів, тож `async`-колбек у ньому не дасть послідовного виконання. Чому так і як правильно — у статті про [Promise і async/await](/blog/promise-async-await-javascript).

### sort змінює оригінал, toSorted — ні

Більшість методів повертає новий масив, але кілька змінюють масив **на місці**: `push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse`, `fill`, `copyWithin`. Найпідступніший серед них — `sort`, бо він ще й повертає той самий масив, тож здається, ніби створив новий.

```js
const prices = [2400, 650, 32000];
const sorted = prices.sort((a, b) => a - b);
console.log(sorted);            // [650, 2400, 32000]
console.log(prices);            // [650, 2400, 32000] — оригінал теж змінився
console.log(sorted === prices); // true
```

У ES2023 з'явилися копіювальні версії: `toSorted`, `toReversed`, `toSpliced` і `with` (заміна елемента за індексом). Вони [працюють у всіх сучасних браузерах з липня 2023 року](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/toSorted) і в Node.js 20+.

```js
const scores = [3, 1, 2];
const asc = scores.toSorted((a, b) => a - b);
console.log(asc);    // [1, 2, 3]
console.log(scores); // [3, 1, 2] — без змін

console.log(scores.with(0, 99)); // [99, 1, 2]
```

Друга пастка `sort` — порядок за замовчуванням. Без функції порівняння [елементи перетворюються на рядки й порівнюються за кодами символів UTF-16](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/sort), тож числа сортуються «як слова»:

```js
console.log([10, 1, 5, 100].toSorted());                // [1, 10, 100, 5]
console.log([10, 1, 5, 100].toSorted((a, b) => a - b)); // [1, 5, 10, 100]
```

Функція порівняння повертає від'ємне число, якщо `a` має йти перед `b`, додатне — якщо після, і нуль, якщо порядок не важливий. Для рядків українською використовуй `localeCompare`, щоб «є», «і», «ї» стали на свої місця:

```js
const cities = ['Їжакевичі', 'Ірпінь', 'Ізюм', 'Житомир'];
console.log(cities.toSorted((a, b) => a.localeCompare(b, 'uk')));
// ['Житомир', 'Ізюм', 'Ірпінь', 'Їжакевичі']
```

## Ланцюжки методів: реальний приклад

Методи, що повертають масив, можна викликати один за одним. Кожен крок робить одну просту річ, і код читається як опис задачі. Завдання: показати назви товарів у наявності, від найдешевшого, і порахувати їхню загальну вартість.

```js
const inStock = products
  .filter((p) => p.inStock)            // лише ті, що є в наявності
  .toSorted((a, b) => a.price - b.price); // від найдешевшого

const list = inStock.map((p) => `${p.name} — ${p.price} грн`).join('\n');
const sum = inStock.reduce((acc, p) => acc + p.price, 0);

console.log(list);
// Рюкзак — 1800 грн
// Навушники — 2400 грн
// Ноутбук — 32000 грн
console.log(`Разом: ${sum} грн`); // Разом: 36200 грн
```

Тут `filter` уже створив новий масив, тому й звичайний `sort` нічого б не зіпсував. Але `toSorted` позбавляє необхідності про це думати.

Ще кілька корисних прийомів одним рядком:

```js
// унікальні значення
console.log([...new Set(['js', 'sql', 'js'])]); // ['js', 'sql']

// сплощення вкладених масивів
console.log([[1, 2], [3], [4, 5]].flat()); // [1, 2, 3, 4, 5]

// map + flat за один прохід
console.log(['a b', 'c'].flatMap((s) => s.split(' '))); // ['a', 'b', 'c']

// останній елемент
console.log([10, 20, 30].at(-1)); // 30

// масив із N елементів
console.log(Array.from({ length: 3 }, (_, i) => i * 10)); // [0, 10, 20]
```

Ланцюжок не безкоштовний: кожен крок проходить масив ще раз і створює проміжний масив. Для сотень чи тисяч елементів це непомітно, і читабельність важливіша. Якщо ж масив величезний, а код гарячий, один цикл `for...of` буде швидшим. Колбеки, до речі, часто «бачать» змінні ззовні — це звичайні [замикання](/blog/zamykannia-v-javascript-prostymy-slovamy).

## Типові помилки

**1. Використовувати `map` для побічних дій.** `items.map((x) => console.log(x))` працює, але створює масив `undefined`, який ніхто не використовує. Для дій без результату — `forEach` або `for...of`.

**2. Забути `return` у колбеку з фігурними дужками.** `map((n) => { n * 2 })` повертає масив `undefined`, а `filter` з таким колбеком — порожній масив. Або пиши `return`, або прибирай фігурні дужки.

**3. Сортувати числа без функції порівняння.** `[10, 9, 1].sort()` дає `[1, 10, 9]`. Для чисел — завжди `(a, b) => a - b`.

**4. Не помічати, що `sort` і `reverse` змінюють оригінал.** Особливо небезпечно в React-стані чи в даних, які прийшли з пропсів: `props.items.sort()` тихо змінює чужий масив. Бери `toSorted` і `toReversed`.

**5. Викликати `reduce` без початкового значення.** На порожньому масиві — `TypeError`, на масиві об'єктів — `'[object Object]650...'` замість суми.

**6. Передавати функцію з кількома параметрами прямо в `map`.** Класика співбесід: `['1', '2', '3'].map(parseInt)` повертає `[1, NaN, NaN]`, бо `map` передає ще й індекс, а `parseInt` сприймає його як основу системи числення. Пиши явно: `.map((s) => parseInt(s, 10))` або `.map(Number)`.

**7. Шукати через `filter(...)[0]` чи `filter(...).length > 0`.** Це проходить весь масив і створює зайвий масив. Для одного елемента — `find`, для перевірки — `some`.

## Перевір себе

1. Що виведе код і чи зміниться `arr`?
   ```js
   const arr = [5, 1, 4];
   const res = arr.map((n) => n * 2).filter((n) => n > 5);
   console.log(res, arr);
   ```
2. Перепиши через один метод масиву:
   ```js
   let hasAdmin = false;
   for (const u of users) {
     if (u.role === 'admin') { hasAdmin = true; break; }
   }
   ```
3. Що поверне `[3, 20, 100].sort()` і чому?
4. Порахуй середню ціну товарів із масиву `products` (з початку статті) одним виразом.
5. Чому цей код виводить `0`, а не `6`?
   ```js
   let sum = 0;
   [1, 2, 3].forEach(async (n) => {
     sum += await Promise.resolve(n);
   });
   console.log(sum);
   ```

> [!solution]- Відповіді
> 1. `[10, 8] [5, 1, 4]`. `map` дає `[10, 2, 8]`, `filter` залишає числа більші за 5. Обидва методи повертають нові масиви, тож `arr` не змінюється.
> 2. `const hasAdmin = users.some((u) => u.role === 'admin');` — `some` теж зупиняється на першому збігу.
> 3. `[100, 20, 3]`. Без функції порівняння елементи порівнюються як рядки: `'100' < '20' < '3'`, бо порівнюються перші символи `'1'`, `'2'`, `'3'`. Правильно: `.sort((a, b) => a - b)`.
> 4. `products.reduce((sum, p) => sum + p.price, 0) / products.length` — це `9212.5`.
> 5. `forEach` не чекає промісів: колбеки запускаються, доходять до `await` і призупиняються, а `console.log` виконується одразу, коли `sum` ще `0`. Рішення: цикл `for...of` з `await` усередині async-функції або `Promise.all` з `map`.

## Коротко

- Для кожного методу запам'ятай дві речі: що він повертає і чи змінює оригінальний масив.
- `map` — перетворити кожен елемент, `filter` — відібрати, `find` — знайти один, `some`/`every` — перевірити, `reduce` — згорнути в одне значення.
- `forEach` повертає `undefined`, його не можна зупинити, і він не чекає промісів — для результатів бери `map`/`filter`, для зупинки `for...of`.
- `sort`, `reverse`, `splice` змінюють масив на місці; безпечні копії — `toSorted`, `toReversed`, `toSpliced`, `with`.
- Числа сортуй лише з функцією порівняння `(a, b) => a - b`, українські рядки — через `localeCompare(b, 'uk')`.
- У `reduce` завжди передавай початкове значення, а для групування є `Object.groupBy`.

Якщо масиви — одна з перших тем у твоєму плані, глянь [як вивчати JavaScript з нуля](/blog/javascript-z-nulya): методи масивів ідуть одразу після функцій. Потренувати їх на коротких задачах можна в курсі [JavaScript Zero→Pro на Loo](https://playloo.app).
