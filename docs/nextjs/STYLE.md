# Стайлгайд курсу «Next.js Zero → Pro»

Обовʼязковий для кожного автора й рецензента. Доповнює, а не замінює: [LEARNING_PLAYBOOK](../LEARNING_PLAYBOOK.md)
(анатомія теми, стиль, джерела), [CONTENT_SPEC](../../CONTENT_SPEC.md) (синтаксис блоків), [COURSE_FORMAT](../COURSE_FORMAT.md)
(курс), [NEXTJS_SYLLABUS](../NEXTJS_SYLLABUS.md) (структура, навички, обсяги). Еталон — модельна тема
`content/Guides/Next.js/Next.js - 07. Server і Client Components.md`.

## 1. Версія і факти

- Курс вчить **Next.js 16.3.8 + React 19.3** (версії з `package.json`). Першоджерело —
  `node_modules/next/dist/docs/**` (те саме, що nextjs.org/docs). Пам'яті моделі не довіряти: кожне API, опцію,
  поведінку звіряти з цими файлами.
- `cacheComponents: true` — базова конфігурація всіх прикладів (так Next.js 16 радить для нових проєктів).
  Поведінку без нього показуємо лише як «було → стало».
- Позначка `experimental` / `unstable_` — завжди, якщо вона є в документації.
- Застаріле (Pages Router, `getServerSideProps`, `middleware.ts`, `unstable_cache`, sync `params`) — **тільки** в темі
  48 або в коротких врізках «було → стало».

## 2. Мова і тон

- Українська, тон «розумний друг-сеньйор»: коротко, точно, без води. Спершу «навіщо», потім мінімальний приклад,
  реалістичний приклад, пастки, «🏭 Як це роблять у продакшні».
- Терміни, які так кажуть на співбесідах, лишаються латиницею й пояснюються при першій появі: Server Component,
  Client Component, hydration, prefetching, Suspense, streaming, static shell, cache, revalidation, Server Action,
  Route Handler, proxy. Повний список — `content/glossary/uk-en.yaml` (`keepLatin`).
- Не «ви», а «ти». Емодзі — лише якорі заголовків за PLAYBOOK (жодних Apple-емодзі в іконках: `icon` — `px:`/`si:`).

## 3. Тема

- Frontmatter: `title`, `id` (`nextjs-core-NN`), **`slug`** (латиницею, з реєстру [ids.md](./ids.md)), `order`, `level`, **`skill`** (id з NEXTJS_SYLLABUS §1), `icon`
  (`px:…`), `tags`, `prerequisites`, `estimatedMinutes`, `nextVersion: 16.3.8`.
- Обсяг — слова **разом із текстом вправ**, без блоків коду й inline-коду (так порівнюємо з JS-курсом): основний
  посібник 5–8k (ціль 6k), Start 3,5–6k. Не розтягувати: глибина, а не вода.
- Мікс вправ на тему основного посібника: ≥ 9 тестів (з них ≥ 2 `output`, ≥ 1 `order`, ≥ 1 `fill`, решта single/multi),
  ≥ 12 карток (рівні Junior/Middle/Senior), ≥ 4 `[!interview]`, ≥ 5 `[!reel]`, ≥ 3 `[!task]` з тестами, ≥ 2 ілюстрації
  (`[!diagram]` для потоків запиту, рендеру, кешу).
- Кожен неправильний варіант — справжня помилка розробника; `**Пояснення:**` пояснює, чому вона хибна.
- `output`-тести в Next.js = «передбач результат»: де виконується код, що в клієнтському бандлі, що закешується,
  порядок стрімінгу, статус-код.

## 4. Код

- Сучасний TypeScript/TSX, коментарі українською, шлях файлу першим рядком-коментарем (`// app/page.tsx`).
- **Кожен приклад перевірено**: зібрано й запущено в скретч-застосунку Next.js 16.3.8 під `/tmp/nextjs-scratch-*`
  (`npx create-next-app@16.3.8`, `cacheComponents: true`, **`react` і `react-dom` закріпити на 19.3.0** — CLI ставить
  19.2.x), або це утиліта з тестом. Неперевірений код у курс не йде.
- Помилки рендеру відтворюй у `next dev`: у `next build` повідомлення мініфіковані. Цитуй **справжній** текст помилки,
  навіть якщо він вводить в оману, і вчи читати Import trace.
- Якщо поведінка розходиться з документацією — пиши, що спостерігається на 16.3.8, і явно позначай розбіжність
  (`> [!warning]`), з посиланням на сторінку документації.
- Приклади з даними в памʼяті під `cacheComponents` пояснюй коротким `[!note]` (чому немає «uncached I/O» помилки),
  однаково в усіх темах.
- `[!task]`: ` ```ts starter ` / ` ```ts tests ` (TS-стрипінг раннера, етап 1) або `js`. Раннер не має мережі, `import`,
  `Request`, JSX — задачі тестують логіку (NEXTJS_SYLLABUS §5.2). Еталон `[!solution]` проходить тести (`pnpm content:check`),
  заготовка — ні (це перевіряє лише `pnpm course:check <курс>`). Перевір і одне правдоподібне хибне рішення: тести
  мають його ловити. 3–6 тестів, назви українською описують поведінку.
- Auth- і security-приклади безпечні за замовчуванням: перевірка доступу біля даних, без секретів у коді.

- `error.tsx` у 16.3 отримує **`retry`** (стабільний з 16.3; `reset` — другорядний): приклади пишемо з `retry`. У
  продакшні `error.message` із Server Component мініфікується (`Minified React error #441…`) — показуй це чесно.
- Нотатка про дані під `cacheComponents`: якщо приклад справді читає дані, невідомі на етапі збірки, назва
  «Чому сторінкам з даними потрібен `loading.tsx` / `<Suspense>`» і посилання «у темах 11–12, 14–16»; якщо дані в
  памʼяті — «Чому в прикладах дані в памʼяті». Без посилання на тему, в якій нотатка стоїть.

- Посилання на теми: на існуючі — wiki-link; текстом — лише «тема N основного посібника» або «тема Start N», ніколи
  просто «тема N» (у курсі дві нумерації).
- Жодних позначок процесу в тексті для учня: «(не звірено)», «ми перевірили», «звірено з … 30.10.2026». Якщо факт не
  звірено — не пиши його або звір.

## 6. i18n-готовність

- Без тексту в зображеннях; діаграми — `[!diagram]` з текстовими підписами.
- Кожна вправа має явний `id`. Не склеювати кілька думок в один абзац-«стіну»: абзац — одиниця перекладу.
- Повідомлення у `expect`/тестах — у назві `test('…')`, не в коді.
