## 1. Спільні правила для всіх курсів I–III

- **Id (registry §2):** курс — як у реєстрі (`fs-cs`, `fs-tools`, `fs-ramp`, `fs-html`, `fs-css`, `fs-jsi`, `fs-ts`, `fs-browser`, `fs-react`, `fs-state`, `fs-fetest`, `fs-perf`); тема — `<курс>-<NN>` (`fs-react-07`; практичні групи теж мають номер теми: `fs-ramp-16` = мікро-ката M01, `fs-ts-33` = челенджі C01, `fs-react-41` = machine coding M01); вправа — `<курс>-<NN>-<тип><nn>` (`fs-react-07-q03`, `fs-ts-35-task11`, `fs-css-31-rev02`), варіант — `v<n>` (`fs-css-03-q02v5`). У таблицях тем пререквізит «03» — тема того самого курсу; інші — повним id.
- **Навички (registry §3):** навичка = розділ курсу, slug `[a-z0-9-]` ≤ 32; глобальний ключ `<курс>/<розділ>` (`fs-browser/security`). Рівні — шкала `it` (`noob · junior · middle · senior · god`, god = Tech Lead); у таблицях тем J/M/S/L = junior/middle/senior/god. Ребра `requires` — таблиця «навичка → передумови» у кожному курсі; модулі JS і Next.js — їхні розділи як навички (`javascript-noob-to-god/core`, `nextjs-zero-to-pro/rendering`).
- **Власники концептів (registry §4):** XSS, CSP, CORS, cookies/SameSite, HTTP-кеш — `fs-browser`; CSRF/сесії — `fs-auth` (тут лише браузерний механізм SameSite); debounce/throttle/скасування/гонки в UI — `fs-state-14` (`fs-react` має лише machine coding, `fs-react-16` — cleanup підписок без теорії гонок); event loop — JS-модуль + `fs-jsi-05` (`fs-browser-07` — лише кадр і rAF); type challenges — `fs-ts`. Інші курси посилаються, не повторюють.
- **Бюджет варіантів (рішення лідера, B2):** кожен концепт теми має пул **≥ 6 варіантів**, **≥ 8 для core-тем** (core = тема з ≥ 5 шаровими Q&A, тобто критична на співбесідах) — або **параметричний генератор** (`gen`), де дані/числа міняються (системи числення, специфічність, box model, складність, trace, пороги CWV, виведення типів). Тест теми бере **1 варіант на концепт** (тест = стільки питань, скільки концептів, типово 4), ніколи більшість пулу; ретейк — інші варіанти, перемішані опції. **Пул вичерпано** → генератор або ремедіація (пояснення + worked example) і перевірка через ≥ 2 дні новим варіантом. Помилка знімається лише двома правильними відповідями в різні дні на невиданих варіантах (§6a.3) — пул 6/8 це витримує з запасом на 2 провали.
- **Код (B2.5):** «засвоєно» = L4 без підказок на **сиблінг-задачі того ж патерну** з **перегенерованим прихованим набором тестів**, іншого дня. Тому кожна задача рампи й челендж TS мають сиблінга в тій самій групі (12 мікро-ката = 6 концептів × 2).
- **Драбина (§5.2b):** L0 worked example з trace → L1 Parsons (`[!quiz] type: order`) → L2 fill (`type: fill` / guided build) → L3 skeleton з псевдокодом → L4 blank → **L5 варіанти й швидкість** (інші рішення §5.2a phase 3 + timed interview mode + explain aloud). **Перевірено:** `parseOrder` (`src/content/blocks/quiz/exercise.ts`) уже підтримує рядки-дистрактори — маркер `// ✗` (`#`/`--`/голий `✗`), перевірка «дистрактор ≠ правильний рядок», ≥ 3 справжніх шматки; тож L1 з 1–3 дистракторами не потребує розширення. Генерувати L0–L3 з одного джерела (§5.2b H) — робота платформи етапу 1.
- **Анатомія теми** — LEARNING_PLAYBOOK §2 + для треку: «що ти вже знаєш → що нового → де це використовується», «🎤 Як відповісти на співбесіді» за рівнями, «Чому так, а не інакше?», «поясни Loo», recall наприкінці. Мін. 2 ілюстрації.
- **Слова (M3)** — дві колонки: «теорія + редакторіали» (текст уроку, розбори рішень) і «текст вправ» (умови, варіанти, пояснення, кроки guided build, моделі шарових відповідей). Базис тексту вправ на одиницю: c 35 · q 70 · gen 150 · po 60 · rd 45 · qa 280 · qa-шар 220 · hc 200 · micro 300 · js 500 · ts 300 · react 500 · mc 900 · domain 350 · rev 350 · test 400 · lab 300.
- **Пояснення вголос:** кожна задача й шарова відповідь має крок «explain aloud» — у Part I українською, з Part II і англійською (`[!talk]`, фрази `fs-en-work` §6).

## 7. Порядок у треку і паралельні потоки

- **Хребет:** I (`fs-cs` → `fs-tools` → `fs-ramp`) → II (`fs-html` → `fs-css` → JS-модуль + `fs-jsi` → `fs-ts` → `fs-browser`) → III (`fs-react` → Next-модуль → `fs-state` → `fs-fetest` → `fs-perf`). `fs-jsi-NN` відкривається після відповідного розділу JS-модуля. `fs-react` machine coding M03–M04 (`fs-react-43…44`) відкриваються після `fs-state/fetching` (власник теорії гонок).
- **Темп (стандартний профіль, хребет 30 хв/день ≈ 3.5 год/тиждень):** Part I ≈ 28 тижнів, II ≈ 76, III ≈ 86. Інтенсив (45 хв) — × 0.67. Досвідчений шлях — таблиця в §0.2.
- **Test-out:** екзамен розділу закриває розділ, але перевірка іншого дня все одно потрібна (§6a). Next.js `basics` зараховується, якщо підтверджено `fs-cs/internet`, `fs-react/basics`, `fs-ts/basics`.
- **Паралельні потоки** — англійська (`outline-english-for-it.md` §4, тижні виведено з цих годин), `fs-algo` (після gate рампи `fs-ramp-25` або placement), `fs-soft`.
