# Аналітика сайту й адмінка

Власна (first-party) аналітика без сторонніх сервісів: усе пишеться в нашу базу Supabase і читається в `/admin`.

## Що збираємо

| Подія | Коли | Що в ній |
| --- | --- | --- |
| `pageview` | кожен перехід (лендинг, блог, застосунок; без `/admin`) | шлях із query, заголовок, зовнішній referrer і UTM першого входу |
| `click` | клік по посиланню, кнопці, `summary`, елементу з `data-track` | текст / `aria-label` (≤ 80 символів), посилання, тег, `data-track`, позиція кліку у вікні (%) і на сторінці (px) |
| `leave` | перехід далі або закриття / згортання вкладки | час на сторінці |

Сервер (`/api/a`) додає: IP (`x-forwarded-for`), країну, регіон і місто (гео-заголовки Vercel `x-vercel-ip-*`),
пристрій, браузер і ОС (з user agent), користувача, якщо він увійшов. Відвідувач — випадковий id у `localStorage`,
сесія — у `sessionStorage` (нова після 30 хв бездіяльності). Боти (за user agent) відкидаються.

- Клієнт: `src/ui/analytics/Tracker.tsx` (у кореневому layout; пакети по ≤ 30 подій кожні 5 с і при закритті вкладки,
  `navigator.sendBeacon`).
- Збирач: `src/app/api/a/route.ts` + `src/server/analytics/collect.ts` (zod-схема, лише same-origin і шляхи цього
  сайту, ≤ 240 подій за хвилину з одного IP на інстанс).
- Таблиця `analytics_events` (`drizzle/0012_analytics.sql`): RLS увімкнено, грантів немає — через Data API її не
  прочитати; пише й читає лише сервер. Рядки акаунта видаляються разом з ним.

**Приватність.** IP і місце — персональні дані: опиши аналітику в `/privacy` (що збираємо, навіщо, скільки зберігаємо)
і задай строк зберігання (рекомендую 90 днів; чистка — окремим кроном, ще не зроблено). Для відвідувачів з ЄС
аналітичні дані зазвичай потребують згоди (cookie-банер) — вирішити перед рекламою на ЄС.

**Історія до запуску** у базі не відновлюється: дані збираються з деплою, де з'явився трекер. Що можна подивитися
окремо: Google Search Console (покази й кліки блогу з пошуку), Cloudflare (запити й країни, якщо домен проксіюється
через Cloudflare), логи Vercel (лише кілька днів).

## Адмінка `/admin`

- Вхід — звичайна форма `/login`: email `ADMIN_LOGIN_EMAIL` і пароль, хеш якого лежить у `ADMIN_PASSWORD_HASH`. Вхід
  проходить ті самі ліміти спроб, що й звичайний. Успіх — підписана (HMAC, `ADMIN_SESSION_SECRET`) httpOnly-кука
  `loo_admin` на 12 год, яка відкриває лише `/admin` (не акаунт учня). Вихід — кнопка «Вийти» в адмінці.
- Також відкривається акаунтом з роллю `admin` (`ADMIN_EMAILS`). Решта бачить 404.
- **Огляд** (`/admin`): відвідувачі, перегляди, сесії, відмови, середній час на сторінці, кліки, увійшли, нові акаунти —
  зі зміною до попереднього такого самого періоду й спарклайнами; графік відвідувачів (пунктир — попередній період);
  «онлайн зараз» (подія за останні 5 хв); топ-5 сторінок, джерел і країн.
- **Аналітика** (`/admin/analytics`): усе з URL-параметрів — період (`range=today|24h|7d|30d|90d|month|custom` +
  `from`/`to`), крок графіка (`gran=hour|day`, інакше авто: години до 2 днів), метрика графіка (`metric`), порівняння
  (`cmp=0` вимикає), фільтри (`path` — точний або префікс із `*`, `ref`, `country`, `city`, `device`, `browser`, `os`,
  `lang`, `screen`, `utm_source|utm_medium|utm_campaign`, `user=in|guest`; комбінуються, видно як чипи). Фільтри за
  джерелом і UTM беруть сесії цілком (ці поля пишуться лише в першому перегляді). Розбивки: сторінки, блог, вхід/вихід,
  джерела, UTM, країни, міста, пристрої, браузери, ОС, мови, екрани, акаунт/гості — клік по рядку додає фільтр. Кліки,
  останні події по 200 (курсор `before`). Відмова = сесія з одним переглядом. Час — київський.
- Код: `src/app/(app)/admin/{page.tsx,analytics/page.tsx}`, `src/server/admin/analytics-query.ts` (модель запиту, SQL —
  лише параметри, колонки з білого списку), `src/server/admin/analytics.ts` (запити по одному з тайм-аутом,
  `sequential` з `stats.ts` — пул Supabase не терпить паралельних запитів на з'єднанні), `src/ui/admin/*` (графік,
  списки, вибір періоду), `src/app/admin-analytics.css`; доступ — `src/server/admin/guard.ts`, `src/lib/admin-token.ts`,
  проксі (`src/proxy.ts`), вхід (`src/app/(app)/(auth)/auth/sign-in/route.ts`).
- Локально з даними: `tsx --env-file-if-exists=.env.local scripts/seed-analytics.ts` (лише localhost; `--clear`
  прибирає згенероване).
- Користувачі, економіка, журнал дій, налаштування — [ADMIN.md](ADMIN.md).

### Облікові дані

```bash
pnpm admin:credentials            # новий пароль → .env.local (ADMIN_LOGIN_PASSWORD), хеш і секрет
pnpm admin:credentials --vercel   # те саме + хеш, email і секрет у Vercel Production (пароль лишається локально)
```

Пароль ніде не друкується: він лише в `.env.local` (у git не потрапляє). Після `--vercel` потрібен деплой. Нова
генерація скасовує старий пароль і всі відкриті адмін-сесії.
