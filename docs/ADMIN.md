# Адмінка `/admin`

Внутрішня панель власника: статистика сайту, користувачі, економіка гри, журнал змін, налаштування. Учням і
пошуковикам не видно (404 і `noindex`).

## Доступ

- Вхід — звичайна форма `/login` з `ADMIN_LOGIN_EMAIL` і паролем (хеш у `ADMIN_PASSWORD_HASH`). Успіх — підписана
  httpOnly-кука `loo_admin` на 12 год (`ADMIN_SESSION_SECRET`), яка відкриває лише `/admin`. Деталі й команди для
  пароля — [ANALYTICS.md](ANALYTICS.md#облікові-дані).
- Або акаунт учня з роллю `admin` (`ADMIN_EMAILS`).
- Кожна сторінка й кожна дія окремо викликає `requireAdminArea()` (`src/server/admin/guard.ts`) — layout не захищає
  server actions.

## Розділи

| Сторінка | Що там |
| --- | --- |
| `/admin` — Огляд | головні цифри й графік за період |
| `/admin/analytics` — Аналітика | детальна аналітика відвідувань (сторінки, джерела, гео, пристрої, кліки, фільтри) |
| `/admin/users` — Користувачі | пошук за імʼям / email / id, сортування за реєстрацією, візитом, XP, баксами, кристалами |
| `/admin/users/[id]` | картка учня: баланси, стан гри, курси, предмети, нарахування, події на сайті з IP, дії адміна — і інструменти |
| `/admin/economy` — Економіка | валюти в обігу, нараховано / витрачено за причинами, найбагатші, популярні предмети |
| `/admin/audit` — Журнал дій | усі зміни з адмінки: коли, хто, що, кому |
| `/admin/settings` — Налаштування | спосіб входу, які змінні задані (без значень), чистка старої аналітики, розміри таблиць |

## Інструменти на картці учня

Усі — server actions у `src/server/admin/actions.ts`: zod-валідація, запис як система в одній транзакції разом із
рядком `admin_audit`, лог `[admin] …` у функціях Vercel.

- **Баланс** XP / баксів / кристалів: ± довільна сума або швидкі кнопки. Це звичайний рядок леджера з `reason = 'admin'`,
  тож баланс, історія й ранг лишаються узгодженими. Списання не опускає баланс нижче нуля (у журнал іде фактична сума).
- **Сердечка** — встановити 0…5. **Заморозки серії** — ±N (не нижче 0). **Подвійний XP** — N годин поверх чинного
  бусту; 0 — зняти.
- **Предмети** — видати або забрати постійний предмет магазину (скіни, спорядження).
- **Бан** з причиною: сторінки застосунку ведуть на `/banned` (причина видна учню), API й дії працюють як для
  гостя (`requireUser` / `apiUser` / `userScope` у `src/server/auth`). Дані не видаляються; розбан — одна кнопка.
  Адмін-акаунт заблокувати не можна.

## Дані

- `profiles.banned_at`, `profiles.ban_reason` — не входять у колонкові гранти учня (сам себе не розбанить).
- `admin_audit` (`drizzle/0013_admin.sql`): `at`, `actor` (`login` або `role:<user id>`), `action`, `target_user_id`,
  `payload`. RLS увімкнено, грантів немає — лише сервер.
- Читання: `src/server/admin/{users,economy,stats}.ts` — по одному запиту за раз (пулер Supabase не приймає
  конвеєрні запити).
