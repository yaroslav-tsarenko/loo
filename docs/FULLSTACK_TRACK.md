## 2. Ринок 2026 — що програма мусить відображати

Повністю — [`market-2026.md`](fullstack/research/market-2026.md), [`loops.md`](fullstack/research/loops.md). Усе про

**ШІ на співбесідах.** Обидва режими обовʼязкові.
- **Meta:** AI-enabled раунд замість одного з двох кодувань онсайту (з 10.2025, розгортається).

## 4. «Метод Loo» і задачі

**7 кроків** (назви фінальні):
1. **Зрозумій** — переказ, входи/виходи, уточнення; обмеження = підказка.
2. **Розвʼяжи руками** — малий приклад на папері.
3. **Наївне рішення** — найпростіший правильний код + складність.
4. **Знайди зайве** — B/U/D: Bottleneck, Unnecessary, Duplicated.
5. **Обери інструмент** — патерн з карти або зведення до відомої задачі; стан і інваріант.
6. **Напиши й перевір** — малими кроками, інваріант у коментарі, сухий прогін, крайові випадки.
7. **Оціни й поясни** — складність, альтернативи, 60 секунд уголос, «а якщо потік / не влазить у памʼять / паралельно».

Візуал методу (піксельні `px:`-іконки на кожен крок) — модельна одиниця етапу 1.

**Карта патернів** — 31 вузол у порядку передумов; повний список, задачі по E/M/H, канонічні задачі й комбіновані hard —
`outline-parts-4-7.md` (fs-algo). Кожен патерн — тема з:
- карткою (тригери, скелет, складність, типові баги, 3 канонічні задачі);
- босом патерну (L4, на час);
- «сестринськими» задачами кожного рівня складності — для перевірки «засвоєно».

Кожні кілька патернів — змішаний набір без назви патерну.

**Драбина** — §5.2a–b специфікації. Автор пише **одне джерело**:
- фінальний розвʼязок з маркерами кроків;
- «чому» на кожен крок;
- псевдо-план;
- 1–3 рядки-дистрактори;
- тести з тегами помилкових уявлень;
- варіанти.

Компілятор виводить рівні:

| Рівень | Що бачить учень |
|---|---|
| L0 | приклад з трасою змінних |
| L1 | Parsons — наявний `quiz order` уже підтримує рядки-дистрактори (маркер `// ✗`, `parseOrder`) |
| L2 | кроки з закритим кодом і тестами кроку |
| L3 | скелет з планом у коментарях |
| L4 | чистий редактор |
| L5 | варіанти й режим на час |

«Вміє написати» = L4 без підказок **на сестринській задачі або з пересіяними прихованими тестами** іншого дня.
≥ 70 % задач мають ≥ 3 варіанти. Розвʼязки — **TypeScript-first** (раннер уже знімає типи).

## 5. Платформа: стан і план етапу 1

Повністю — [`platform-audit.md`](fullstack/platform-audit.md).

### 5.1 Блокери (до масового контенту)

1. **Памʼять контенту.** Один знімок усіх посібників у кожному сервері: **133,7 МБ** heap (4 курси, 17 822 одиниці);
   бандли 7,7 МБ парсяться на старті. Трек ≈ ×2,9 одиниць (≈ 51k) → без шардування ≈ 300–390 МБ.
   **Рішення:** шарди по посібниках, ліниве завантаження з LRU, бандли по курсу, тест бюджету heap.
2. **Довіра клієнту.** `finishTask({ solved })` приймає вердикт браузера; тести й еталон ідуть на сторінку.
   **Рішення:** серверний вердикт у воркері з лімітами CPU; приховані тести й ключі — лише на сервері.
3. **Модель засвоєння** не вміє §6a (гейти дорадчі, 80 %, помилки знімаються тим самим питанням, FSRS лише для карток).
   **Рішення:** concept id + пули варіантів, помилки на рівні концепту, гейти 100 %, повтор іншого дня, FSRS для задач.

## 6. Знання, що тримаються

**Пули варіантів** — контракт для всіх курсів (закриває рецензію B2):
- **Розмір пулу:** ≥ 6 варіантів на концепт, ≥ 8 на ключовий (ключова тема = ≥ 5 шарових Q&A); де дані варіюються —
  параметричний генератор.
- **Тест теми:** **1 варіант на концепт**, ніколи «10 з 12».
- **Пул вичерпано:**
  - генератор дає новий варіант;
  - якщо генератора немає — ремедіація (пояснення + розібраний приклад) і повторна перевірка через 3 дні на варіанті,
    який учень бачив найдавніше, з перемішаними опціями й датою.
  - Такий успіх зараховується з нижчою довірою, а концепт отримує мітку «поповнити пул» для авторів.
- **Шарові Q&A не є елементами гейту:** це самоперевірка й FSRS.
- **Відкриті відповіді:** 100 % пунктів рубрики, ≥ 3 варіанти завдання на рубрику, тож ретейк отримує свіже завдання.
- **Кодування:** «засвоєно» = L4 на сестринській задачі того ж патерну або з пересіяними прихованими тестами іншого дня.
- **Гейт рампи** — теж 100 %.

**Анти-ґеймінг:**
- позиції правильних відповідей рандомізуються;
- пул не видається повністю за одну сесію;
- числа й дані змінюються;
- «засвоєно» = успіх на невиданому варіанті іншого дня.

**Цикл помилок:**
1. «Мої помилки» — з концептом, типом хибного уявлення й джерелом.
2. Ремедіація: коротке пояснення → 1 розібраний приклад → нові варіанти.
3. Закриття — 2 правильні відповіді в різні дні на нових варіантах.
4. Відкриті помилки блокують гейт розділу.
5. «Робота над помилками» — перша в щоденному міксі.

**Спіралі** (явні посилання між витками):

| Спіраль | Витки |
|---|---|
| Кеш | HTTP-кеш (`fs-browser`) → TanStack Query (`fs-state`) → кеш Next.js → Redis (`fs-nosql`) → стратегії кешу (`fs-queues`) → CDN і дизайн кешу (`fs-sd`) |
| Стан | змінні (`fs-ramp`) → замикання (JS) → React state → менеджери стану (`fs-state`) → транзакції (`fs-sql`) → розподілений стан (`fs-dist`) |
| Конкурентність | event loop (JS, `fs-jsi`) → гонки в UI (`fs-state`) → libuv, worker threads (`fs-node`) → черги (`fs-queues`) → ізоляція (`fs-sql`) → консенсус (`fs-dist`) |
| Узгодженість | форми → MVCC → кеш-інвалідація → CAP/PACELC, саги |
| Безпека | HTTPS (`fs-cs`) → XSS/CSP (`fs-browser`) → auth (`fs-auth`) → вебхуки й підписи (`fs-integr`) → threat modeling (`fs-sec`) → prompt injection (`fs-ai`) |
| Продуктивність | складність (`fs-ramp`) → рендер (`fs-browser`) → Web Vitals (`fs-perf`) → EXPLAIN (`fs-sql`) → профайлінг Node → SLO (`fs-obs`) |

**Власник концепту** — [`registry.md`](fullstack/registry.md) §4: теорія й Q&A концепту живуть в одному курсі, інші додають
свій ракурс. У рецензійному гейті кожної партії — Haiku-скан дублікатів формулювань.

**Атлас знань:**
- **Вузол** — навичка (`<курс>/<навичка>`, ≈ 330 вузлів); теми — листя вузла.
- **Ребра** — `requires` і `usedIn` з таблиць «навичка → передумови» outline-файлів.
- **Інтерфейс:**
  - «ти тут»;
  - пошук;
  - глосарій uk ↔ en (ціль ≈ 2 000 термінів);
  - сторінка-підсумок і шпаргалка на модуль;
  - на частину — «як усе складається» (повний шлях запиту браузер → DNS → CDN → балансувальник → Next.js → API → кеш →
    БД і назад).
- **Збирання:** атлас будується з даних курсів, не вручну.

## 7. Готовність і план

Модель — [`outline-parts-8-9-11.md` §4](fullstack/outline-parts-8-9-11.md).

- **Докази:** оцінені результати, вага спадає вдвічі кожні 21 день; кодування — лише самостійні L4.
- **Домен:** 0,35 розвʼязки + 0,20 пригадування + 0,30 рубрики раундів + 0,15 дотримання «Методу Loo», мінус штраф за
  відкриті помилки, обмежено покриттям навичок, з довірчим інтервалом. Некодові домени: 0,25 / 0,55 / 0,20.
- **Дотримання методу:**
  - розпізнаний патерн, назване «зайве»;
  - крайові випадки до коду, спочатку наївне рішення, правильна складність;
  - для відкритих відповідей — повний STAR, спершу діапазон зарплати, мнемоніка PAUSE.
- **Луп:** раунди з вагами лупу (з `loops.md`), обмежено найслабшим раундом + 10.
- **«Готовий»** — усе разом:
  - луп ≥ 85, кожен раунд ≥ 80;
  - 2 успішні прогони в різні дні;
  - немає відкритих критичних помилок;
  - достатня англійська.

  UI показує 3 головні блокери.
- **Калібрування.** «≈ 99 % проходження» — проєктна ціль. Пороги спершу калібруються на синтетичних профілях; перше
  зовнішнє калібрування — реальні співбесіди власника (за його згодою).
- **План:** учень задає ціль (тип компанії, рівень, дата) → тижневий план: спершу прогалини, щодня помилки → задачі →
  Q&A → англійська; раз на кілька днів — system design.
